# High-level roadmap

> **The whole-project view, ID slice — a dated snapshot.** This chapter carries ID's share of the merged priority list built by the Code Book programme (tracker [#13905](https://github.com/developing-today/code/issues/13905)): the items ID owns, in full, and one-line pointers to the items ID only touches. The census behind it was taken on **2026-11-23/24**; statuses are as of that census unless a later read is named. The merged list itself lives in the [Code Book](https://developing-today.github.io/code/code/). Where this chapter and a living tracker disagree, the tracker is right and this chapter is stale.

This chapter does not replace [Roadmap, issue map and the design-record index](roadmap-and-issue-map.md). That chapter is the ID programme's own record: the phase spine, the epic and tracker map, and the full design-record index. This chapter is the cross-project ranking — where ID's items sit in the whole project's order, why they sit there, and what their timing record says. The two chapters cross-reference; neither duplicates the other. The [Current ID issue map](../research/current-issue-map.md) remains the living census of open ID issues.

The merged list is ordered across the whole project: execution substrate first (fleet), then the physical substrate (lab), then the data substrate (backups, ingest, storage placement), then search intelligence (Atlas and ID together), then the ID platform build-out, then the gateway, PM and fork surfaces, then the record itself. ID owns items 15–23 — the consumer-facing graph apps and the whole ID platform tier. Item numbers below are the merged list's numbers, kept so a reader can move between books and the Code Book without renumbering.

Types used below: a *capability set* is a capability set to reach; a *problem* is a problem to solve; a *milestone* is a milestone; a *shift goal* is a goal that marks a shift. Status words are the census's: done, in flight, designed, not started — each with its evidence.

## Item 19 — ID scale and performance hardening: measured limits at 10× and 100×

- **Type:** problem.
- **Description:** A generator and harness producing worlds at 10× and 100× current sizes, measuring join time, replay, frame cost and memory on laptop-class and server-class hosts, ending in a measured limits table — with Drew's performance doctrine (a multiplier is proven by benchmark, never asserted) as the bar.
- **Status (census 2026-11-23):** in flight. At census, two of five measurement slices were closed with real numbers and the chain was gated on the flag-held #13084 and the in-progress #13086. Both gates have since cleared (re-verified before this chapter merged): the #13084 hold was released and the issue closed with the join-benchmark PR #13424 (merged 2026-11-23), and #13086 closed as completed the same day — four of the five measurement slices are now closed; #13087 and #13088 remain open. A codified wall was found: the `WorldLimits` participants cap of 256 against tier targets of 320 at 10× and 3,200 at 100× — a design decision the runs inherit.
- **Most related:** [#6281 — scale core topic](https://github.com/developing-today/code/issues/6281) · [#6304 — scale v1 design](https://github.com/developing-today/code/issues/6304) (open, in review; design document landed PR #13090) · [#13083 — stress-world generator](https://github.com/developing-today/code/issues/13083) (closed — 10× is 11,001 worlds and 200,000 events in 35.7 seconds) · [#13085 — frame cost](https://github.com/developing-today/code/issues/13085) (closed — measured flat to 1M events) · [#13084 — join-time benches](https://github.com/developing-today/code/issues/13084) (closed — the census-time flag hold was released; join-benchmark PR #13424 merged 2026-11-23) · [#13086 — memory profile](https://github.com/developing-today/code/issues/13086) (closed, completed 2026-11-23; in progress at census) · [#13087 — first 10× run](https://github.com/developing-today/code/issues/13087) · [#13088 — 100× feasibility](https://github.com/developing-today/code/issues/13088) · [#5685 — DoS suite and benchmark programme](https://github.com/developing-today/code/issues/5685).
- **Timing:** #13083 and #13085 closed with measurements in the 2026-11-23 programme window; at census #13084 was flag-held (no date — it needed Drew's item-specific approval), and the hold was subsequently released, the issue closing via PR #13424 on 2026-11-23; #13086 also closed as completed on 2026-11-23. #13087 and #13088 inherit the chain with no independent dates.
- **Ordering rationale:** measurement before optimisation, and before currency and federation load arrives; ranked below federation because its harness already exists and can run in parallel.
