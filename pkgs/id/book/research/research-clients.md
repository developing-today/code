# Playable, accessible and authorable worlds across ID shells

_Research snapshot of November 23, 2026. Code and issue observations refer to the cited revisions and collection times._

**Design proposal v1.** This extends the staged Clients, Roc and Lifecycle chapters and the existing six app fixtures. It specifies how a person proves an app works across hosts, how delayed input is handled and how an author changes the app. Repository evidence here is from main at `7310a95730791e66da98f7b0e13865930058a516`. The examples below are independent acceptance oracles. Their implementation, physical-device results and any change to the shell contract require separate evidence. The checked guest ABI, shell contract and book keep their existing names and versions.

### Task profiles and accessible interaction

An app release should declare the user tasks it offers. For each essential task record the entry screen, semantic target, allowed action, required input precision, alternate path, success record and availability under refusal of each requested effect. Use existing contract kinds and IDs where they suffice. A host reports which tasks it can **complete** and which it can only display. The declaration can begin as a fixture alongside the package. A protocol addition is warranted only when two independent hosts need to exchange a missing datum.

For example, Mine may resolve to the existing ore tile ID plus a mine action. A terminal participant moves to the tile or chooses its numbered entry. A touch user taps its labelled region. A screen-reader user chooses the object from a nearby-targets list and activates Mine. The authoritative result is the same world event and ore balance for equal starting conditions. Each route discloses the same cost before admission. A companion hardware shell that only supports existing token-bound forms may confirm a proposed limited action, but cannot claim playable spatial navigation merely by receiving its resulting world head. An app can require precise path input for a freehand stroke. Creating an authored polyline by entering points is an alternate task only when it has the same data semantics.

The host should track focus separately from persisted selection and gesture capture. Scope focus to a program, a view family and an author-stable control ID. Within that family keep focus if the active control survives a refresh and still acts. On removal, choose the next enabled surviving control in the old reading order, then the previous one. On a deliberate navigation between views move to the destination heading or first active control. Freeze the target and view revision at gesture start. A release activates only after validating the same logical binding and applicable host admission. Where stale-decision validation is confined to a negotiated profile, inspect the server enforcement before generalizing it. Use token-bound forms for actions that already use form confirmation. If the required precondition cannot cross the current boundary, disable the stale action and redisplay for explicit selection. A visual focus transition emits zero world events. A display acknowledgment never commits user intent.

Use a screen-reader-friendly object index for large boards. Give each actionable entity a name, position, state and available action list in deterministic reading order. Announce a player-relevant result once per accepted operation. Individual sprite animations and pointer movement need no announcement. Web checks include actual DOM accessibility attributes and keyboard traversal. Android checks include merged and unmerged trees plus a physical assistive-service walkthrough. IME pre-edit, selection handles, zoom and hover stay local. On committed text preserve the user's exact string according to the field's published semantics. A reconnect discards stale host-only gesture/IME state and resumes from accepted world state.

**Acceptance fixture.** View 40 lists controls A, B, C. Focus B. View 41 inserts D before A but preserves B's binding. Focus remains B with zero journal events. Pointer-down on B at 41, followed by a replacement view 42 reusing the ID for a different action, then pointer-up, results in zero admitted actions and a refreshed choice. A fresh explicit activation against 42 commits its declared action once. With an Android labelled button containing an icon, the navigable action occurs once and has one accessible name. Verify first in the model, then through a real input adapter into the durable event stream. Re-running the production renderer to generate its own expected rows supplies no independent oracle.

### Ticks, drawing and assets

Split three clocks. Input sample time is host-local. A committed logical tick is a guest input. Presentation time is host-local and can interpolate a committed state. When a node sleeps, reconnect from the last durable head and fold recorded ticks. Generating elapsed wall-clock ticks on each rejoining shell would multiply simulation work and outcomes. An app that intentionally advances during absence must specify which authority produces the bounded catch-up event, how it orders against inputs and how the limit is shown. Until that policy exists, a manual Step advances exactly once through the ordinary admission path. A replay on a 30 Hz display and a 90 Hz display should consume the same prefix and reproduce the same published records.

An asset manifest can map the semantic cue `ore-collected` to a text description, optional image/audio hashes, declared encoded sizes and media types. The entitlement, decode bounds and renderer capabilities are evaluated before opening media. Decorative assets can be marked as such. For the app suite, a loss of speaker output or a denied download must still communicate the collection through its published state and accessible description. Give each requested derivative a versioned decoder or transform identity when exact derivative bytes matter. A sprite palette, display size and resampling choice do not change the rules. Keep missing, inaccessible and failed media distinguishable in private host diagnostics. Do not disclose private media identifiers to participants outside their read scope.

A headless Bevy projection reads committed events and keys entities by stable world ID. Rebuild it at any valid checkpoint. For identical accepted inputs, a stalled renderer and a headless batch both yield the hand-computed world records, including deterministic tie-breaking between competing moves. Compare the source record and emitted intent per phase; this detects an ECS system writing authoritative state outside the journal. Frame-rate evidence measures display behavior separately from guest fuel.

### Direct authoring, offline edits and distribution

An optional build sidecar, keyed by compiled module content ID, maps author-declared semantic IDs to package-relative source anchors. Validate it against the module and expose only source a user can read. The compiler/runtime may omit anchors for dynamic controls. A stale or missing sidecar yields an inspectable semantic target and explicit unavailable-source status. Never infer an editable file from a label, mutable row number or path sent by a guest. Selecting Inspect on a published world reads the authorized manifest and projection. Editing forks a local draft, recompiles, runs the existing fixture gate on a complete history and previews in the scratch world. Publishing requires package/write authority and the documented world upgrade policy. Changes to requested effects require a newly valid grant for the added effect. A participant with read/play permission can inspect public information and continue running the last accepted revision after a failed build.

Sketch example. One symbol is the segment from (0,0) to (2,0). Two instances reference its hash, with translations (1,1) and (5,1). The author creates a replacement segment ending at (3,0) and retargets only the first instance. Published endpoints become (4,1) and (7,1). Replaying the old revision yields (3,1) and (7,1). A drawn preview can cache raster tiles by document revision, viewport and renderer version. Neither a cache eviction nor a zoom should alter any endpoint. An absent symbol preserves the reference and placement and presents a missing-asset placeholder. Defer continuous constraints until fixed-point/range, iteration bound, cycle behavior, precise failure and fuel ceilings have independent examples. A deterministic failure cannot silently choose different geometry on another host.

Mind map example. Dragging a node or invoking “Move under…” must submit the same source and destination IDs. Rerender or reordering during a drag cannot reinterpret an array index as a different parent. A denied content grant between opening the chooser and commit keeps the committed graph and reports the failed operation without revealing private siblings. For concurrent structural moves, use the accepted content-class tree policy. Before declaring equivalence, specify the fixture's old parent, both concurrent moves, actor identities and expected resulting tree, including how the UI exposes a superseded move. The archive's CRDT/namespace record owns that choice. A client alone cannot settle it.

### Physical device proof

Keep the current ESP32-class shell's supported confirmation task. A physical proof should identify board, firmware revision, paired node, transport, input device, display, measured memory peak and reconnect results. A fresh wake retrieves the form, a deliberate press answers it, and disconnect/reconnect reproduces exactly the admitted action or its refusal. A missing presentation token results in no outgoing form result. Required free-text entry is unavailable on a confirmation-only profile. Degrade locally for presentation or refer the user to another owned shell after an explicit decision where a handoff is necessary. Preserve operation identity and avoid replaying the grant on another device by default.

A separate partial-display experiment has a measurable ceiling. A 240×240 RGB565 framebuffer uses 115,200 bytes of pixel storage. A 240×20 strip uses 9,600 bytes and two strips use 19,200 bytes, excluding stride padding, transport, stacks, decoded assets and driver allocations. Record those additional costs on the actual board. Do not reuse a strip until transfer completion. If a patch's base view is missing, recover a full view through the existing contract before updating the displayed committed state. Measure display completion separately from durable event acceptance and readback. No board size, RAM or successful run is implied by the arithmetic.

## A counterexample for simulation replay

Consider a proposed guest that starts at 2 and supports two authorized actions, double and add one. Accept them in that order and the result is 5. Reverse the order and it is 6. Equal guest bytes, fuel limits and a set of event IDs do not specify the outcome by themselves. Croquet gives its replicated model discrete virtual time and orders events for a session. ID can record a world-specific accepted input sequence with a defined tick order, or choose an operation algebra with a justified merge rule. Applying a blanket global order across the signed graph would exceed the Phase 8 causal-validity decision. In a parity test, specify the admitted order independently and vary the number of rendered frames on each client. Both clients should produce 5 for the first history and 6 for the second. Crossed offline branches need the app’s explicit admission or merge rule.
