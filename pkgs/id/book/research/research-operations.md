# Operating one graph across intermittent peers and hosted backstops

*Research snapshot of November 23, 2026. Code and issue observations refer to the cited revisions and collection times.*

A traveler edits a document offline. Their Android node suspends after sending an event. A hosted relay received it, but the reply never arrived. Later the traveler meets a Linux peer that has the same document. What should the app display? This scenario separates four questions with different answers: what the local node saved, what another node accepted, where bytes can still be retrieved, and which edits the app can currently display. An ID host should expose each answer at the strength of its evidence. The same answers should be available to a caller that chooses an eligible direct peer.

This is a proposed design extension to the existing store, federation, lifecycle, release and scale chapters. Implementation references below use the inspected [source tree at 7310a95](https://github.com/developing-today/code/tree/7310a95730791e66da98f7b0e13865930058a516/pkgs/id). References to open work identify existing owners' issues. These scenarios have not been executed in this research pass.

At reconnect, reconcile dependencies before advancing the visible projection. | A stale cached grant is evidence of what the device knew. ## Storage and placement as observable contracts

The native port already describes capabilities, limits and typed refusals. The repository includes policy based on operator-local residency evidence, hosted routing to a bound Durable Object namespace, and a hosted range comparison protocol. An eligible read today cannot promise future availability after eviction, quota exhaustion or lease expiry. A stable object identifier lets a recovered copy regain its identity, but does not create another copy. [Core port](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-core/src/port.rs) · [Residency routes](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-events/src/residency_routes.rs) · [Worker routing](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/hosted-worker/src/routing.ts) · [Range protocol](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/hosted-worker/src/range.ts)

Proposed client contract:

| What the app may show | Required evidence | Recovery or downgrade |
| --- | --- | --- |
| Saved on this device | The selected local adapter completed its documented commit boundary. | On reopen, verify the event or recover the last complete transaction. Disclose browser eviction limits separately from successful IndexedDB commit. |
| Delivery pending | A durable local intent has a target and can be replayed after restart. | Retry only within the existing retry, expiry and authority policies. A lost reply leaves the remote outcome unknown. |
| Accepted by a peer | A named accepting peer supplied verifiable evidence with an operation-specific meaning. | Reconcile by event identity. A later peer may have a different custody observation but must agree on the event digest. |
| Retained until a stated time | A valid, scoped commitment binds a peer, object and time. | At expiry, remove the promise. A signed historical receipt can remain an accurate record of what was promised. |
| Available from a peer | A bounded read at an observation time produced bytes matching the expected digest. | Surface a failed subsequent fetch separately. One observation has a time and a scope. |
| Visible in this application | Required parents and content are available, authorized and accepted under the projection’s rules. | Show a missing dependency or pending conflict explicitly where its disclosure is permitted. Shared payload hashes do not override per-caller access. |

ID’s native outbox already syncs queue records, replays unfinished entries on restart and distinguishes refusal, retry and delivery. Its implementation also bounds attempts and finished records. The federation receipt slice distinguishes authenticated evidence from unverified storage claims. The table proposes how callers should interpret these facts. A protocol-specific delivery result must be translated explicitly before a user sees it as acceptance. [Outbox](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-sync/src/envelope_outbox.rs) · [Receipt slice](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-sync/src/federation/slices/b19_signed_receipt.rs) · [Hosted export](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/hosted-worker/src/export.ts) · [Native export reader](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/src/hosted_export.rs)

**Placement decision.** Evaluate access scope and locally trusted placement constraints before sending even a range fingerprint. If all eligible peers are unavailable, retain the local intent and report the placement reason at a disclosure level appropriate to the caller. Transfer and acknowledge only the permitted subset. A peer’s successful transport handshake supplies reachability evidence. Jurisdictional enforcement also depends on operator configuration and separate provider evidence. Routing unit tests and fixture exports cannot establish where a live provider retained replicas, backups or traffic. Preserve the existing jurisdiction chain and the separate authorization for a live canary. [Jurisdiction parent](https://github.com/developing-today/code/issues/3399) · [Canary gate](https://github.com/developing-today/code/issues/2285)

## Differential proof for peer and hosted routes

Define an operation history containing logical request identity, actor, grant/frontier, input digest, explicit clock and outcome. Run identical inputs on a direct path and a hosted path. Compare canonical admitted events, projection outputs at a common frontier, stable refusal classes and retrievable hashes for an authorized reader. Route identities, signatures by different custodians, wall-clock latency and local storage accounting are route-specific and should be checked against their own contracts. Jepsen’s model of permitted operation histories gives a useful way to state exactly which observation would falsify each property. [Jepsen consistency models](https://jepsen.io/consistency/models) · [ID relay gate](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-sync/src/relay_ingest.rs) · [ID pull policy](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-events/src/pull_policy.rs)

| Script at fixed logical time | Independent acceptance oracle | Existing landing point |
| --- | --- | --- |
| Receiver commits, reply is lost, sender restarts and retransmits. | A deterministic expected event set contains one admitted event and one application effect. The sender reports an unknown outcome until it obtains affirmative evidence. | Outbox and relay protocol [#2036](https://github.com/developing-today/code/issues/2036). |
| Withhold two gossip notifications. Deliver a child first, then authorize reconciliation with its missing parent. | Before repair, the visible frontier never claims unavailable prerequisites. On fair delivery within scope and budget, both projections reach the expected digest. With authorization withheld, the denied reader learns no protected parent identity. | Existing range/graph comparison and [five-node bridge #2249](https://github.com/developing-today/code/issues/2249). |
| Disconnect one peer, revoke its read authority at the authoritative frontier and reconnect it. | Historical availability on the disconnected device and future delivery are distinct observations. Evaluate newly requested protected bytes under the declared revocation rule. Replay the request under the same authorization frontier for cross-route comparison. | [Hosted-world parity #10698](https://github.com/developing-today/code/issues/10698) after its owning chain. |
| Compact, interrupt between checkpoints, reopen, then sync against an untouched reference store. | Compare expected durable facts, fork evidence and needed predecessors. Old ephemeral bodies may disappear only under the declared retention rule. | Assigned retention [#3797](https://github.com/developing-today/code/issues/3797). |
| Restore portable export into an eligible fresh store with an interrupted import, then repeat. | Verify event and object hashes, scope, expected projection, explicit unsupported entries and idempotency. Compare an inventory against an independent fixture, so a shared exporter/importer omission fails the check. | [Export/import #3810](https://github.com/developing-today/code/issues/3810) and follow-up [#13313](https://github.com/developing-today/code/pull/13313). |

For each script, record the resolved commit, fixture digest, adapter, profile, seed, clock, sequence of fault injections, expected observation, actual observation and Fleet run URL. A disconnected peer can remain disconnected indefinitely. State liveness as conditional on later authorized connectivity, retained dependencies and available budget. A local safety violation can be demonstrated with a finite counterexample even when the network never heals. Keep host feature absence separate from a failed implementation of a supported feature.

## Releases, recovery and operating evidence

An old local app should be able to open already-authorized content while offline when its declared profile permits that. Accepting a new update has additional conditions. A proposed updater verifies the role authorized for that product and target, metadata expiry under an available trusted time source, persisted version counters, dependency compatibility and artifact digest. Without adequate freshness evidence, preserve the last verified installation and record the pending update. Store sufficient rollback information to recover the previous executable *and its compatible data*. When an update introduces an effect, obtain the new grant before that effect becomes available. Validate required OS and hardware behavior on the named platform. The staged release chapter retains the existing Linux → Android → Web → macOS → Windows priority and proposed per-product tag structure. Packaging and the second desktop remain tied to their existing issues. [Platform packaging #12819](https://github.com/developing-today/code/issues/12819) · [Second desktop #12817](https://github.com/developing-today/code/issues/12817) · [Native shell #12657](https://github.com/developing-today/code/issues/12657) · [TUF client update procedure](https://theupdateframework.github.io/specification/latest/)

Use the four operational signals of latency, traffic, errors and saturation at three boundaries: first usable local view, peer/hosted reconciliation to a declared frontier, and verified restore. Measure each with a defined denominator. For example, calculate reconciliation success from eligible attempts with a defined target frontier, and record ineligible or refused attempts separately. Observe queued byte volume, age of oldest eligible delivery, denied operations by coarse reason, incomplete projections, compaction peak memory and time-to-recover. Bucket by reviewed adapter and profile enums. Use local opt-in correlated traces to diagnose individual runs. Avoid identity, object hash, graph path or namespace as fleet-wide metric labels. ID already separates structured operational logging from audit; keep signed audit evidence in its independently authorized store. [Google SRE monitoring chapter](https://sre.google/sre-book/monitoring-distributed-systems/) · [ID structured logging](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/src/structured_logging.rs)

The staged scale survey reports 958,616 view fuel for the measured Territory fixture at 10k, 100k and 1M events. The fixture concerns a bounded view; it supplies no transport, mobile, join-latency or 3,200-participant evidence. A future result should cite both the benchmark’s independent oracle and the measured workload profile. Keep resident blended cost distinct from peak compaction cost, distinguish cold and warm starts, and record refusals at the 256-participant cap before interpreting a target above that cap. Do not ascribe the 320/3,200 target tiers to measured support. [Frame study #13085](https://github.com/developing-today/code/issues/13085) · [Memory study #13086](https://github.com/developing-today/code/issues/13086) · [Tier decision #13083](https://github.com/developing-today/code/issues/13083) · [Historical join-time study #13084](https://github.com/developing-today/code/issues/13084) · [Workload oracle](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/benchmarks/tests/workload_oracle.rs)

## Implementation order and prerequisites

1. Verify the issue, live owner, dependency status and current main before selecting a slice. Attach parity vocabulary and recoverability claims to the staged federation, store and lifecycle topics. In particular, recheck [#9082](https://github.com/developing-today/code/issues/9082) before editing it. The staged packet already records a bounded IndexedDB adoption decision. Treat a browser transaction, reopening a browser, eviction recovery and durable retained custody as separately observable properties.
2. Prefer one lost-ack operation trace reused by the outbox/receiver and hosted adapter. Publish the expected event inventory before writing adapters, and verify both an interrupted and an uninterrupted history. The five-node relay, hosted-world parity and retention cases each stay with their existing work. A route-dependent grant denial or changed projection is grounds for a finding only after ruling out fixture, capability-profile and frontier differences.
3. Add one restore plus reopen trace alongside the existing export ownership. On a real discrepancy, link a minimal expected inventory to the owning issue/PR after the fresh claim check. Put clocks, schemas, digest inventory and dispatch link in the result. The inspected native export suite already contains delayed and old-key rebind history cases. Reuse these for the recovered binding inventory and add an interrupted materialization check as a separate oracle. Keep provider retention and residency separately gated.
4. Use the packaging slice for a wrong-platform rejection, a stale-metadata rejection, grant-preserving update and recovery of the previous install on one eligible target. Grow coverage per platform on existing release authority. Keep scale and live-service work under their recorded holds. A runnable proposal, a sent dispatch request, an actual completed run and a merged result are four distinct states in the tracking record.
