# References, schema changes and publication across hosts

*Research snapshot of November 23, 2026. Code and issue observations refer to the cited revisions and collection times.*

A note, a gallery entry and an embedding can refer to the same bytes while making different promises to their readers. The design below gives each reference an explicit identity and a way to show what happened when a peer was offline. It builds on three existing ID mechanisms. The friendly-name prototype already stores a logical target, an optional exact revision and the surface the author typed. The version DAG already retains concurrent heads and permits explicit owner selection. The gallery core already verifies bundles and separates its admission policy from signature verification. The first implementation should connect these mechanisms at their existing boundaries. ## What an author can promise a reader

| Author action | Identity to retain | Proposed rendering and evidence |
| --- | --- | --- |
| Refer to a living note by name | Logical target, surface the author chose, optional locator hints | Show a viewer-authorized head or indicate competing visible revisions. Keep the authored surface after a rename. A locator disappearing leaves a resolvable identity. |
| Quote a paragraph or attach a comment to a sketch region | Exact source revision, addressable selector, unit/coordinate convention, optional exact-context evidence | Reopen that revision when authorized. Confirm the excerpt against the pinned source. Offer a proposed reattachment when a successor moves it. Record acceptance as a separate assertion. |
| Follow a mutable path in a sidecar | Store the typed path as specified in the existing related-link design | Missing target yields its defined dangling state. A cache miss supplies insufficient evidence to declare a deletion. Keep the path separate from a byte-exact citation. |
| Import a guest library or presentation asset | Pin the exact bundle/asset and relevant dependency identities at release | Upgrading a friendly alias can affect future resolutions. A previous install and replay can still name the earlier input. Resolve every transitive input from the manifest or refuse with the missing dependency. |
| Describe a result, review or license finding | Issuer, subject at an appropriate revision, type of statement, evidence source and supersession/withdrawal | Preserve contrary authorized claims and let each consumer choose the applicable policy. A license classifier gives evidence to an operator. Executing an effect still requires the corresponding grant. |

Xanadu's treatment of reused text motivates exposing the origin at the point where a quote is read. W3C Web Annotation offers selectors for pieces of a resource, including text and media, and distinguishes a target from information identifying its state. Unison illustrates why a definition can keep its identity across renames and why its dependency identity matters. ID already has multiple hash profiles and signed envelopes. Reusing these ideas requires an explicit object kind, revision and authority check on every traversal. The manuscript need not change the repo's hashing scheme. ## A branching reference with an independently known result

Proposed fixture. Publish note N at revision A with body `red kite`. The selector for the quote uses zero-based half-open Unicode scalar positions [4,8), the exact text `kite` and the pinned revision A. Two disconnected editors produce B with body `red paper kite` and C with body `red kites`, both succeeding A. Replicate C before A on one peer and B before A on another. At the complete authorized causal cut the expected head set is {B,C}. A read of the pin still yields `kite` at [4,8) on A. Copying the offsets to B would select `pape`. Matching `kite` to C would leave the new suffix outside the selection. Neither observation authorizes a silently retargeted annotation. An owner who selects B changes the display of a live reference according to its policy. The quoted archival reference to A stays usable to an entitled reader. A later manual reattachment to B at [10,14) is a second statement with its own issuer and target. This fixture has no concurrent-writer tie-break by wall time. [#9129](https://github.com/developing-today/code/issues/9129) · [Reference rendering and viewer filtering](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/src/references.rs)

Repeat with a reader who may see A and B but cannot see C. Apply the viewer's visibility rule before generating head counts, branch badges, labels, backlinks, layouts or snippet candidates. The expected view for that reader equals the run in which the hidden input C was absent when existence itself is protected. If policy permits an existence-only marker, it must be an explicit separate capability/profile and a different fixture. Revocation can stop future service to a holder while already received bytes remain in a disconnected reader's possession. Local reference text supplied by the author can remain visible under the existing inert-text rule.

## Schema migration without changing what was signed

Cambria explores reusable bidirectional transformations between schemas. ID can adopt the useful part as a deterministic read projection identified by source schema, destination schema and transform identity. Keep the signed input bytes and the origin revision. In current ID, the version-edge rule checks equal schema. A migration that changes the schema should emit a separately identified derived object and typed provenance or use a separately approved cross-schema adapter. Silently adding an ordinary cross-schema `succeeds` edge would violate today's rule. [Cambria](https://www.inkandswitch.com/project/cambria/) · [ID version admission](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-core/src/graph/version.rs) · [W3C provenance relationships](https://www.w3.org/TR/prov-o/)

Use a structured note whose old record contains `title="Kite"`, an extension `ink="indigo"`, and no subtitle. The new view adds an optional subtitle. When an older editor alters the title to `Flight`, the expected underlying state retains `ink="indigo"` and any subtitle a newer client added. An adapter may emit a typed title-only patch binding its source revision. An adapter capable only of whole-record replacement must require a current full-fidelity base or refuse the edit. Two independent oracles compare original object bytes after read-only projection and the set of unedited fields after a write. For ambiguous or lossy transforms, publish the derived result and its known losses. Permit reverse edits only for a documented subset with checked round-trip behavior.

## Moderation, licenses and gallery publication

AT Protocol labels distinguish the labeler, subject, labels and negation. W3C PROV distinguishes entities, activities and agents. Use the patterns to make a local decision legible. Preserve the subject revision, asserting key, evidence and the operator policy that chose to list or withhold the subject. A mirror can fetch verifiable content without adopting another registry's listing decisions. The V4 refined outline explicitly keeps local admission and names questions about paid programs and public mirrors. It is an issue-comment design record. Operator choice, global payment policy and reputation weighting must keep their existing decision owners. [AT Protocol labels](https://atproto.com/specs/label) · [Program ecosystem V4](https://github.com/developing-today/code/issues/6295#issuecomment-6878159503) · [Reputation and disputes](https://github.com/developing-today/code/issues/9147)

At ingest, distinguish a publisher's declared license, the classifier's detected expression, a disagreement, and an unknown result. The ID taxonomy already makes these states explicit. In an Atlas export, record the evidence, subject and classifier/profile version and link to the original expression. A redistributability decision belongs to the applicable configured policy; a download or run still crosses an independent capability boundary. A corrected classifier output should supersede its earlier assertion without deleting either the source artifact or the publisher's declaration. A private operator's decision must not materialize in a public label feed without a publication grant. ## Which decisions require agreement

Under the CALM formulation, adding more facts preserves monotone conclusions. Finding a signed assertion is different from proving that no competing assertion exists. For ID, define the scope and frontier before exposing a local answer such as “only current head,” “no outstanding dispute” or “eligible to spend.” Proposed product wording should identify the fully observed input frontier or report an incomplete view. A disconnected peer can show the two specific revisions it knows. Settling a shared spend requires the ledger's configured admission mechanism, or previously partitioned rights where an approved design supports them. A search result can indicate its local source generation without promising global completeness.
