_Research snapshot of November 23, 2026. Code and issue observations refer to the cited revisions and collection times._

The [What the scale measurements establish and which experiment comes next](research-measurement.md) distinguishes the process-lifetime high-water mark from the cost of an individual phase and records the historical join-time approval boundary.

This review used main `4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a`, the GitHub REST issue census, and the linked issue comments on November 23, 2026. The benchmark values are previously recorded results. This review ran no benchmarks, approved no held work and made no production change.

## What the measured tiers establish

The reference laptop is a Ryzen 7 7840U with 16 threads, 123 GB RAM and NixOS. The frame profile instantiates a Territory guest with two seats and applies alternating cursor moves. It measures the time to render the resulting view and layout five times at each history length. Fuel is the corresponding dedicated call’s last measured consumption. A constant fuel value describes render work for this fixed-state shape; this workload says little about an expanding map, more visible entities, hundreds of participants or the cost of replaying the complete journal. [Benchmark implementation](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/benches/world_bench.rs#L2537) · [Limits table](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/doc/2026-11-23T07-53-00Z_design_scale_perf_stress_v1/2026-11-23T07-53-00Z_design_scale_perf_stress_v1.md#L185)

The memory profile measures baseline-relative RSS of a population of idle worlds, then active worlds with 100 events each, then one hot world. The blended value divides the process RSS increase by all successfully held worlds. The total RSS column includes the process baseline. The 10× population held 10,000 idle worlds, 1,000 active worlds and its capped hot world. Dividing total RSS by count computes a different statistic. The reported tier values are medians of five runs on the same reference machine. [Measurement code](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/benches/world_bench.rs#L2423) · [Results](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/doc/2026-11-23T07-53-00Z_design_scale_perf_stress_v1/2026-11-23T07-53-00Z_design_scale_perf_stress_v1.md#L195)

The process high-water mark after journal recovery, world restore and compaction to a 64-entry checkpoint set, minus pre-operation RSS, was **5.59 MiB at 2,000 entries** and **89.34 MiB at 100,000 entries**. Fixture construction ran earlier in the same process. Each figure is a median across five runs; the measurement does not isolate the compaction phase. The memory sweep encountered no resident-set wall at the measured populations on that host. The full 10× stress program is still outstanding: join latency, sustained concurrent actors and the requested hot-world population have separate evidence requirements. The earlier 5,180 µs per sequential journal append/fsync implied about 193 unbatched appends/s per world. [#8239](https://github.com/developing-today/code/issues/8239) has since closed; current main contains a batched append path, so the earlier estimate cannot serve as the achieved throughput of that path.
