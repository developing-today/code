# Media that remains understandable when the renderer changes

*Research snapshot of November 23, 2026. Code and issue observations refer to the cited revisions and collection times.*

A field notebook contains a signed sketch, a spoken explanation and a private reviewer annotation. It must still open on an offline laptop, make sense on a text terminal and survive export to a machine that has never run the original app. The following design joins ID's existing media records, attachment rules and presentation tiers. It proposes a small rendition and annotation contract. It does not require another media store.

## Existing decisions and a source finding

At inspected main `7310a95730791e66da98f7b0e13865930058a516`, a signed `media.put` event identifies an artifact. Its `MediaRef` describes external bytes with BLAKE3, length, MIME type and optional dimensions or duration. The size ceiling is 256 MiB per artifact and 64 KiB per stream frame. Removing a media reference leaves collection to local maintenance, with a coded 30-day grace after the live reference count becomes zero. The blob gate checks current world membership and references. Knowledge attachments additionally resolve read access per object. OCR and thumbnails inherit the source restriction, while authored annotations are distinct objects with their own authorship and visibility. A readable notebook does not make its referenced attachments readable. [Media implementation](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-store/src/media.rs) · [Root blob gate](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/src/blob_gate.rs) · [Attachment decision](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/doc/knowledge-layer-attachments-media-5844.md)

**Concrete implementation finding.** The reusable `MediaStream::push_frame` checks per-frame size and available frame credit before appending to its buffer. Additional credit can be granted. Aggregate artifact admission occurs in `finish_artifact`, after buffering. The static code therefore permits accumulated bytes beyond the eventual artifact ceiling. A repair should reject the next frame before growth using checked arithmetic and the tighter applicable host or artifact limit. Define whether failure terminates the stream and when memory is released. A test with a small configured limit should cover exact capacity, overflow by one byte, repeated credit, discard, and zero partial artifacts. Review caller reachability separately. No live failure was observed. ## Worked manifest and access decisions

The following names and dimensions describe a **synthetic fixture**. Use actual content hashes computed from the fixture for a future test. The annotation, text and presentation objects stay in their appropriate graph schemas. Only an actual image, audio or video reference uses the existing media header.

| Object | Contents and lineage | Rendering and authority |
|---|---|---|
| `field-note/v1` | Stable note, localized title, ordered references to the sketch and the audio. Text properties distinguish missing translation, explicit empty text and removal. | Private group note. Present authorized children in document order. Do not disclose a withheld target, title, count or filename in a public export. |
| `drawing/v1` | A versioned stroke document with stable stroke IDs and an author-supplied description. Coordinates use declared integer units on a 400×200 canvas. | The editable document is authoritative for its strokes. A PNG master is an independent media object with a signed derivation link. A terminal can present the description and selectable stroke labels. |
| `preview/v1` | A 100×50 crop-free rendition from the pinned drawing. Its recipe specifies orientation, output color interpretation and filtering. Name the renderer revision and result digest. | Use the source's read decision plus any tighter derivative rule. A resource-limited board may display the authored label or glyph and skip rasterization. An operator cannot relax the group's access by transcoding. |
| `speech/v1` and `captions/v1` | A six-second recording and an authored caption at ticks [2000, 4000) with timescale 1000. Record the original audio as one bounded artifact. A trusted host may derive a seek index bound to that artifact. | A reader with only a separately released excerpt gets only that approved media object. An authorized terminal can render the cue without an audio device. If captions are absent, display that fact only to an authorized reader; a generated transcript is a separate derivative with engine and revision. |
| `review/v1` | A private reviewer writes a comment on a stable stroke ID and the original drawing version. The drawing later migrates to a schema with stroke widths. | A reader may see the drawing while the review remains private. A cross-schema migration creates a separately identified signed derivative linked to the source. The existing successor relation requires equal schema. Retain the old bytes according to policy. Replay preserves the distinction between absent old width and an author-supplied value. Keep the old anchor or require a separately reviewed mapping. |

**Proposed host contract.** Resolve a logical object and version, then evaluate object read, blob gate, rendition purpose, local policy and provider capability. Budget transfer bytes, cumulative staging, decoded dimensions and pixels, frames, audio samples, scratch space and elapsed processing separately. Reconcile declared metadata with parsed format metadata before expensive allocation. Cancellation or admission failure leaves no published derivative. For deterministic exporters compare canonical decoded values or bytes only where the transform profile specifies reproducibility. Record exact output bytes and producer revision for externally encoded assets. Adopt the world's semantic fallback ladder and measured device-profile cost decisions for sprites. Preserve authorship or licensed source attribution when exporting an asset or generating a distribution copy. License metadata alone grants no node capability. ## Verification and build order

1. **Bound the existing stream first.** Work from the original [media implementation](https://github.com/developing-today/code/pull/10653) and [artifact decision](https://github.com/developing-today/code/issues/2342). A model summing admitted lengths independently predicts the buffer size, refusal and terminal outcome at every step. Exercise a complete and a cancelled recording. Assemble no more than the synthetic profile allows.
2. **Implement an authorized attachment view.** Use [attachment semantics](https://github.com/developing-today/code/issues/5844) and [partial sync](https://github.com/developing-today/code/issues/5838). Construct peers with identical authorized content, one with an extra private review. Compare permitted projection, thumbnails, search snippets, annotations and exported filenames against independently specified expected sets. Source revocation must invalidate subsequent reads under the profile's freshness contract. A physically disconnected reader's already-delivered bytes remain subject to local retention. Verify resumed transfer and a missing authorized payload independently from hidden-reference behavior.
3. **Add one accessible recipe across Linux and Android.** Work under [presentation assets](https://github.com/developing-today/code/issues/5970) and [device cost](https://github.com/developing-today/code/issues/6012). Use a hand-specified 4×2 pixel test card with transparent and opaque colors. Compare selected pixel coordinates and straight/premultiplied alpha according to the fixture's specified conversion; verify preserved source digest independently. For audio use a generated signal whose sample intervals are prescribed; check exact boundaries, caption time and cancellation. A host without a decoder must still open the note and let a user select named actions. Benchmark once the baseline interfaces and device profiles are fixed.
4. **Prove export can be independently understood.** Use [knowledge interchange](https://github.com/developing-today/code/issues/6439). Run a separate verifier over package bytes, ID event signatures, object-to-payload references and schema definitions. Open a permitted package with the original app absent and compare its stroke order, titles, cue placement and warnings to the fixture. A disclosure-unsafe signed native closure must fail before payloads are written; a redacted interchange export follows its separate contract. Destination import evaluates its own permissions. [Existing native export rules](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/doc/2026-11-08_design_id6439_knowledge-interchange-and-export.md)
