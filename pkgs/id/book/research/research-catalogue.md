# World capability catalogue

_Research snapshot of November 23, 2026. Code and issue observations refer to the cited revisions and collection times._

The [capability catalogue](evidence/capability-catalogue.csv) describes **36 production entries** at [main 7310a957](https://github.com/developing-today/code/tree/7310a95730791e66da98f7b0e13865930058a516/pkgs/id). The source of truth is the assembled Rust registry. Its stable order consists of the 34 entries generated by the host registry macro followed by the two declared client manifests. Six of the host entries are pure, compile-gated Roc modules. The feature-only test entry `RegistryProbe` is outside the production count. This is the world-provider catalogue. Graph admission methods, Rust APIs, MCP tools and proposed future capabilities have separate surfaces. [Registry and assembly][reg]

**Reading a row.** Each row identifies the version, protocol kind, side, required actor scope, default ceiling, disclosure class and argument schema. JSON argument names ending in `?` are optional. The Rust schema names `kv.set.value` as a structured payload and its executor accepts arbitrary bounded JSON. A ceiling allows an operator to offer a capability. A grant, any applicable actor scope, local client consent and OS permission are additional decisions. Each row links the primary signature or pure Roc source and a separate result/dispatch or coverage reference. Result field summaries refer to the successful inner payload or event; requests use the existing correlated result envelope. [Policy and envelopes][reg] · [Host execution][dispatch]

**SDK and execution.** Eight requests have named builders in `RocCap.roc`. Other requests can be represented as data subject to the contract and host support. Building a request has no I/O effect. Six modules appear in the production Roc platform’s `exposes` list. The host authority audit explicitly identifies the two speech requests without an executor. The common parser also leaves `speech.capture` unrecognized. The native-shell source implements opt-in `client.file.read`. The client notification manifest documents a content-free re-sync hint. Each target column distinguishes common host mediation, an identified binding, an unavailable reference path, or a target-specific binding that needs verification. A browser talking to a world host does not establish browser-local execution. No host was built or run to create this table. [Roc helpers][sdk] · [Roc exports][plat] · [Dispatch coverage][audit] · [Subscription parser][sub] · [File executor][file]

**Fuel, fees and bounds.** Wasmtime guest calls use instruction fuel under the configured engine. The provider manifest exposes operational bounds and no fee field. The `host_unit_proposal` column proposes what a host might count, such as bytes hashed, active watches or rows visited. These quantities are neither measured instruction fuel nor currently assessed token charges. The CSV retains the Rust bound expressions by name, including dynamic world limits. A reserved price or fee schedule would need a version, refusal behavior, a settlement rule and a calibration fixture. [Sandbox][sandbox] · [Registry bounds][reg] · [Guest settlement][burn]

**Keeping it current.** On the authorized laptop, extend the production manifest, executor or explicit unsupported disposition, Roc declaration if applicable, and the two-provider-aware exit proof together. Regenerate from the host macro plus `CLIENT_CATALOG_ENTRIES`, resolve the referenced argument and bound declarations, and compare the ordered names, public kind, class and ceiling against the assembled registry. Reject duplicate rows, new unclassified kinds and missing evidence links. Attach separate test evidence before a per-target cell changes from unverified to supported. Keep discovery, failed execution, successful execution and hardware evidence distinguishable. The proposed cross-host oracle feeds the same request to two equivalent profiles with the same grants and asserts the same protocol disposition, payload contract and visible effect count. The [existing exit proof][exit] and [authority-boundary test][audit] provide independent local expectations. Use the current tracking issue and book identifiers for subsequent additions.
