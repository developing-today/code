# What a disconnected node can say about the graph

_Research snapshot of November 23, 2026. Code and issue observations refer to the cited revisions and collection times._

A reader opens a shared mind map on a train. The map has a title, several visible nodes, a redacted reference, and one attachment whose bytes never finished downloading. Those last two cases need different local behavior. Only the interrupted download can be retried as an authorized object. On reconnect, a scope exit can remove an otherwise valid cached result. A search for the old title must obey the same decision as opening the map directly.

## An offline contract for graph apps

**Proposed.** The host keeps private records of snapshot issuer, grant, epoch, manifest digest, verified chunks, available content and the last applied scoped update. The existing snapshot protocol supplies the transfer identity. One authorized working set can contain a complete note and an unavailable video. The host presents item-level readiness only for disclosed objects. An issuer's completeness declaration is evidentiary and bounded by that issuer's view. Local verification establishes agreement with its manifest. Neither observation proves that every peer agrees.

| Event                                                                               | Local transition                                                                                                                                                 | Allowed user-visible result                                                                                                                                   |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An authorized attachment is listed and its last chunk has yet to arrive             | Record the verified manifest entry and retain a restart position. Acknowledge durable writes with the transaction semantics of the actual store.                 | Show “Available after download” for that disclosed attachment. A text-only version of the app can continue.                                                   |
| A requested attachment is outside the grant, or a direct lookup names an unknown ID | Use the accepted existence-privacy rule. References already shown inside a scoped document can carry only the approved opaque placeholder.                       | Direct lookups produce the same public outcome. A placeholder can preserve the documented intra-grant equality without exposing a target ID or remote totals. |
| An update leaves a gap, or local materialized data was evicted                      | Invalidate the affected local readiness claim. Resolve gaps by fetching a fresh scoped snapshot. Preserve separately authorized drafts.                          | Distinguish readiness of local material from the state of the issuer. Do not infer a deletion.                                                                |
| A scope exit is applied while the app has a page open                               | Remove its visible supports before releasing subsequent query, history, preview or index results. Obey configured local retention and deletion rules separately. | New views consistently withhold the item. A local implementation cannot retract bytes already exported to another principal.                                  |

Apply the same contract to the hosted backstop, native disk store and opt-in browser projection. Conditional on the outstanding [store decision](https://github.com/developing-today/code/issues/9082), compare native and browser outcomes across failure immediately before and after committing the frontier. An oracle must recognize loss of the browser cache as a recoverable loss of materialization. The staged Chromium handle-close evidence alone does not establish process-crash durability. ## A native federation question precedes optimization

The native initiator constructs its hello from the replica inventory and refused-event set. The responder constructs its reply the same way and includes IDs of divergent objects. B09 filters envelope offers based on the link configuration, and the wire representation carries withheld IDs with reasons. This matters because B09 describes an **internal implicit-trust link**, whereas the scoped-grant transfer design deliberately hides ungranted existence. The files establish what enters these messages. They do not establish who may reach each deployment, whether an internal peer is entitled to that metadata, or authorization to file or implement a resolution. [Initiator](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-sync/src/federation/exchange_net.rs#L586) · [Responder](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-sync/src/federation/exchange_net.rs#L773) · [Wire offer](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-sync/src/federation/exchange_net.rs#L412) · [B09](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-sync/src/federation/slices/b09_anti_entropy.rs#L288)

**Proposed disposition.** Under [implicit-trust sync #9142](https://github.com/developing-today/code/issues/9142) and [partial replication #5800](https://github.com/developing-today/code/issues/5800), document which peer class may learn metadata in each message before extending the exchange to any more restrictive profile. Review caller authorization and deployment boundaries. A peer entitled to metadata for the complete internal replica can retain that contract if that entitlement is explicitly enforced. Any grant-limited integration should compute the permitted inventory before forming identifiers, digests or refusal reports. A synthetic conformance fixture compares public protocol fields in two worlds differing only outside the grant, on both sides of a reconnect; compare local diagnostics separately. Timing and traffic-size equivalence require their own measurement. No network test, leak or external exposure is asserted.

## Atlas search and publication acceptance

**Proposed public navigation contract.** The host fixes content frontier, path-binding generation and view ordering for a page series. On resume, recheck authority and the desired binding semantics. Continue the same permitted view or require a restart with a uniform, nonrevealing outcome. An explicit pinned link may continue to an old retained version if authorized. An alias selected as “follow current” must visibly re-resolve a rename or concurrent rebind. Projected tag claims, duplicate supports and the order of visible edges must behave the same through CLI, GUI, agent and embedded APIs. Page cursors are opaque continuation aids; possession supplies no independent authority. [Navigation #7612](https://github.com/developing-today/code/issues/7612) · [Reference matcher](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-core/tests/graph_query_reference.rs)

**Proposed derived-index contract.** For each emitted fact keep the source assertion, transform revision and visibility partition. For embeddings add immutable content identity, chunk coordinates plus normalization and chunker revision, and model/tokenizer revision. Keep source provenance and visible support at result time even if bytes or vector computation are deduplicated inside an allowed storage boundary. Two identical public/private attachments may share content bytes while their titles, paths, spans and explanations have different visibility. A projection retraction or subject removal must invalidate lexical results, neighbor expansion, result counts, snippets and local response caches under the same serving decision. A model migration builds an independent generation, records coverage and validates it against exact retrieval before a switch. A policy cannot guarantee immediate revocation on an isolated peer; report and enforce its specified freshness contract.
