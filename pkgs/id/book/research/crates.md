The architecture document identifies the root `id` crate as the public entry point. Its re-exports expose selected parts of the internal crates. For embedders, introduce compatibility promises at an explicit boundary with a minimal consumer fixture. Start with a headless, authorized read of a graph snapshot and a renderer consuming only the projection. Record feature sets, default dependencies, serialization versions, and refusal semantics. Treat the CLI, TUI and hosted routes as clients of that interface. [Public entry point](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/src/lib.rs) · [Architecture](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/ARCHITECTURE.md)

**Currency registry.** The root depends on `id-currency-registry` and uses it from the currency gateway and reconciliation code. Retain the library. Document the seam where the portable registry feeds the root, then check the same fixture through both callers. The architecture table already lists the root consumer. [Gateway](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/src/currency/gateway_poc.rs) · [Reconciliation](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/src/currency/reconcile.rs)

**Rendering.** `id-render` contains a compiler for semantic markup. It validates assertions, composes a target-neutral representation and lowers it to web, native and custom GUI outputs. Its own fixtures exercise those lowerers. Keep it as the renderer library with an explicitly recorded integration gap. Proposed first consumer is a fixture-based preview through the existing developer tooling. Compare native and web action identities, accessibility roles and defaults against independently named expectations before adding a public re-export. [Renderer](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/crates/id-render/src/lib.rs) · [Conformance fixtures](https://github.com/developing-today/code/tree/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/crates/id-render/tests)

**Importer and shells.** `id-import-notion` defines an injectable acquisition boundary plus durable inventory and resume primitives. Record it as an importer awaiting a production caller. The native and hardware shells are execution endpoints. Having no crate above them is expected for their role. [Importer](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/crates/id-import-notion/src/lib.rs) · [Native shell](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/crates/id-native-shell/src/main.rs) · [Hardware shell](https://github.com/developing-today/code/blob/4cfceaa8afc08cf2cea88b9d733a2ace14c8ad5a/pkgs/id/crates/id-hw-shell/Cargo.toml)
