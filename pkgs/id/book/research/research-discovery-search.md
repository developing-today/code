# What a reader can find in the ID graph

*Research snapshot of November 23, 2026. Code and issue observations refer to the cited revisions and collection times.*

**Proposed addition to the graph, Roc host and platform chapters.** At main `7310a95730791e66da98f7b0e13865930058a516`, ID has a typed triple matcher and derived indexes, and Atlas already offers a reusable retrieval pipeline, a lexical branch, several vector strategies, fusion and an evaluation harness. The next integration decision is what counts as a reader's *searchable corpus*. An authorized object, an authorized edge to it, and permission to include its text in a hosted model request are three different propositions. Clarifying these lets us design a useful local-first search without assuming that a common index may answer every question. ## Navigation and rank have different contracts

Falcor's path sets let a client specify the fields it wants through aliases or references. Datomic demonstrates parameterized relations over a database value with an explicit historical basis. Compose these ideas in ID by lowering a bounded path into typed triples evaluated against one identified content snapshot of admitted assertions. For example, a board's visible notes and their tags can be collected with a bounded relation join and assembled into the requested path shape. Include the assertion ID and provenance for every selected edge. Two signed annotations with identical endpoints remain distinguishable. Traversal never enters an inaccessible edge or object, even if another path could reach its endpoint. Read authority is checked against current policy when serving a historical frontier. [Falcor path sets](https://netflix.github.io/falcor/documentation/paths.html) · [Datomic query data reference](https://docs.datomic.com/query/query-data-reference.html) · [Datomic database values](https://docs.datomic.com/reference/filters.html) · [ID reference matcher](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-core/tests/graph_query_reference.rs)

A local frontier identifies a snapshot. A remote issuer making a completeness claim about a particular frontier should bind that frontier to its attestation as a proposed extension. Stable navigation pages can store the last public sort key for the pinned frontier. A search cursor additionally needs retrieval generation, rank parameters, policy scope/epoch and stable source identity for ties. If any changes, start a fresh query. Existing Atlas fusion breaks tied scores on best branch rank then chunk ID. The cross-device ID adapter should explicitly map index rows to stable source IDs so a rebuild that reallocates local row IDs cannot reorder equal-scoring objects without a declared cursor reset. Differential dataflow suggests maintaining derived rows through additions and retractions. Apply that idea first to ordinary local indexes with watermarks. Measure replay and correction cost before adopting an incremental query engine. ## A worked retrieval oracle

Use query embedding (1,0). These intentionally small vectors are a synthetic algebraic fixture. Each candidate's cosine distance is one minus its normalized dot product with the query. The lexical ranks below are stipulated inputs to the fusion oracle. They are independent of tokenizer or BM25 implementation.

| ID | Reader can see | Vector | Exact distance | Visible vector rank | Visible lexical rank |
|---|---|---|---:|---:|---:|
| 11 — A | Yes | (4,3) | 1/5 | 1 | 2 |
| 22 — B | Yes | (0,1) | 1 | 3 | 1 |
| 33 — C | Yes | (3,4) | 2/5 | 2 | Absent |
| 44 — H | No | (1,0) | 0 | Excluded | Excluded |

With both branch weights equal to one and fusion constant 60, A scores 1/62 + 1/61, B scores 1/61 + 1/63, and C scores 1/62. Expected fused order is **A, B, C**. A top-two vector search over the whole collection followed by filtering returns only A, while the exact authorized vector answer is A, C. Fetching more candidates can improve recall, but the stop condition must report when the permitted search budget cannot establish a full requested page. For the strict local profile, a scan over authorized rows is a simple reference and fallback. Atlas already implements exact scan as its default vector strategy and a depth-escalating indexed alternative. LibSQL documents the accuracy tradeoff in its DiskANN index. [RRF paper](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf) · [Atlas vector strategies](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/atlas-search/crates/atlas-core/src/lib.rs#L12-L21) · [libSQL vectors](https://docs.turso.tech/features/ai-and-embeddings)

Give A a readable edge to C, C a restricted edge to B, and A a route to B through H. A one-hop expansion of A may show C and the permitted assertion. No expansion emits H, the restricted C–B assertion, or an inferred A–B shortcut through H. If B appears independently via lexical retrieval, attribute the result to that branch. This prevents a misleading explanation of why the reader can see B. Keep graph expansion a separately labelled phase until an evaluation establishes an explicit, versioned ranking contribution.

**Ranking statistics require a separate decision.** Atlas filters permitted candidate rows inside its SQL, then sorts by `bm25(chunks_fts)`. SQLite's BM25 uses term frequencies and document-length statistics from the FTS table. Changing other rows can consequently change the ordering of readable hits. This matters if an ID deployment promises that changes wholly outside a reader's view cannot change visible ranking. The narrower contract that every returned row is authorized does not require this property. A test fixture can keep two visible one-token hits (“orchard” and “beacon”) and three neutral rows constant, while switching twenty private one-token documents from orchard to beacon. The rarer query term reverses between corpora. For a strict view, use an authorized local lexical corpus, physically separated common visibility scopes, or versioned public weighting over allowed postings. Define which contract each profile offers. Even shared ANN can vary under the addition of inaccessible vectors. Test hidden-only mutations for exact eligible rank, stable count, explanations and pagination where that stronger contract is advertised. This is a design condition for ID's proposed adapter. ## A bounded host ABI and an accessible viewer

Propose three host operations with distinct units. A batched embedding call admits text bytes, token limits, number of examples, model and output capacity before producing an owned immutable result. A linear solve admits scalar type, rows/columns, algorithm and scratch capacity. A geometry operation uses explicit point/vector semantics, axes and units. Represent interop numeric data with element type, shape and contiguous little-endian layout. Validate dimensions and checked products before allocating, reject non-finite and zero-norm input for cosine, and charge repacking and workspace separately. A batch of 128 rows of 768 f32 values requires exactly 393,216 bytes for the vector buffer alone, plus 512 bytes for one f32 distance per row. Tokenization, allocator overhead, model state, and workspace need separate limits. Refuse an oversize call or negotiate a smaller batch before materializing it. The existing embedder is the first model adapter. Profile host-only faer for decompositions, nalgebra for geometry, and ndarray views for shaped interchange when a measured workload warrants them. The app ABI can remain stable across these choices. [faer](https://docs.rs/faer/latest/faer/) · [nalgebra](https://www.nalgebra.rs/docs/user_guide/points_and_transformations/) · [ndarray](https://docs.rs/ndarray/latest/ndarray/struct.ArrayBase.html)

For the viewer, build one authorized node/edge collection before calculating degrees, paths, community grouping, force layout or bounding boxes. A hidden node added to an unauthorized graph must not move visible nodes under the strict profile with a fixed layout seed and identical starting coordinates. Cytoscape's compound parent dimensions depend on its descendants. Graphology supports keyed parallel edges, and Sigma v3 is the archived WebGL rendering reference. A local table, Cytoscape inspector and optional WebGL overview should select the same assertion ID and offer the same permitted actions. Keep inaccessible vertices out of all three data models. Benchmark the same visible graph for label legibility, interaction latency, memory and keyboard access before selecting a renderer by workload. [Cytoscape.js compounds](https://js.cytoscape.org/#notation/compound-nodes) · [Graphology](https://graphology.github.io/) · [Sigma v3 archive](https://v3.sigmajs.org/) · [ID visualization #9126](https://github.com/developing-today/code/issues/9126)

**Evaluation order.** First reuse ID's reference matcher and index-rebuild fixture for navigation. Second add the four-vector fixture, two lexical corpus variants and fixed-seed layout to a proposed ID scope test. Third run the Atlas evaluation format over separate lexical, dense, hybrid and expansion configurations with per-view relevance judgments. Report recall@k against exact authorized nearest neighbors separately from judged relevance, nDCG@k/MRR, chunks per parent, fallback fraction, p95 latency and peak resident bytes per host. Include identifiers, Unicode, absent models, rare terms, restricted rows and incremental model cutover. An embedding parity test checks token/vector compatibility only. Quality, authority and host limits require their own oracles. These checks are planned and have no execution or deployment result in this pass.
