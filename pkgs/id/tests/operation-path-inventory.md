# Operation path inventory — admission and hooks (ID/Atlas slice 9110-13)

Issue: developing-today/code#10177. Design basis:
`doc/2026-11-13T03-40-00Z_design_id-atlas-summit/crosscut/versioned-design.md`,
section "Operation pipeline (mandatory ordering)". Port contracts: slice
9110-02 (issue #10160, closed) — `crates/id-core/src/port.rs`,
`PORT_CONTRACT_VERSION = 2`.

The design's exit rule for this slice: "Before claiming extensibility
coverage complete, inventory every normal ingress/read/write/sync/query/
stream/bucket path and identify its adapter, gate location, hooks, bypass
tests, and recovery semantics." This document is that inventory for
`pkgs/id`. Entries whose path has not yet migrated to the fixed gate are
listed explicitly as `partial` or `unmigrated`; per the issue, explicit
unmigrated entries block the completeness claim until covered.

## Completeness: NOT COMPLETE

The V2 exit gate is not met. Two paths are `unmigrated` (federated query
slices are registry-only; no production object-bucket adapter exists) and
most paths are `partial`: they reach a real fixed check today (signature
verification, the membership admission gate, the blob gate, import
verification) but not yet the full uniform pipeline (versioned-config
resolution, replay/idempotency, tenant/scope authorization, pre-commit
reauthorization, ordered hook phases). No row in this inventory may be
read as proof that the uniform gate covers that path yet.

## Method

Rows were enumerated from the checked-in source at the slice branch base
(origin/main 3a8e96fc18): the port-contract surface from 9110-02, the
membership admission gate, the blob gate facade and its owning crates,
the sync envelope/protocol handlers, the event-store ingest path, the
world journal, hosted import/export, the backup mesh, grant/key
presentation, the web router, log sync, and DHT discovery. Every row
names a file and symbol that the coverage test
(`tests/admission_path_coverage.rs`) re-verifies against the source tree
on each run, so a moved or renamed entry point fails the test instead of
silently invalidating this inventory.

## What blocks completeness

1. P-QY-01: implement the federation query slices behind the fixed gate
   (query grants and privacy are slices b17/b18 in the registry) or keep
   this entry unmigrated; the completeness claim stays blocked either
   way until the slices land gated.
2. P-BU-01: land a production object-bucket adapter against
   ObjectBucketPort with the store adapter conformance suite passing.
3. Every `partial` row: migrate the path onto the full mandatory
   ordering — versioned config and capability check, fixed admission
   (signature, semantics, replay/idempotency, authorization,
   tenant/scope), ordered prepare hooks, pre-commit reauthorization,
   commit, post-commit delivery — and add the bypass test named as
   MISSING in the row.
4. Hooks: no path runs the design's typed hook lifecycle today. Hook
   coverage claims are blocked until at least the prepare and
   post-commit phases exist on the gated paths and the hook model tests
   from the design's conformance section pass.

## Maintenance rule

Adding a new normal path to `pkgs/id` requires a new row here in the
same change. `tests/admission_path_coverage.rs` carries the canonical
path-ID list and fails when the inventory and the list diverge, when a
row is missing a field, when a named entry point or bypass test no
longer exists, or when this document claims completeness while any row
is not `gated`.
