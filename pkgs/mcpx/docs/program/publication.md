### Source-backed extension to the existing gate

1. **Record semantic IDs and source evidence.** At each checked ref, emit command paths with visibility and aliases, flag IDs keyed by defining command plus scope, and the settings registry with conditional defaults, scope, accepted resolution layers, named probe or specific exemption. Join probe declarations to a separate result carrying test name, dispatch handle, platform, input SHA and oracle. Do not treat a test name as evidence of an executed test. Extract frontend and upstream transport registrations by direction and public Go declarations and methods by package/receiver/signature under the supported tags. Populate the checked inventory from code and the released binary's isolated help/schema paths. Keep historical snapshots as historical rows.
2. **Bind IDs to the operator reference.** Require a published chapter and valid section anchor, or an explicitly owned named gap. A shared table-level anchor is acceptable if the row identifies the subject; an arbitrary mention in an archive is insufficient. Pair the subject with its relevant meaning, such as flag owner, accepted setting layers or restart effects. Render per-setting named probe/exemption details adjacent to the existing registry-generated reference. Derive provenance examples from synthetic config in an isolated environment. Add no live secret values or live paths to the book.
3. **Check base-to-head changes.** Compare sets and behavioral signature fields per semantic ID. Added or changed entries update their current section in that change, and deleted entries remove or mark superseded the public reference. Keep corrections on archived chapters with scope/date/replacement. Preserve existing placement, docs-twins, command registration and effect-ratchet tests. Compare severity and identity of known gaps so exchanging one gap for another with the same count fails.
4. **Run the negative controls remotely.** A new flag on an existing command, a shadowed inherited flag, a new conditional default at the same setting path, a changed public method receiver, removal of a chapter from SUMMARY and a README link to a missing rendered file must each produce the corresponding diagnostic. Capture both the documentation build receipt and the published verification. The coverage chapter itself discloses a remaining size warning in its search-index build; require the actual runner's warning stream before declaring the zero-warning criterion met. [Existing gates](https://developing-today.github.io/code/coverage.html#the-gates-that-hold-this)

Two additional cross-checks belong in the working queue. The landing page advertises a 0.1.0 download, while Install describes several tag-driven channels as waiting for their first tag. Verify the actual tag, release asset/checksum and registry publication for each platform before changing the claimed channel. Separately reconcile the Install chapter’s system-service row with the Nix module and distinguish the installer-created unit from a Nix-provisioned service. Those product states require source and release receipts. [Home page](https://developing-today.github.io/code/) · [Channels](https://developing-today.github.io/code/install.html#channels)
