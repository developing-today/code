# High-level roadmap

This chapter is mcpx's section of the whole-project priority list: the merged census of record for the Code Book programme. The full merged list, ordered across the whole project, lives in the [Code Book](https://developing-today.github.io/code/code/); the programme is tracked on [#13905](https://github.com/developing-today/code/issues/13905). The ordering logic is stated once there and summarised here: execution substrate first (nothing else lands without a trustworthy queue, build capacity, and transport), then the physical substrate, then the data substrate, then search intelligence, then the ID platform build-out, then the gateway, PM and fork surfaces, then the record itself. Within a tier, dependency order wins; ties break on leverage.

One item is mcpx's own and is given in full below. The remaining mcpx-assigned items belong primarily to another book; they appear as one-line entries at the end, each linking to the primary book's high-level roadmap chapter. This book previously carried its programme in its trackers rather than in a roadmap chapter; the [MCPX research and implementation plan](overview.md) carries the implementation order and acceptance conditions, and the [MCPX issue map](issue-map.md) carries membership, dependencies, status and evidence issue by issue. This chapter cross-references both rather than duplicating them. Statuses are as of the 2026-11-23 census unless a later read is named. Timing is taken from the census record: where the record has no timing, this chapter says so rather than projecting a date.

## 25. mcpx completion — supervisor, session resume, config tail, embedding surface

- **Type:** problem.
- **Description:** Finish the MCP gateway: a supervisor owning every stdio child's pipes for its whole life (replacing the takeover handoff), cold-restart session resume completed, the settings effect-probe exemption tail burned to zero, and the embedding/API surfaces (Go API, C ABI, WASM, mcpx as its own upstream) decided.
- **Status:** in flight, close on several fronts. The daemon, roughly 50 commands and 252 settings are live; this book is the largest in the project (84 chapters, roughly 288k words) and is the Pages root. Atlas→mcpx integration is live: the laptop's mcpx carries the `atlas` remote server. The supervisor design ([#1384](https://github.com/developing-today/code/issues/1384)) and Phase 3 supervised stdio by default ([#9963](https://github.com/developing-today/code/issues/9963)) have merged PRs, with the acceptance check owned by [#13264](https://github.com/developing-today/code/issues/13264); the issue map records that PR #11343 made supervision opt-in and that the default change still requires verifying distinct sockets and children for two instances of the same configured name across a restart. Session resume ([#1414](https://github.com/developing-today/code/issues/1414)) has phases 1–2 landed; the Phase 3 DELETE question is open. OAuth for remote servers ([#1950](https://github.com/developing-today/code/issues/1950)) landed 2026-11-23 (PR #12869).
- **The exemption tail, with its counting rule stated:** the programme census counted exactly 8 settings — 5 unheld/unclaimed, and 3 flag-held (`plugin.instructions`, `plugin.disabledTools` via [#8472](https://github.com/developing-today/code/issues/8472); `protoTasks.cancelGrace` via [#8473](https://github.com/developing-today/code/issues/8473)). This book's own pinned inventory tells the later story: at `d24c19c6e065` all 241 published setting paths matched 236 named-probe rows and five exemptions, as recorded in [Effect probes and test venues](settings.md) and the [MCPX research and implementation plan](overview.md). The two counts use different snapshots — the census counted the flag-held settings in the tail, the pinned inventory counts exemptions remaining after probes landed on November 23 — and the tail's direction is the same in both: shrinking to zero.
- **Most related:** [#13264 mcpx programme tracker](https://github.com/developing-today/code/issues/13264) · [#1900 backlog super-tracker](https://github.com/developing-today/code/issues/1900) · [#1384 supervisor design](https://github.com/developing-today/code/issues/1384) · [#9963 Phase 3: supervised stdio by default](https://github.com/developing-today/code/issues/9963) · [#1414 session-resume design](https://github.com/developing-today/code/issues/1414) · [#1877 embedding mcpx](https://github.com/developing-today/code/issues/1877) · [#1950 OAuth for remote servers](https://github.com/developing-today/code/issues/1950) · [#1940 code-mode interop](https://github.com/developing-today/code/issues/1940) · fleet-MCP design-mill passes #10389/#10390/#10393/#10405 (all open at census).
- **Timing:** the exemption-tail shrink log is dated per setting (2026-11-17 → 2026-11-23, the #8467–#8474 chains); 11 sibling plugin exemptions cleared 2026-11-23. [#1950](https://github.com/developing-today/code/issues/1950) OAuth landed 2026-11-23 (PR #12869). The programme tracker [#13264](https://github.com/developing-today/code/issues/13264) was filed 2026-11-23T12:39Z. No completion date in record; nothing has missed against one — the tail is reprioritised by gates, not dates: the three flag-held exemptions move only under their item-specific approvals, and the supervisor default waits on the restart verification named in the [MCPX issue map](issue-map.md).
- **Ordering rationale:** mcpx is the tool gateway every agent already uses daily, so its reliability items outrank its expansion items; it sits in Tier 5 of the merged list because Tiers 0–4 are its dependencies, not its dependents.
