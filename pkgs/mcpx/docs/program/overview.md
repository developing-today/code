# MCPX research and implementation plan

MCPX lets clients discover a tool, inspect its interface and call it through one gateway. Tool search answers which operation to invoke. Atlas searches documents after the caller selects its search tool. The two rankings have different inputs, permissions and feedback. [Commands](../cli.md) · [Integration contracts](interop.md)

This program covers the client, daemon, server pool and consumers. The chapters distinguish proposed behavior, implemented interfaces, runtime observations and the evidence required for completion. An open tracker can contain a merged implementation. A named test proves that a check exists; an execution result also requires the commit, venue, non-skipped assertion and outcome. [Program tracker](https://github.com/developing-today/code/issues/13264) · [Published coverage audit](../coverage.md)

## Maintaining the evidence

The [issue map](issue-map.md) records membership, dependencies, status and evidence separately. Check the latest claim before changing a shared component. The [maintenance epic](https://github.com/developing-today/code/issues/12459) owns recurring reliability work. The [platform tracker](https://github.com/developing-today/code/issues/1900) retains references from the predecessor repository. Keep the repository name on those references when reconstructing dependencies.

At [d24c19c6e065](https://github.com/developing-today/code/tree/d24c19c6e0654f2466fc98bc86e3dacb786f5067) all 241 published setting paths matched 236 named-probe rows and five exemptions. The 236 rows refer to 225 distinct test functions. The [pinned inventory](settings-d24c19c.csv) includes declared defaults, provenance documentation, environment names, function definitions and written reasons. Winning values belong to an individual running process.

For each implementation, save the Fleet handle, commit, runner, non-skipped assertions and outcome. Use the same fixture for an unchanged neighbor, a refused operation or a fallback as appropriate. Distinguish a merge, passing checks and observed deployment. Update the relevant reference in the same change that alters a command, flag, setting, transport or route.
