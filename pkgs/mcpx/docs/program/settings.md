## Wasm embedder selection and reload

The latest #8471 checkpoint parked task 20152 after replacing its final runtime-ledger exemption line with a reasoned settings exemption. PR #12725 merged. On November 23 the issue remained open with both parked labels, and the open-PR search for `wasmPath` returned zero. The registry still had five exemptions. The tracker decision and the missing product probe are separate facts. [Checkpoint](https://github.com/developing-today/code/issues/8471#issuecomment-7088142178) · [Merged PR](https://github.com/developing-today/code/pull/12725) · [Effect map](https://github.com/developing-today/code/blob/1f9bc15391ca1c2efa639463a6369392456c27e5/pkgs/mcpx/internal/settings/effect.go#L287)

Use a synthetic in-tree module with a reviewable WAT source beside its small reproducible Wasm binary. Export one linear memory and `embed(i32 pointer, i32 UTF8ByteLength) -> i32 outputPointer`. Its optional allocator may return 64. Reserve output at byte 4096 and return a 384-float vector with component zero equal to the input's first byte, component one equal to its UTF-8 byte length and all others zero. Use two short literal inputs with unequal byte lengths, including one multibyte code point. No model weight, network, compiler or credential is needed during the test. The oracle must read vectors from the ordinary API, since an absent export, embed error or missing module can silently activate the built-in fallback.
