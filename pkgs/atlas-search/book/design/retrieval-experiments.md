# Planner, approximate search and ranking experiments


Compile a query in two steps. The core authenticates the client and resolves the permitted corpus IDs, tier, policy generation, current tombstones, and index generation. It intersects these with explicit request filters. The planner accepts this already narrowed scope, a query, optional conversation references and a deadline. Its output records query class, exact filters, strategy, original-query branch, any bounded variants, maximum candidate budgets and reasons. Use an opaque scope handle that every branch requires. Resolve conversation references and previous turns under the current identity and scope. Authenticated client identity is distinct from the indexed source-client field accepted as a content filter. The planner may narrow eligible material. Conflicting hard filters produce a defined validation error or empty intersection. Never recover by broadening scope.

| Input class | First serving experiment | Measurable oracle |
| --- | --- | --- |
| Exact ID, symbol, commit, file path or quoted literal | Preserve case, punctuation, quoting and negation. Route to scoped exact lookup and/or FTS with deterministic tie ordering. Keep hybrid as control. | Exact match rank, MRR, quoted reference retention, false rewrite rate |
| Structured request with explicit kind/topic/project/source-client/date | Parse a typed allowlist. Bind values. Use a fixed reference clock/time zone for relative dates and half-open intervals at DST boundaries. Limit extracted filters to unambiguous text. Explicit structured parameters and authentication prevail. Keep ambiguous text searchable. | Filter precision/recall by field, exact effective-set equality, identical interpretation across REST/MCP/CLI |
| Follow-up referring to an earlier entity | Add the nearest unambiguous authorized antecedent as a second lexical/dense variant, preserving the original utterance. If history is absent, ambiguous, expired, from another identity or no longer authorized, use original only. | Context-sensitive pairs, stale context, pronoun ambiguity, cross-session rejection, changes in nDCG@10 |
| Ordinary topical or alias-only | Use scoped BM25+dense. Test curated versioned aliases as a lexical expansion only when source and token class support the mapping. Avoid synonym expansion inside quoted identifiers. | Topic-stratified candidate recall, semantic-twin precision, alias recall, number of branches and p95 |
| Underspecified conceptual request | Shadow one local HyDE branch and retain the original query. Embed generated text as a *document*. Treat generated content solely as a search vector. Compare against one ordinary rewrite with the same budget. | Incremental relevant documents exclusive to the branch, no-answer false positives, token/latency cost |
| Explicit comparison or broad conceptual question | In separate ablations, decompose into at most two queries or generate one step-back abstraction. Keep original branch and route every variant through the same scope. Deduplicate normalized variants before retrieval. | Evidence coverage for both subquestions, off-topic rate, recall per extra branch |

Proposed fast path uses a finite grammar, bounded input and deterministic classifier, with p95 below 10 ms on the serving machine, measured separately from transform inference. Decide between literal, filtered, contextual and topical classes before costly transforms. Enforce hard limits on original plus generated branches, context size and total elapsed time. Results carry executed strategy and degraded-state enum. Timeout or model failure leads to a scoped baseline. Ignore duplicate results within a branch, merge on eligible canonical chunk/occurrence identity, and preserve alternative authorized provenance. Cap the total voting weight of a generated-query family so near-duplicate rewrites cannot multiply a single intent. Freeze baseline RRF parameters and declared tie breaker before comparing. Evaluate lexicon expansion, multiple query/RRF, HyDE, decomposition and step-back one at a time on designated classes. The original studies establish mechanisms and research settings. Atlas needs its own comparisons. [Conversational rewriting](https://arxiv.org/abs/2112.08558) · [RRF](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf) · [RAG-Fusion](https://arxiv.org/abs/2402.03367) · [HyDE](https://aclanthology.org/2023.acl-long.99/) · [Step-back](https://arxiv.org/abs/2310.06117)

For #5773, test spelling off/deprioritized/on independently of rewrite off/deprioritized/on. Limit candidates to a scoped corpus vocabulary by frequency, Damerau–Levenshtein distance and trigram overlap. An error paste, code symbol or quoted exact phrase stays literal. For #5774, preserve raw mode and explicit zero signal weights, persist the effective parameter vector, and expose per-hit raw-only / rewritten-only / both membership. ## Eligibility and ANN design

The SQL boundary matters. libSQL documents a three-argument `vector_top_k(index, query, k)`. Its documented metadata-filter example joins and filters after selecting indexed candidates. If the only allowed result is the (k+1)st neighbor, this query can return nothing. For Atlas, select physical partitions containing only eligible rows before invoking ANN. For other combinations use an exact scan of the eligible row set, or a backend shown to honor predicates within candidate generation. Apply this discipline across FTS, lexical/sparse, dense, graph, profile and learned ranking. Ensure branch/token statistics and snippets derive from permitted partitions. Record the model, index generation, scope generation, partition map and applied filters with an evaluation run. While the reported mixed-monolith condition is unresolved, admit only verified eligible partitions on the low-ceiling path. [libSQL vector functions and index usage](https://docs.turso.tech/features/ai-and-embeddings)

Reference fixture for a disposable libSQL database, proposed for Fleet dispatch. Use deterministic scalar cosine as an independent oracle. Separate databases or partition-bound stores are appropriate in production. The two tables here demonstrate the candidate-selection issue without any corpus input.

```sql
CREATE TABLE all_docs (doc_id INTEGER PRIMARY KEY, allowed INTEGER, v F32_BLOB(2));
INSERT INTO all_docs VALUES
  (1, 0, vector32('[1,0]')),
  (2, 1, vector32('[0.8,0.6]'));
CREATE INDEX all_vec ON all_docs(libsql_vector_idx(v));
CREATE TABLE allowed_docs (doc_id INTEGER PRIMARY KEY, v F32_BLOB(2));
INSERT INTO allowed_docs SELECT doc_id, v FROM all_docs WHERE allowed = 1;
CREATE INDEX allowed_vec ON allowed_docs(libsql_vector_idx(v));

-- Exact eligible result must be 2.
SELECT doc_id FROM allowed_docs
ORDER BY vector_distance_cos(v, vector32('[1,0]')), doc_id LIMIT 1;

-- Eligible index must also yield 2. Assert which index the planner opened.
SELECT id FROM vector_top_k('allowed_vec', vector32('[1,0]'), 1);
```

Augment with an empty authorized set, restrictive date interval, expired grant, query switching ceiling, deleted source, duplicate content at two ceilings, index read ahead of tombstone sync, and fallback to exact search when a filter cannot be pushed down. Instrument the synthetic backend to record candidate IDs visited and index handles opened. Merely observing clean final hits misses hidden reads. Never log raw candidate IDs/text from real secret-tier data. Cache invalidation must precede serving a query under a changed policy. For replicas, verify policy/tombstone freshness before use. A disconnected client cannot promise immediate revocation from cached data. Offer disconnected operation only within an explicitly accepted freshness model, or for independently shareable snapshots. Turso documents that changes from other replicas become visible at sync; version-pin and probe both target runtimes. [Turso embedded replicas](https://docs.turso.tech/features/embedded-replicas/introduction)

Do the smallest capability experiment first. Inspect schema and index declarations. Native float32 vectors also occupy BLOB storage, with 4 bytes per component. Verify dimensions, endian decode, finite values, norm and scalar cosine for synthetic vectors matching the producer’s serialization, then a tier-appropriate local sample. Compare the pinned service engine and embedded-replica engine. Check availability of `vector_distance_cos`, `libsql_vector_idx`, and `vector_top_k`, correct positive/negative/self distances, row identity after sync, update/delete behavior and restart. Declaring a new type alone does not build an ANN index. Convert or copy a packing-compatible row into a shadow table when verified. Missing runtime functions warrant either scoped exact fallback or a separately evaluated local ANN backend with an eligible-ID selector and deletion support. [Turso vector representation and functions](https://docs.turso.tech/features/ai-and-embeddings)

Snowflake reports relative nDCG@10 losses of 1.81%, 2.17%, 2.13% and 3.06% on four published suites when truncating this 768-dimensional model to 256 dimensions. Its documented query side uses lowercase `query: `, CLS pooling and normalization. Record the exact artifacts and prompt used in Atlas. Reuse a valid stored float vector’s first 256 components and renormalize both query and document prefixes for cosine. Reject zero/nonfinite outputs. Retain the full vector for rescoring. A second index costs storage even when encoder inference is avoided. Turso’s approximate storage formula includes a copy of the base vector plus graph-neighbor storage for each node, so stage a sample and measure bytes per row, build/ingest throughput, write volume and free-space headroom before extrapolation. [Snowflake model card and compression comparison](https://huggingface.co/Snowflake/snowflake-arctic-embed-m-v2.0) · [DiskANN index settings and size model](https://docs.turso.tech/features/ai-and-embeddings)

| Arm, against one frozen authorized corpus | Purpose | Result to record |
| --- | --- | --- |
| Exact float32 768 | Ground truth for this model | Ordered nearest chunk IDs, ties, scoped row count, cold/warm query timings |
| Exact normalized 256, then optional 768 rescore | Isolate MRL loss before introducing graph search | Recall overlap at k and relevance Recall@100, top-10 nDCG, candidate pool sizes |
| Native DiskANN 768 | Isolate graph approximation versus exact 768 | Overlap/recall for each k, p50/p95, resident bytes, disk bytes, update/delete lag |
| Native DiskANN 256 → full 768 rescore | Test two-resolution retrieval against both preceding rows | Quality/latency/space frontier at candidate depths 50/100/200 |
| Exact eligible subsets | Establish fallback performance for uncommon filters | Latency vs eligible cardinality and indexed selectivity |

Choose tuning on the development set only. Keep the same scoped rows, query weights, cache warmth and worker count. Try defaults first, then a bounded sample of `search_l`, neighbor count and neighbor compression as supported by the pinned engine. Measure local and synchronized replicas independently. A rollback selects the old generation, subject to current tombstone/policy epoch. Keep the old generation current enough to roll back. Never resurrect revoked rows.

## Sparse, late interaction, reranking and feedback

1. Freeze lexical+dense RRF at the measured deployment revision. Add SPLADE learned sparse retrieval in a tier-partitioned inverted index. Record postings per item, bytes, elapsed indexing, candidate yield unique to sparse and exact-ID regressions. Distinguish M3 lexical weights from a separately trained SPLADE model. [SPLADE](https://arxiv.org/abs/2107.05720)
2. Evaluate local BGE-M3 independently on its dense (1024 dimensions), lexical-weight and token-vector outputs. Use model-tagged tables and its own query preprocessing. Compare Arctic+dense/lexical controls, M3 dense alone, M3 sparse alone, and combined branches. Apply late interaction over the same fused 100 candidates, scoring token-level MaxSim and recording actual token-vector bytes per document. Use per-model ranks or a calibrated fusion; never take cosine between M3 and Arctic/BGE-small vectors. [BGE-M3 model card](https://huggingface.co/BAAI/bge-m3) · [ColBERT](https://arxiv.org/abs/2004.12832)
3. Independently rerank identical fused pools of 50/100/200 eligible chunks using a local cross-encoder. Pin model, tokenizer, truncation policy, runtime, artifacts and exact CPU. Compare reference pair-score ordering on fabricated public text and numerical tolerance before comparing relevance. Benchmark cold initialization, warm/worst-case batch p95, memory and truncation on long-document slices. fastembed 7.7.1 documents an ONNX-only BGE v2-m3 variant and names its actual conversion repository. Verify pinned Atlas support and weight provenance. A Candle port needs equivalent XLM-R classification head, pair tokenization, logits and hardware-specific verification. A failed worker can fall back to fused order. Keep the UI aware of degraded behavior. The advertised +5–15 ranking gains and 50–500 ms CPU range in the request are hypotheses with no Atlas measurement. Hosted comparison would require approved shareable queries *and* passages, allowed plan quota, and a separate offline run. [BAAI reranker card](https://huggingface.co/BAAI/bge-reranker-v2-m3) · [fastembed model enum](https://docs.rs/fastembed/7.7.1/fastembed/enum.RerankerModel.html)
4. Join each feedback event to an exposure record by request ID, anonymous scope, variant, generation, rank, timestamp and eligible result identifiers. Preserve explicit helpful/unhelpful labels, reads, reformulations, and missing outcomes distinctly. Deduplicate retry event IDs, cap repeated events per session, and choose a fixed attribution window. Clicks depend on rank and exposure. Sample disagreements for private judgment and record coverage. Train or tune a weight on historical windows only, then evaluate on a subsequent held-back time block. Behavior features must respect current tier, expiry and deletion on every use. [Joachims et al., click interpretation](https://www.cs.cornell.edu/people/tj/publications/joachims_etal_07a.pdf)

## Evaluation, release decision and next pass

Use two benchmarks. **Index fidelity** computes overlap@k against an exact same-model search within the same authorized set. **User relevance** assesses known relevant chunks or source occurrences with graded judgments. A faithful ANN can conserve a poor ranker, and a strong reranker cannot recover excluded candidates. Log judged coverage, candidate Recall@50/100, nDCG@10, MRR@10, Precision@5 and no-answer false-positive/abstention rates. For filtered corpora with fewer than k eligible rows, normalize overlap by the actual exact-oracle set size and report empty sets separately. For no-answer examples, exclude undefined nDCG/recall and report that denominator. Report p50/p95 per stage, warm/cold, and full request wall time under representative concurrency. [TREC judgments and collection alignment](https://trec.nist.gov/data/reljudge_eng.html)

Expand dev judgments from temporally binned Fleet and eventual ID traces. Include zero results, repeated reformulations, unclicked requests, easy and difficult examples. Stratify by query class, input surface, corpus/source, tier, length, aliases, identifiers, semantic twins, distractors, long documents, date filtering, recently changed records, and deliberately no-answer queries. Treat the source trace as sensitive, keep text inside its permitted zone and export only approved aggregates or synthetic fixtures. Pool top-ranked candidates from all plausible arms. Blind adjudicators to originating model. Keep a provenance ID, applicability window and classified rationale locally. Group by session/project and near-duplicate document family before splitting. Track exact versioned chunks and parent source IDs so a rechunk does not look like a universal relevance regression. Where a candidate introduces many previously unjudged top hits, publish coverage and adjudicate them before declaring a loss. [TREC pooling practice](https://trec.nist.gov/pubs/trec33/papers/overview_33.pdf)

A run manifest should record pinned commit, corpus snapshot, exact subset filter, policy/tombstone epoch, qrels hash, split and label versions, runtime/CPU, model artifacts, truncation, candidate pool sizes, tie rule, transform budget, cache state and runner ID. Replay baseline and challenger interleaved, under identical limits. Pair queries when estimating deltas; compute confidence intervals by resampling at the session level where queries share a source session. Report per-slice n and interval; small slices remain inconclusive. Do feature/tuning selection on supported development data. Treat the 54 used by the Jaccard gate as a known near-exact regression set. Freeze one candidate, selection rule and margins before opening a freshly sequestered, independently sampled holdout. Repeated CI should use versioned development/regression fixtures. Reserve new holdouts for locked promotion decisions and rotate as they are consulted. Inspect duplication between old and new sets at session, passage and document-family levels.

**Initial proposed release gates, subject to calibration against the measured baseline.** All canary privacy/purge/identity assertions pass across all surfaces. ANN overlap@50 lower confidence bound at least 0.95; retrieval candidate relevance Recall@100 delta lower bound at least −0.02; overall nDCG@10 delta lower bound at least −0.01 for a speed substitution. Use at least 2× improvement in dense p95 as the initial minimum worthwhile ANN speedup. A quality-led change such as reranking must show a positive paired nDCG@10 lower bound and fit a declared end-to-end p95 budget. Report class-level regressions; withhold the change for a class where the safety or quality criterion fails or remains indeterminate. Thresholds are absolute fractions except the speed ratio. Predeclare minimum material improvement and power before any model selection. Set numerical service latency budgets on the measured target hardware.

**Sequence.** (1) Scope oracle and sanitized replay fixture; (2) deterministic flags/filter/context planner with branch-scope parity; (3) exact 256 and native vector capability fixture; (4) per-eligible-partition graph shadow; (5) learned sparse, late interaction, local reranker in isolated arms; (6) feedback-assisted evaluation; (7) second-model generation cutover only on quality/latency and operational acceptance. If any arm loses its intended slice, record that result and proceed with the cheapest winning configuration. Run public CI from main under the existing policy and use one targeted Fleet dispatch on an exact branch commit for premerge verification. Keep private evidence at the proper tier and dispatch only approved fixtures to remote runners.
