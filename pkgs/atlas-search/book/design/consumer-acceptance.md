# Consumer, cache and recommendation acceptance

The request adapter authenticates the calling principal. Each hop binds the downstream request to that principal and operation using a trusted channel or replay-limited signed assertion; the origin verifies the assertion. Derive effective scope inside the retrieval core by intersecting the identity grant with the transport ceiling, eligible corpora, requested restrictions, and current policy manifest. If a hop loses the identity, return a bounded authorization error. Treat absent scope details and unknown classification as denied. For HTTP MCP authorization, require the token's audience to be this service and use separate credentials for downstream APIs. [MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)

Every retrieval branch receives the same authorized source and tier selection before scanning, counting, sampling, hydrating or computing similarity. The reference resolves to an occurrence, revision and chunk. Identical bytes in two sources do not grant access to both provenances. Derived artifacts inherit the restrictions of every input, including the seed, co-occurrence edge, profile, graph path and feedback. Choose serving partitions already inside the ceiling, or compute an eligible subset before ranking. A global top-K followed by a row filter leaks information through results and can starve an authorized branch. A status tool only counts accessible material; an explanation names eligible signal types and rank contributions without disclosing private source names or query text.

Keep an authority-owned publication token for the immutable index snapshot and separate policy/revocation epochs covering the scope. Content publication advances the index token. Tightening access or publishing a tombstone advances the appropriate epoch before old references or cached pages can serve. An authoritative epoch check is required on every hit carrying revocable content, including any origin-bypassing read; an unvalidated or unavailable authorization service returns no such hit. Physical cleanup is tracked separately on each replica and cache. A TTL alone leaves a revocation window. For a simple first release, cache only opaque authorized candidate references and rerun scoped hydration at the origin on every hit. Suppress caches for local-only or secret-bearing requests at hosted boundaries. Fail closed if access metadata and corpus epochs belong to different publications.

## Versioned contract and acceptance

Extend the existing schema additively, reserve a new major for incompatible semantics, and expose a negotiated capabilities record for optional operators. Each adapter maps into typed core operations. Validate max page size, bounded UTF-8 snippet bytes, allowed sort, dates, filters and unknown modes before expensive work. Preserve existing CLI bytes and exit codes with frozen fixtures. Delay optional field emission for legacy output; use a versioned JSON representation for new fields. Keep the current names and representations from the checked-in seed and parity fixtures when wiring these proposals.

Use synthetic labels and counts only. A fixture run through curl establishes the adapter contract; a harness row turns verified only after the harness itself succeeds.

## Durable Object expiry and migration (#6805)

Use a versioned key over a deterministic encoding of operation/normalized request, stable scoped grant fingerprint, response schema, index publication, policy/tombstone epochs, model, planner and rank revision, and feedback/profile revision for recommendations. Apply a keyed digest to low-entropy identifying inputs. Never trim significant query syntax or sort multi-valued fields whose order changes results. Preserve order for batches and sort only explicitly unordered sets. Do not log text, refs or digest inputs. The Worker retains its credential-free database boundary. Reuse D1 invalidation signals where they match the authoritative revocation contract. Store-level purge is insufficient evidence of cross-cache enforcement.

1. Add an envelope with schema, expiry, creation time, eligible scope binding and serialized byte count. The v1 indefinite-retention rule was an explicit owner decision in #6805. the owner's new brief requests a fix. Compare a 5-minute absolute TTL against generation invalidation plus a longer age bound on a replay before selecting a production default; tune with replay hit rate, revalidation latency, plan-quota writes, bytes and cleanup lag. Never extend life merely on read. Cap a DO's encoded bytes and pages. Bound global admission using a per-principal request/byte budget and stop new fills at the limit. Skip errors and unauthenticated responses.
2. Check expiry and epochs before returning a hit. An envelope with missing fields is expired. On a miss, coalesce identical in-flight fills. Scope-check re-entering results after origin I/O; prevent an old generation completing after invalidation from resurrecting an entry. Test an authorization change racing an outstanding fill.
3. Set the single DO alarm to the earliest stored expiry. On alarm recheck time and generation under the same serialization discipline as writes. Remove only due generations, restore the next alarm for remaining rows, and clear storage and alarm when the instance is empty. Retry handling must be idempotent. Include cases for hibernation, delayed delivery, lost response, and an old alarm firing after renewal. [Cloudflare alarms](https://developers.cloudflare.com/durable-objects/api/alarms/) · [Storage cleanup and compatibility dates](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/)
4. A new key namespace or lazy expiry leaves old, never-read objects on disk. First disable legacy reads/fills and identify whether the deployed class/binding also stores non-cache state. Dry-run a cursor-based object inventory, record aggregate counts and quotas only, then plan a rate-limited legacy-only sweeper protected by a generation check. Resume from a checkpoint and repeat inventory until old stored data is accounted for. Preserve new writes during cleanup. Review the destructive live cleanup separately from shipping the read-time expiry code. [Cloudflare namespace object inventory](https://developers.cloudflare.com/api/resources/durable_objects/subresources/namespaces/subresources/objects/methods/list/)
5. Separate mitigation and rollback. Disabling cache reads safely bypasses a bad envelope deployment; re-enabling a legacy cache would revive unverified content. Instrument expired-envelope misses, old-generation rejects, quota admissions, discarded oversized bodies, alarm lateness and reclaimed bytes. Reject unrecognized cache versions on both read and write.

Priority test: two principals query the same text concurrently. Warm both caches, revoke one grant, delay alarms, restart Worker, then read immediately. The authorized caller receives its new scoped response. The revoked caller gets no references, snippets, counts or stale cursor. Check both adapters against the same core fixture. Include a legacy object with no recorded expiry and a never-revisited object in the cleanup rehearsal.

## Single-user recommendation design (#9140, #9109)

Maintain an independent feature set per eligible privacy/source partition and model/index generation. Retain occurrence IDs and profile contribution references locally so deletion/reclassification can subtract the old contributions, or rebuild the affected profile and block that generation until rebuilt. Cross-tier pair counts must also be retired when an input disappears. Keep personalized query suggestions out of a shared cache.

| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| Similar items         | Seed vector; nearest authorized occurrences in its model space. A profile uses the L2-normalized sum of positive item vectors times event weight and exponential half-life decay. Dedupe event IDs and cap repeated actions per session. An empty or zero-norm profile falls back to authorized recency. | More-like-this; feed candidates             |
| Session co-occurrence | Deduplicate opens or selections per session, maintain unordered item pairs in a finite time window, cap distinct items/session, dampen large generic sessions, shrink low-support pairs. Respect time and tier at event creation and retrieval.                                                          | Related results; sparse profile fallback    |
| Provenance graph      | Enumerate bounded 1-hop typed edges whose source, target and relationship all pass policy; bound per-edge-type degree.                                                                                                                                                                                   | Linked notes, objects and project neighbors |
| Recency / frequency   | Decay locally scoped events, cap per-item contribution. Suppress recently seen items per surface and honor explicit dismissals.                                                                                                                                                                          | Cold start and resurface                    |
| Query suggestions     | Begin with curated eligible metadata terms. Personal query history requires local classification, deletion propagation and a purpose-specific policy before promotion.                                                                                                                                   | Suggestions without leaking query history   |

Union with source budgets, dedupe by logical item while retaining eligible occurrence attribution, then combine calibrated features or rank-based fusion. Compare against recency-only, similarity-only and prior successful-item baselines. Over the fused pool select the next item by λ × relevance minus (1 − λ) × highest similarity to an already selected item; clamp both component scales and break ties on a stable partition-local identifier. Add bounded freshness or exploration only as a reproducible seeded treatment. Record inclusion reason locally and evaluate exploration separately. [Carbonell and Goldstein, MMR](https://www.cs.cmu.edu/afs/cs/Web/People/jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf)

For the DO “next 10,” keep #12873's frozen total order (score descending, immutable recommendation ID ascending) and existing cursor binding to parent SnapshotId + position, optional expiry, and explicit done signal. Do not add generator progress or security fields to the canonical parent/page preimages without a version bump and fixture review. Bind the surrounding session to principal, disclosure scope, pinned input generation, model and policy epoch. Reject obsolete grants before replaying the signed page. #13353 already persists the pinned parent, stable order, cursor and replay responses atomically per tenant/subject. Use its restart, replay, wrong-parent, per-page identity and failed-write oracles. Fan-out finishes gathering the cutoff-eligible pool by an explicit deadline **before** freezing the parent. A late branch belongs to a later snapshot. Record missing branches in snapshot metadata before signing. Bound candidate counts, accumulation bytes, fan-out parallelism and maximum lifetime. Confirm the signer, grants and DO binding with synthetic data before any production rollout. See the existing fan-out backpressure design and the still-open retention/object and comparison issues. [Fan-out design clarification](https://github.com/developing-today/code/pull/13104) · [Object/retention](https://github.com/developing-today/code/issues/10173) · [Persistence/comparison](https://github.com/developing-today/code/issues/10189)

Evaluate on globally time-cut sessions. Candidates, graphs, availability, feedback and profile features all use their state at each prediction time. Report recall of the eligible next engagement, nDCG@10, coverage, per-list redundancy, repeated-seen rate, latency, and dismissals where observed. Use a per-session bootstrap and state sample sizes. No exposure is an unknown label; report the exposure/logging policy and bias separately. Keep subjective resurfacing judgments distinct from open-rate proxies. [ACM RecSys 2025 temporal leakage study](https://recsys.acm.org/recsys25/poster-3/)

## Fleet and ID rollout

Fleet first needs observable data age: stamp every result with scoped publication and status with observed source watermark where available. Compute source lag from a captured reconciliation watermark. An older document timestamp alone cannot establish lag. Then add the scoped cache and bounded batch request. The existing #12868 decision puts the sync owner and the replica PipelineTransport in the same process, keeps LocalShardTransport on static files, and rejects secret tier pre-network. Close the engine-specific spike before picking the crate. An offline client may only keep physically scoped replicas that the device and principal may possess. Embedded replicas synchronize a database into a local file, so replicating the mixed monolith to a lower-ceiling lane is unsafe. Pin the client engine and compare exact and ANN ordering, ext/type support and indexes against matched fixtures. Require an explicit maximum offline lease per data class; classes requiring immediate central revocation cannot be served offline without a reachable authority. Display last sync and publication in offline responses. Its named oracle requires duplicate delivery to create one vector per full pipeline identity, distinct model revisions to stay separate, and invalid/unsigned derived inputs to be rejected before indexing. For the ID → Atlas vectorization adapter, reconcile with the design's hook/adapter contract.
