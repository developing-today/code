D. Secrets broker and credential distribution

At the November 23 review, #13081 was open and Xaltha owned the active correction. PR #13125 remained unmerged. The implicated heal script repeatedly restarted a cold broker before its first refresh completed. Xaltha’s later two successful heal invocations used an already-warm broker. The recorded sandbox change still permits restarting a refresh after its progress counter stalls. Its propagation and a cold activation need separate evidence. Incident and ownership · PR #13125

The inspected broker serializes refreshes, bounds each provider child to 60 seconds, and performs a list followed by eight-way parallel gets. Its default full-refresh interval is 900 seconds. Its health handler derives serving readiness from a previous successful refresh. At 221 entries a full sweep therefore models 222 child starts, or 2,211 at 2,210 entries, excluding retries and read-through misses. These are subprocess counts. Provider request counts and elapsed times require separate measurement. Broker source

Proposed refresh experiment. Use synthetic projects of those two sizes and revisions changing 0%, 1% and 100% of entries. Verify which fields a project-scoped list returns in the installed CLI. If it supplies complete values and revisions, parse once in memory. Otherwise reuse unchanged entries by immutable item ID and revision, and fetch changed entries only. Instrument child starts, provider calls, peak memory, throttles and p95 cold/warm duration. Partial or unauthorized enumeration must never implicitly delete the cache. An authoritative scope revocation must prevent serving its entries. Tag writes by refresh epoch so a late response cannot reinstate an older value. Choose freshness by the consuming service’s revocation requirement. Provider CLI contract

Proposed distribution contract. A manifest binds a provider project and immutable item ID to a specific service principal, audience, seat capability, destination and file mode. Existing daemon/client token names that look similar cannot substitute for each other. Install atomically with the intended owner and mode 0600. Require an encrypted private local copy for approved credentials and verify it with revision metadata and an isolated restore canary. Report only the outcome. Privileged issuance and deployment require current authorization. Designated continuity credentials may serve a prior value only within an explicit audience, expiry and maximum stale age. Denial or known revocation ends every fallback; a transport error is a separate outcome. Enrolment precedent · Scoping work

Proposed acceptance and drift checks. For each runner surface record the workflow, referenced action and prep script at immutable SHAs, declared platform and actual image digest. Report missing, pending propagation, or diverged. Run the cold and offline warmed shell with the workflow’s actual UID, HOME, effective Nix configuration, build-user model and required cargo/bun binaries. Preserve the workload’s named oracle separately. A job that mounts the host’s configuration cannot prove that a fresh NixOS host has the right accounts, systemd units or store layout. For cached verification, bind the target checkout tree, task and oracle version, lockfile, toolchain, effective image, platform, flags and repository audience. Reauthorize artifact reads and verify their digests. Commands with external effects receive fresh execution.
