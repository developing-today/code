# Quota decisions, operator status and service contracts

## A decision record that survives a bad reading

Keep the quota contract alongside the pm-stack gatherer, forecast and review jobs. Publish a versioned observation and decision schema that Fleet's placement adapter can consume. A new independent quota crate would duplicate classification and provider scope. A pool record needs its provider and billing owner, plan or eligible SKU, binding window, reset, observed and gathered times, source revision and quality. A decision records its input IDs, policy revision, exclusions, selected route and next observation. Preserve the distinction between the current reading and the last known valid reading. [Admission design](https://github.com/developing-today/code/tree/1f9bc15391ca/doc/2026-11-14T18-05-00Z_design_fleet_quota_admission) · [Admission source and fixtures](https://github.com/developing-today/code/blob/1f9bc15391ca/pm-stack/aggregator/test/quota-admission.test.ts) · [Stage-three design](https://github.com/developing-today/code/tree/1f9bc15391ca/doc/2026-11-22T22-35-00Z_design_quota-plane-stage-3)

| Condition                                           | Proposed dispatch decision and oracle                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fresh eligible plan                                 | Burn by earliest binding expiry with OpenAI as final reserve. Permute provider and input order against a fixed clock and verify a stable result. A provider onboarding manifest supplies meter, reset semantics, included routes, owner and classification fixtures.                                                  |
| Stale, absent, retained-after-error or invalid read | Attempt a fresh measurement before a dispatch decision. A result no more than 60 minutes old qualifies. Mark a failed measurement unknown, including source and age. Keep already authorized plan capacity available where documented policy permits it. An unknown cannot establish a wall or financial eligibility. |
| Admission threshold                                 | Test both sides and equality at 100%, and sustained readings at or above 99.5% over the configured evidence interval. Keep unknown ticks and reset boundaries explicit. Record which admission rule fired.                                                                                                            |
| Provider disable                                    | Require below 1% remaining in the binding window plus corroborating plan-limit failures before disabling a provider. A 402 ends the affected attempt with at most one bounded retry. One failed call cannot disable the provider. Preserve the receipt for each decision.                                             |
| Section risk                                        | Preserve shipped section buckets and the pending-wall threshold of 85%. Include contributing capacity and observation quality. Add forecasts with horizon, estimate and error band, measured against later outcomes by section and reset period.                                                                      |
| Possible financial overage                          | Admit only demonstrably included plan work. Keep money-denominated or unclassified routes out of the eligible set. No provider fallback may widen billing permissions.                                                                                                                                                |

The Go placement recorder introduced a separate monthly 97% launch guard. A later revision rejects invalid values, treats a sample retained after a failed tick as stale, retries once and can use the latest valid monthly reading with the fallback recorded. When there is no such reading, the recorder returns failure. Preserve provenance for that path and test how its caller handles the result. A monthly launch reserve, a section notification, a forecast margin, admission and provider disable are distinct outcomes. Source changes establish implementation; deployment and route-wide enforcement require their own observations. ## One operator read with visible gaps

The queue's work-inspection API already projects readiness, ownership/execution and remote-resource observations with provenance. Reuse its ID and reference resolvers for a unified status reader. Present per-section source, last successful observation, age, errors and visibility. A timeout yields a partial response. It must never turn a missing queue, quota pool or seat into a measured zero. Bind the caller's scope before computing aggregates. [Inspection projection](https://github.com/developing-today/code/commit/e488516315b) · [Projection tests](https://github.com/developing-today/code/commit/672f293f87a)

| Status section      | Authority and test                                                                                                                                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Work                | Count by stored status at one writer watermark. Classify quarantine with its evidence. Follow the event cursor for claim, park, block, handoff, completion and reasons. Test page continuity during a concurrent append. |
| Deployment          | Join named active generation and binary source to the intended release manifest and book revision. Simulate one unreachable broker and one deliberately deferred service.                                                |
| Seats and shortlist | Join enrolled principal, capabilities, last seen and shortlist observation time. Record age of oldest ready entry and the proportion already dispositioned on handout. An offline seat can have unknown depth.           |
| Dispatch            | Group reservations and provider jobs by dispatch, attempt and job to avoid double counting. Distinguish accepted submission, setup failure and verified workload result.                                                 |
| Quota and channels  | Show per-window wall, forecast, reading age and decision separately. For each channel leg, name its dependency and last successful semantic probe.                                                                       |

A 48-hour stall sweep uses the last **substantive** transition. Heartbeats, observer reads and repair dry runs do not advance it. Report task ID, elapsed time, unresolved native prerequisites, independent body-level gates, holds, owner and next observable event. Future condition-park deadlines are a separate disposition. Test a case where heartbeats continue for 49 hours and a due dependency with a surviving manual gate. A status listing is read-only; ownership and any mutations remain with the responsible operator.

For cost, collect billing owner, platform/SKU, repository, run, attempt, job ID, unit, observed duration, source and price-rule revision. Attribute a job to a lane/task with an explicit relation. Preserve an unattributed bucket and avoid dividing shared jobs arbitrarily. Where the provider rounds per job to whole minutes, two 31-second jobs and a separate 12-second rerun represent three rounded minutes. Check invoice/accounting evidence separately from observed wall clock. Generate Fleet Reports with source watermarks, schema and visibility. Atlas ingestion upserts idempotently by report and revision; advance the export cursor only after acknowledgement. Replay a failed acknowledgement, verify one matching record, and verify the public reader cannot infer private pool or seat membership from aggregates.

## Atlas, ID and mcpx

**Atlas.** Preserve the ranked-chunk and flag-parity contract of the existing CLI. Extend the typed client and retain its renderer. A cache key includes authorized corpus/scope, index generation, ranking/configuration revision, normalized query, filters and limit. A bounded batch API returns a status and ordering per query. Test a mixed denial, timeout and success and compare single-query bytes with the pinned CLI fixture. Telemetry for a golden set needs approved redaction, opt-in sampling and aggregation independent of search results. An offline libSQL replica copies source pages. Use scope-specific datasets and signed manifests with validity, digest and generation. Keep public corpus as the default offline scope. Verify a denied marker is absent even from the persisted replica. A private offline dataset needs a separately accepted revocation-delay bound. [Atlas program](https://github.com/developing-today/code/issues/13241) · [Fleet search source](https://github.com/developing-today/code/tree/4cfceaa/pkgs/fleet/crates/fleet-search)

**ID.** Twelve members in the inspected 13-member Fleet workspace had library roots; the multicall binary composes them. A public Rust function accepting argv or returning an integer exit code promises less than an independently versioned service interface. Build an external minimal Cargo consumer at pinned versions on applicable platforms, inject synthetic transports and secrets, and reject accidentally enabled server features. Preserve the CLI rendering as a compatibility oracle.
