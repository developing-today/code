# Queue guarantees and dispatch decisions

A queue grant authorizes a worker to attempt a task. A provider run, a merge, and an external side effect each have their own authority and evidence. After a lost reply, a worker needs a way to identify which operations already committed before it retries.

## What the November rollout proved

The November 23 acceptance receipt identifies a generation 6 broker and two seats at `bcc8043`. A second seat with an empty local cache resolved another seat’s placement handle. A later six-queue sweep read 449 blocked or parked rows. Its dry run produced 37 repairable missing dedupe attestations, six refusals, two intervening state changes and 404 rows without a validator defect. The subsequent operator ledger records all 37 candidate IDs transitioning to queued. This closes that drain. A new census needs a fresh watermark and new evidence. A packet gaining a valid shape can still refer to an issue with open dependencies. [Cross-seat receipt](https://github.com/developing-today/code/issues/13146#issuecomment-7103726386) · [Census](https://github.com/developing-today/code/issues/13191#issuecomment-7104845806) · [Write receipts](https://github.com/developing-today/code/issues/13191#issuecomment-7105556112)

The #13091 fix excluded condition parks from retries and absorbed already-completed work. Recheck future double-serve reports against the claimant’s source revision, the broker’s active generation, the prior disposition and the writer’s event order. Include a genuinely eligible task in the same test to distinguish a correct exclusion from a disabled claim path. [Merged correction](https://github.com/developing-today/code/pull/13143)

## Proposed grant and repair contract

The conditional claim update serializes the winner for an eligible row. Reply loss, expiry and reassignment still permit another attempt at the work. Give each grant a monotonic epoch and each process an instance ID. A claim request has a retry-stable ID. Commit the task mutation, lease record and receipt together at the writer. Authenticate holder, epoch, status and deadline when committing heartbeat, checkpoint, handoff or completion. A broker restart recovers the receipt from the writer. Establish acknowledged-write survival for the actual managed database configuration before promising survival of promotion. Require destination idempotency keyed to the logical operation, across epochs, for external effects. An unknown non-idempotent outcome goes to reconciliation before another execution. These guarantees implement the scope of the existing orchestration charter. [Execution charter, §§13–14](https://github.com/developing-today/code/blob/4cfceaa/doc/2026-11-13T03-20-24Z_design_pm-stack-fleet-orchestration/sources/02_charter_v1_1.md)

Use the published queue repair workflow to preview candidate changes, check the current deduplication basis, and record the result for each issue. A refusal belongs in the operator receipt together with the route for resolving it. [Queue repair](https://github.com/developing-today/code/pull/13218) · [Atomic repair and independent holds](https://github.com/developing-today/code/issues/13579)

For an ageing quarantine, expose the defect class, affected fields, detecting validator revision, first unresolved event, last substantive transition and permitted repair route. A fairness sweep can touch a row without changing the disposition. An operator needs an unknown-age result when the necessary event has expired. Treat a missing dedupe stamp, absent repository, ambiguous priority, live holder and exhausted attempts as different defects. Only the first can acquire a new attestation solely from a successful live dedupe check. An authoritative producer can supply missing scope or priority. Preserve refusals with the responsible party and next observation.

| Failure injected | Observable acceptance result |
|---|---|
| Lost grant response, broker restart, same request retried | One committed grant and one receipt for the request. |
| Two processes use one display name, first process resumes after transfer | A late heartbeat or completion leaves the new grant and checkpoint intact. |
| Final dependency resolves twice while work is parked on a separate condition | One dependency transition. Independent condition remains active. |
| Previously completed issue re-enters via a new packet key | Recorded disposition and intentional revival policy decide eligibility. |

At the inspected source revision, a normal lease starts at 45 minutes while `agent next` uses four hours for work that can last hours without automatic renewal. The default heartbeat computes an absolute deadline 15 minutes from receipt. At minute five this can shorten a four-hour grant by 220 minutes. A proposed normal-renewal rule preserves the later of the existing deadline and the permitted new deadline. Collect heartbeat gaps, abandoned-grant recovery, false reclaims and write cost before changing the defaults. Introduce epoch-aware callers alongside old seats and enforce fencing after outstanding old grants drain. [Intake rationale](https://github.com/developing-today/code/blob/4cfceaa/pkgs/fleet/crates/fleet-agent/src/next.rs) · [Lifecycle](https://github.com/developing-today/code/blob/4cfceaa/pkgs/fleet/crates/fleet-queue/src/turso_queue/lifecycle.rs)

Measure the claim path first on disposable data with a production-shaped status distribution at current and tenfold row counts. Exercise 1, 8, 16 and 32 lanes against one contested row and independent rows. Repeat five seeded trials per cell. Report sample counts, grants per second, eligibility-to-grant p50/p95/p99, lost compare-and-set retries, contention-budget exhaustion, genuine empty responses, store reads/writes and duplicate wake collapse. Measure caller-to-broker and broker-to-commit latency separately. Tailnet and managed failover claims require observations on the corresponding route. Record verified included usage headroom before a managed-volume test. The November acceptance receipts do not contain these measurements; current managed claim throughput, tailnet latency and tenfold capacity remain unmeasured in this record.

## Proposed placement and cross-seat visibility

Placement already computes a dry-run decision and reasoning. Extend that same function with the registry and policy revision, observation ages, capacity exclusions, cache history, billing owner, reservation and tie-break. First enforce repo visibility, runner class, included billing eligibility and platform. Count each macOS slot against both the macOS sublimit and its parent capacity. Reconcile local reservations with provider jobs by dispatch ID so a job consumes a slot once. Keep the public-only fork boundary. Among eligible options, estimate completion time by target repo, command class, platform and image. Distinguish assignment lag, provider job queueing, execution and preparation failures. Prefer a sticky follow-up when its cache savings exceed the additional wait. The three workflow-level timestamps alone cannot identify the first runnable job. [Placement implementation](https://github.com/developing-today/code/blob/4cfceaa/pkgs/fleet/crates/fleet-queue/src/placement.rs) · [Known accounting gaps](https://github.com/developing-today/code/issues/13178)

A November 23 REST sample of the most recent 100 fleet-command runs from each of the three runner repositories found identical creation and start timestamps, to the second, in all 300 records. Across their different windows the pages contained 83 successes, 210 failures, two cancellations and five active runs. Those counts mix infrastructure and workload outcomes. The timestamps cannot measure assignment lag. Use per-job events and workload classes to evaluate a routing change. [Organization runs](https://github.com/developing-today/fleet/actions/workflows/fleet-command.yml) · [Fork organization runs](https://github.com/developing-today-forks/fleet/actions/workflows/fleet-command.yml) · [Upstream runs](https://github.com/dezren39/fleet/actions/workflows/fleet-command.yml)

Retain the immutable request ID across an ambiguous dispatch. Persist provider run and attempt when available. An older API that acknowledges submission without the run ID needs exact correlation against the submitted ID before retry. For a single provider attempt, a delayed nonterminal observation must never erase a terminal one. A genuine rerun is a new attempt. Authorize cross-seat summaries by repo and authenticated installation, with separate checks for command details, logs and artifacts. Propose a 60-second freshness target for active runs and measure it under broker and provider degradation. Use a third seat with an empty cache to test late updates, tie timestamps, denied grants and reruns. [Session storage](https://github.com/developing-today/code/blob/4cfceaa/pkgs/fleet/crates/fleet-queue/src/turso_queue/placement_sessions.rs)

Routine dispatch uses plan-covered GitHub-hosted capacity. For an eligible Blacksmith exception, predeclare the work class, expected benefit, bounded runtime and verified included balance. A missing billing reading cannot authorize spend. Verify explicit Codespace selection on an already-running authorized instance via both [Fleet shell](../reference/shell.md) and [GitHub CLI SSH](https://cli.github.com/manual/gh_codespace_ssh). A queued Codespace placement separately needs its own selection, liveness, cap, core-hour reservation and result receipts. Resolve the existing credential-scope decision before claiming support across seats. [Scope decision](https://github.com/developing-today/code/issues/12237)

Reuse a completed result only for deterministic commands keyed to the target tree, command, workflow, image, platform, toolchain, dependencies, test inputs and oracle revision. Verify artifact ID, digest, expiry, producer and reader scope. A runner repo’s head SHA may identify a different repository from the checkout under test. Preserve both identities. For other work, reuse approved dependency caches and execute the command. Roll out learned ordering in shadow against the current decision function, score predicted completion against matched runs, then enable one eligible command class with a single rollback switch.
