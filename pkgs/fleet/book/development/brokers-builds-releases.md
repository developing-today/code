# Brokers, remote builds and the release train

## D. Secrets broker and credential distribution

At the November 23 review, #13081 was open and Xaltha owned the active correction. PR #13125 remained unmerged. The implicated heal script repeatedly restarted a cold broker before its first refresh completed. Xaltha's later two successful heal invocations used an already-warm broker. The recorded sandbox change still permits restarting a refresh after its progress counter stalls. Its propagation and a cold activation need separate evidence. [Incident and ownership](https://github.com/developing-today/code/issues/13081) · [PR #13125](https://github.com/developing-today/code/pull/13125)

The inspected broker serializes refreshes, bounds each provider child to 60 seconds, and performs a list followed by eight-way parallel gets. Its default full-refresh interval is 900 seconds. Its health handler derives serving readiness from a previous successful refresh. At 221 entries a full sweep therefore models 222 child starts, or 2,211 at 2,210 entries, excluding retries and read-through misses. These are subprocess counts. Provider request counts and elapsed times require separate measurement. [Broker source](https://github.com/developing-today/code/blob/1f9bc15391ca1c2efa639463a6369392456c27e5/pkgs/fleet/crates/fleet-queue/src/secrets_broker.rs)

**Proposed refresh experiment.** Use synthetic projects of those two sizes and revisions changing 0%, 1% and 100% of entries. Verify which fields a project-scoped list returns in the installed CLI. If it supplies complete values and revisions, parse once in memory. Otherwise reuse unchanged entries by immutable item ID and revision, and fetch changed entries only. Instrument child starts, provider calls, peak memory, throttles and p95 cold/warm duration. Partial or unauthorized enumeration must never implicitly delete the cache. An authoritative scope revocation must prevent serving its entries. Tag writes by refresh epoch so a late response cannot reinstate an older value. Choose freshness by the consuming service's revocation requirement. [Provider CLI contract](https://bitwarden.com/help/secrets-manager-cli/)

**Proposed distribution contract.** A manifest binds a provider project and immutable item ID to a specific service principal, audience, seat capability, destination and file mode. Existing daemon/client token names that look similar cannot substitute for each other. Install atomically with the intended owner and mode 0600. Require an encrypted private local copy for approved credentials and verify it with revision metadata and an isolated restore canary. Report only the outcome. Privileged issuance and deployment require current authorization. Designated continuity credentials may serve a prior value only within an explicit audience, expiry and maximum stale age. Denial or known revocation ends every fallback; a transport error is a separate outcome. [Enrolment precedent](https://github.com/developing-today/code/issues/12898) · [Scoping work](https://github.com/developing-today/code/issues/10358)

## E. Channel recovery and broker generations

Proposed health reports expose liveness, readiness, observation time, dependency status, serving generation and operation progress. A dependency failure should never fan out into a series of downstream restarts.

| Leg | Discriminating observation | Recovery owner |
|---|---|---|
| Tailnet | Local daemon available; expected peer reachable | Host service manager handles absent daemon. A peer outage has its own disposition. |
| Relay | Listener accepts and completes its upstream handshake | Relay supervisor reconnects once transport is ready. |
| Session broker | Expected protocol version and framed health response | Broker supervisor repairs a failed listener or handshake. |
| Secrets broker | First successful refresh, current activity and scoped canary | Refresh worker times out provider calls and retries. While `refreshing:true`, heal reports slowness and leaves the process running. |
| GitHub | Authenticated read succeeds for the intended repository | Credential owner handles denial; rate limits get bounded backoff. |

**Cutover contract.** Size each gate from the slowest supported legitimate cold operation including allowed retries and probe delay. A child timeout bounds one fetch, not the entire inventory. Deploy through the registered per-service generation path. Proposed hardening serializes deploy and heal per service, journals the candidate and prior closure before switching, then records the serving executable digest after readiness. Reconcile interrupted switches at both journal boundaries. A test with two generations on the same port must demonstrate that rollback restores the former listener's executable identity, the pointer and journal, and a successful authenticated canary. [Generation machinery](https://github.com/developing-today/code/blob/1f9bc15391ca1c2efa639463a6369392456c27e5/pkgs/deploy/deploy.py)

**Cold-recovery oracle.** In a disposable stack, pause the second synthetic fetch across two normal heal decisions. The broker PID must survive both, finish the sweep and serve the delayed entry. Test two concurrent healers and verify at most one recovery. Place an executable with an incompatible loader before a working binary; the version/protocol test-exec must select the latter. Terminate all five disposable legs, restore them from their registered inputs, then invoke recovery again and require zero restarts. The production cutover needs the measured window and an available rollback generation. [Cold-start incident](https://github.com/developing-today/code/issues/13081)

**Proposed acceptance and drift checks.** For each runner surface record the workflow, referenced action and prep script at immutable SHAs, declared platform and actual image digest. Report missing, pending propagation, or diverged. Run the cold and offline warmed shell with the workflow's actual UID, HOME, effective Nix configuration, build-user model and required cargo/bun binaries. Preserve the workload's named oracle separately. A job that mounts the host's configuration cannot prove that a fresh NixOS host has the right accounts, systemd units or store layout. Use an isolated NixOS VM for those proofs and an authorized laptop activation only for machine-specific behavior. The #13159 evidence family retains its item-specific hold. [Executor acceptance](https://github.com/developing-today/code/issues/13159)

For cached verification, bind the target checkout tree, task and oracle version, lockfile, toolchain, effective image, platform, flags and repository audience. Reauthorize artifact reads and verify their digests. Commands with external effects receive fresh execution. For R2, count eligible store paths, fulfilled paths by substituter, upload bytes, and wall minutes saved across comparable cold and warm cohorts. Track provider queueing separately. Treat each organization's measured occupancy and reservations as part of one pool with per-org and nested macOS limits. A private job requires an authorized surface. Use included capacity only; a shared budget needs a bounded reservation or preallocated allowance to remain safe during a broker outage.
