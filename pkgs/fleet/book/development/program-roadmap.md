# Fleet research and implementation roadmap

Fleet lets a seat find work, claim it, move the work to a suitable executor, and show what finished. Its brokers, agents and providers answer different questions. A successful claim identifies the current holder. A completed run identifies one provider attempt. A merged change establishes repository completion. A deployment needs a separate receipt from the serving process. The [archived charter](https://github.com/developing-today/code/blob/main/doc/2026-11-23T12-45-06Z_design_fleet_program_investigation/charter.md) records the governing rules. [Program tracker](https://github.com/developing-today/code/issues/13272)

Record a new baseline when any named authority changes. For a build, keep workflow, attempt, checkout, execution route, workload outcome and artifact identity. For a repair, keep the deterministic proposed edit, actual committed receipt and subsequent readback. For a release, keep source, binary, bootstrap pin, broker generation and published book revision. Leave unavailable fields unknown.
