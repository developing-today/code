## Working order

Start with queue and intake correctness, then the build and release path. A prerequisite inside the census appears ahead of its dependents. Among independent items, Fleet platform work comes before the [PM orchestration design mill](https://github.com/developing-today/code/issues/9196). Within each group, operational tasks come first, followed by issue priority and issue number. Review the owner, latest comments and item-specific holds before taking a row. A design issue orders design work only.

The last column lists live native predecessors. “Design” identifies an additional open prerequisite declared in the issue body. For a blocked label without an open native edge, the column links to the recorded gate or correction. A dash means the checked sources yielded no open prerequisite. An existing claim, verification window or held implementation can still govern pickup. A successful release, live cutover or production repair needs its own receipt.
