# github-backup

Mirrors of Drew's GitHub estate, kept on the laptop, updatable forever,
with a dedicated GitHub App for rate limits and webhook freshness.

**This directory is the canonical home of the whole system** — scripts,
systemd units, the webhook Worker source, the config schema, and the
docs. Nothing load-bearing lives only on a machine: a fresh laptop plus
this repo plus Bitwarden rebuilds everything (see `docs/RUNBOOK.md`).

## Layout of the backup tree (`~/backups/github` on the laptop)

```
<owner>/<repo>.git     bare mirrors (git clone --mirror: all branches+tags)
plan.json              generated by reconcile.py from config.json + GitHub
MANIFEST.json          generated: what exists, sizes, HEADs, last fetch
FAMILIES.md            generated: fork-family anchors (alternates pool)
state.json             generated: fetch/drain bookkeeping
clone-status.jsonl     clone pass log (append-only)
fetch.log              fetch failures (append-only)
reconcile-YYYY-MM-DD.md  weekly sweep reports
```

## Design

- **Scope (config.json):** all non-fork repos + forks under 500 MB across
  17 owners, plus force-includes; 7 passive giants are excluded by Drew's
  ruling 2026-10-31 (upstream is their backup). Edsebooks (HTTP 451) and
  vertexinc (SAML) are recorded gaps, not silent misses.
- **Pool/dedupe:** forks sharing an upstream are cloned with git
  alternates against a family anchor, so e.g. the three nixpkgs copies
  store one shared history plus deltas. Members are NOT self-contained —
  the tree is the unit. Cold copies use `git bundle` (materializes
  objects), never a bare tar of a member `.git`.
- **Freshness:** a dedicated GitHub App (`developing-today-backup`,
  metadata:read + contents:read, push+repository events) sends webhooks
  to the Cloudflare Worker in `worker/`; the Worker verifies the HMAC
  and queues events in KV; the laptop drains the queue every 5 min
  (per-repo coalescing 15 min) and fetches just those mirrors.
- **Correctness floor:** a weekly reconciliation sweep re-inventories
  GitHub, diffs against the tree, clones new repos matching the tier
  rules, and flags new giant forks as `pending-drew-review` instead of
  cloning them. Webhooks may be missed; the sweep may not.
- **Daily fetch:** every mirror is fetched daily regardless (12 h
  coalescing), so even total webhook loss degrades to daily freshness.
- **Rate limits:** the App's installation tokens have their own pool
  (5,000/hr base, scaling with installed repos toward 12,500/hr),
  separate from Drew's personal token that the fleet uses.
- **Secrets:** by name only, in Bitwarden Secrets Manager — see
  `config.json` → `app.bitwarden_secret_names`. Values never enter this
  repo, the backup tree, or chat.

## Components

| Path | What |
|---|---|
| `config.json` | owners, tier rules, exclusions, gaps, App/Worker names |
| `bin/ghb_common.py` | shared inventory + plan builder |
| `bin/clone_all.py` | resumable parallel initial clone (from plan.json) |
| `bin/fetch_mirrors.py` | daily fetch / targeted fetch of named repos |
| `bin/reconcile.py` | weekly sweep: inventory → plan → clone new → report |
| `bin/manifest.py` | regenerate MANIFEST.json + FAMILIES.md |
| `bin/drain_queue.py` | drain Worker queue, fetch pushed repos |
| `bin/app_setup.py` | App manifest flow, credential storage, install report |
| `worker/` | Cloudflare Worker webhook receiver (wrangler) |
| `systemd/` | laptop user units + timers + installer |
| `docs/RUNBOOK.md` | copy-paste operations: install, add org, upgrade, DR |
| `tests/` | regression tests (plain python3, no deps) |
