The code-repo programme set (91 open issues, title-matched) is defined in [Goals and intentions](goals-and-intentions.md); it is a different set from this one and the two are not merged.

## Ordering rule

Both fork repos carry explicit priority labels (`priority/high`, `priority/normal`, `priority/low`) on most open issues, and the code repo uses the same family on part of its set. Order is therefore: (1) `priority/high` → `priority/normal` → `priority/low` → no priority label; (2) within a tier, `user/escalated` first; (3) then `status/blocked`/`queue/blocked`; (4) then oldest first. Milestones: **none** of the open issues on either fork, and none in the code set, carries a milestone (the API `milestone` field is null throughout) — milestones play no part in the ordering. Cross-references from code issues are noted where the title/body itself states them (e.g. opencode#2782). The table below is in that order.

## Record notes on this map

- **CI is recorded two ways at once.** opencode#2785 (2026-11-23, priority/high, row 3) reports "CI run silence — no completed Actions run within threshold", while opencode#2638 and #2518 are open CI-_failure_ issues about specific completed runs (44247391571, 43849921062). Both can be true for different workflows, but as recorded they describe the same repo's CI as simultaneously silent and failing, with no surface reconciling the two (D58). **Update (2026-11-25, #13963 slice 1):** reconciliation — the surfaces differ: #2785 is the ci-watch silence signal (no completed run on the watched workflows within its threshold), while #2638 (still open) and #2518 (now closed) record failures of specific completed runs on other workflows. Both records stand as written. D58 is settled on the record.
- **A "done" label on an open issue.** opencode#2505 carries `status/done`, yet the issue is open. Either the label or the issue state is wrong (D53).
- **A "shipped" title on open migration work.** opencode#2295 is titled "…core migration (**shipped** — tracking home)" and sits in the no-priority-label tier of this map as an open issue, while its parent migration opencode#374 (priority/high, row 1) remains open (D54). The full statement is in [Goals and intentions](goals-and-intentions.md). **Update (2026-11-25, #13963 slice 1):** #2295 has been retitled without the "shipped" claim; D54 is settled (see Goals and intentions).
- **The platform epic is open and unprioritised.** opencode#2319 "epic: opencode fork — platform work" — the issue that states the fork's purpose in [The forks: what they are and why we carry them](the-forks.md) — carries no priority label and sits in the last tier of its own programme's map. The map records the labels as they stand; it does not re-rank.
