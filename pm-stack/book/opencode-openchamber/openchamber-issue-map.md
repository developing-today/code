## Ordering rule

Both fork repos carry explicit priority labels (`priority/high`, `priority/normal`, `priority/low`) on most open issues, and the code repo uses the same family on part of its set. Order is therefore: (1) `priority/high` → `priority/normal` → `priority/low` → no priority label; (2) within a tier, `user/escalated` first; (3) then `status/blocked`/`queue/blocked`; (4) then oldest first. Milestones: **none** of the open issues on either fork, and none in the code set, carries a milestone (the API `milestone` field is null throughout) — milestones play no part in the ordering. The table below is in that order.
