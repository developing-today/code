## Routing-mode recommendations

The record does not contain controlled head-to-head comparisons of ordered, round-robin, and weighted selection under equal per-provider conditions. These are conservative recommendations from the available observed behavior, not a claim that the winning mode has been experimentally proven. Preserve the documented free/paid weights where capability fits, but do not infer deterministic precedence from weights alone; rely on per-leaf failover rather than treating a pool as exhausted.

### Reproducible context-window test required to close the gap

For each **wired provider/model leaf**, record model ID, provider, date, request shape, accepted input-token count, server-reported usage, and outcome. Use a fixed payload family of deterministic text blocks and increase only the input size (binary search after the first rejection). A pass is the server accepting the request and reporting usage consistent with the intended input; a failure is an explicit context-length rejection or truncation detected by a planted end-of-prompt sentinel. Repeat the boundary once to reject transient provider errors. Report the highest repeatable pass, the first repeatable fail, and the gap; do not label a vendor's advertised limit as tested. This document has not run that test, so **all tested-context ceilings remain unknown**.

## Free-first proposal and fall prevention

Retain the already deployed `openai-payg-free` → paid OpenAI tail pattern as the reference candidate: three successful turns were served by the alias, and its configured weight is 3 versus 0.1 for the paid tail (B3; plan row 24; route chapter §4). This does not prove those turns were zero-cost or that weights guarantee deterministic precedence. Do not increase the paid tail's position or weight based on this evidence. The merged runtime changes in [PR #13208](https://github.com/developing-today/code/pull/13208) and [PR #13273](https://github.com/developing-today/code/pull/13273) record honoring quota-reset timestamps in 429 bodies and benching auth-failed leaves before new sessions (both merged 2026-11-23); #12228 tracks the associated soak. If every candidate is walled, preserve structured failure rather than silently treating an unverified provider as successful.

This is a recommendation and a verification boundary, not a request to change live configuration. The existing probes demonstrate one successful free path and the code record demonstrates fall prevention; they do not establish tested context ceilings or a comparative routing-mode winner.

## Acceptance limits

- The provider and free-tier inventory already exists in `the-plans.md`; this chapter adds evidence-qualified routing and never-serve recommendations rather than copying the whole roster. Its summary table is provider/path-level, not the complete leaf-by-leaf inventory.
- No controlled comparative mode trial exists in the cited sources. Mode recommendations above are explicitly provisional and do not claim that the packet's measurement criterion is fully satisfied.
- No reproducible empirical context ceiling exists for every wired free model in the current evidence. This provider/path-level summary marks the gap rather than substituting catalog limits; it does not itself satisfy the leaf-by-leaf inventory or tested-context acceptance criterion.
- No configuration files or live provider settings were changed.
