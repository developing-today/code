IMPLEMENTATION SUMMARY
================================================================================

The slice 1 implementation provides the complete claimant/executor for the
opencode execution lane, implementing all 6 steps of the execution flow:

1. SUPERVISION (Step 1) - Bound session recovery
   - Checks bound sessions for recovery candidates
   - Implements zero-message session recovery (#4758)
   - Implements gone-session recovery
   - Uses atomic recovery operations via migration 0022
   - Verifies zero messages before deletion
   - Deletes session before reclaiming task
   - Only runs in live mode

2. GATE (Step 2) - Candidate discovery
   - Runs poll.py to discover unbound opencode-lane tasks
   - Filters for tasks with lane="opencode" and no session_id
   - Filters for tasks in "handed_off" or "launch_failed" stage
   - Returns empty if no candidates found

3. CAP (Step 3) - Concurrency limit enforcement
   - Queries OpenCode server for active root sessions
   - Uses 36-session concurrency cap (raised from 12→20→36 on 2026-11-05)
   - Returns cap_room (available slots) or -1 if unknown
   - Never launches when cap_room <= 0

4. LAUNCH (Step 4) - Session creation and binding
   - Creates worker sessions via OpenCode server API (POST /api/session)
   - Verifies session location matches requested directory
   - Deletes misplaced sessions
   - Atomically binds session to task using repo-queue bind
   - Uses compare-and-clear guards (migration 0021)
   - Sends execution prompt to bound session
   - Respects queue priority (order in QUEUES list)

5. TERMINAL STATES (Step 5) - Handled by worker sessions
   - Workers use repo-queue terminal verbs (complete/park/block/fail)
   - Workers include execution context with session_id

6. LOGGING (Step 6) - Fire execution records
   - Logs all fire executions to ~/.local/state/opencode-claimant/fires.jsonl
   - Records timestamp, mode, candidates, launched sessions, cap_room, skips
   - Each fire is one JSON line in fires.jsonl

KEY FEATURES IMPLEMENTED
================================================================================

✅ Mode System (shadow/live)
   - Default: shadow (discovery only, no mutations)
   - Live: full execution including session creation
   - Mode file: ~/.local/state/opencode-claimant/mode
   - Missing/unreadable file defaults to shadow

✅ Four Queue Monitoring
   - repo-health-code-pilot
   - repo-health-opencode-pilot
   - repo-health-openchamber-pilot
   - repo-health-nix-pilot

✅ 36-Session Concurrency Cap
   - Monitored via OpenCode server API (GET /api/session)
   - Only root sessions without terminal markers count
   - Active window: 30 minutes (ACTIVE_WINDOW_MS)
   - Fail-closed: returns -1 if server unreadable

✅ Recovery Rules (#4758, Phase 3 of #4912)
   
   Zero-Message Recovery:
   - Bound session with no messages
   - No activity markers
   - Silent for >30 minutes
   - Attempts remaining
   - Process: verify → delete → reclaim atomically
   - launched_by: opencode-claimant-recovery:zero-message-deleted

   Gone-Session Recovery:
   - Bound session absent from server
   - Attempts remaining
   - Process: verify absence → reclaim atomically
   - launched_by: opencode-claimant-recovery:gone-session

   Exhausted Attempts:
   - Delete zero-message session
   - Fail task terminally with session_id in execution record
   - Use repo-queue fail with deterministic reason class

✅ Atomic Operations
   - Bind operations use compare-and-clear (migration 0021)
   - Recovery operations use atomic bind with special launched_by values
   - Prevents double-binding and duplicate execution
   - Single transaction clears both ledger and progress bindings

✅ Session Location Verification
   - Creates session with location.directory set to PRIMARY_CLONE
   - Verifies response.location.directory before binding
   - Deletes misplaced sessions (wrong directory)
   - Prevents session→repo attribution errors (#4870)

✅ Task State Verification
   - Re-verifies task state before launch
   - Checks lane, session_id, and stage
   - Skips if task state changed during fire
   - Prevents double-execution of working tasks

✅ Hard Rules Compliance
   - Never work tasks directly (claim/bind/launch/record only)
   - No credentials in prompts/logs (uses broker client tokens)
   - No cap violations (enforces 36-session limit)
   - No double-binding (never bind session you didn't create)
   - Atomic operations (bind and recovery use compare-and-clear)
   - Session location verification (verify before binding)
   - Task state verification (re-verify before launch)

✅ Fire Logging
   - Logs to ~/.local/state/opencode-claimant/fires.jsonl
   - One JSON line per fire
   - Includes: timestamp, mode, candidates_seen, sessions_launched,
              cap_room, skips
   - Shadow mode produces same log format as work log
