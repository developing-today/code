# Cost anomaly detector (#4825, partial)

The detector and warning-only intake are implemented and covered by local fixtures. The alert tick (`runAlertTick`) now runs the detector whenever a caller injects an evidence loader (`AlertTickOptions.costAnomalyEvidence`), posting warning incidents to the same alert store as every other throat incident. **No production caller injects a loader yet.** No route, startup hook, timer, environment setting, data reader, schema change, or notification class is added. The only intake is dependency-injected, and unless its caller explicitly enables it, it does not read evidence or call the alert store. This does not complete #4825.

The evidence producer now exists (`src/cost-anomaly-producer.ts`): it reads the rollup store through an injected reader, reduces records with `selectRollups` (one consistent attribution version per window), pairs adjacent unattributed windows, and assembles `CostEvidence` for all four classes, with the certified auxiliary facts below supplied through injected seams that return null when uncertified. It performs no I/O of its own and the server does not call it; the end-to-end store → producer → intake → alert-ledger path is covered by `test/cost-anomaly-producer-4825.test.ts`.

## Evidence a future producer must certify

Use elapsed UTC calendar weeks (Monday–Monday) or months. Both sides of each comparison must cover the whole exact period. An empty cache, filtered Project view, absent observation or stale source does not certify a zero.

- **Burn without progress:** a complete existing spend rollup plus complete issue-closure history for the same epic/project, time window and attribution version. Consume one existing unit at a time; never blend tokens, PAYG dollars or plan-window percentage.
- **Single session:** a complete epic token rollup and the maximum root-session token count from that same pool, epic, window and attribution version. Include folded sub-sessions once, not as competing root sessions. Alert strictly above 50%.
- **Unattributed growth:** complete current and immediately preceding unattributed token rollups with complete denominators covering their same pools, periods and attribution versions. Each denominator is the total source population before attribution, not a sum of overlapping Project and epic rows. Alert strictly above a ten-percentage-point increase.
- **Charge without activity:** a complete, deduplicated monthly total of matched PAYG charges for one service, together with complete service-level session and quota coverage certifying zero activity in that month. Do not interpret lack of project attribution as inactivity; unmatched or estimated charges do not qualify.

The warning includes the scope, UTC interval, compared values and a link to the existing Projects or quota surface. The producer emits one authoritative fact per key; the intake does not reconcile conflicting raw observations that do not both qualify. One batch collapses identical warning evidence and suppresses conflicting warnings for the same key. Subsequent ticks use the ordinary alert ledger dedupe: an open incident retains first-seen evidence while its occurrence count and last-seen timestamp update. This intentionally does not alter alert-ledger semantics. In the existing store, warning incidents do not enter critical push delivery or escalation queues.

## Still needed

Production rollup ingestion is not wired by the current repository. The producer's certified sources now all have in-repository implementations. The charges-side seams: `src/cost-anomaly-sources.ts` implements `monthlyCharges` from the charges pipeline's matched charges (exact cent totals per service and month) and `serviceActivity` from a per-service-month activity census, certifying `complete` only when an ok coverage span covers the whole calendar month — absent, partial, or conflicting census data certifies nothing. The rollup-side seams: `src/cost-anomaly-rollup-sources.ts` implements `closedChildren` from a per-scope-window closure census, `busiestRoot` as the maximum folded root total of a per-epic-window root-session census, and `sourceTotal` from a per-window source-population census, certifying `complete` only when ok coverage spans cover the whole rollup window — the busiest root only when every root entry is whole-window certified, since a partially covered root set could conceal a larger root. Before activation, verify the source-to-rollup reconciliation, and verify warning presentation in Needs-you and Today/brief against the live application architecture without sending pushes. Do not turn on a producer merely because the detector tests pass.
