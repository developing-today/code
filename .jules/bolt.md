## 2025-02-14 - ProseMirror DOM Node Recycling
**Learning:** ProseMirror has built-in DOM node recycling for widget decorations (`Decoration.widget`). However, this is completely broken if you attach a global generation counter or randomized value to the `key` of the decoration (e.g. `g${gen}`). This forces ProseMirror to consider every single decoration as a completely new widget on every transaction, causing it to destroy and recreate the DOM nodes leading to severe layout thrashing and garbage collection pressure.
**Action:** When implementing ProseMirror decorations, always use the factory function pattern `() => HTMLElement` for `Decoration.widget` construction and derive the `key` string solely from underlying dynamic data properties (e.g., ID, position, opacity, connection state) to enable DOM node recycling. Only recreate the DOM node when its visual state fundamentally changes.
