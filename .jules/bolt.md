## 2024-05-18 - ProseMirror Decoration Node Recycling
**Learning:** ProseMirror reuses DOM nodes for decorations if the `key` matches and it doesn't use the DOM layout, however, if `key` changes on every keystroke, ProseMirror completely recreates DOM node trees causing severe layout thrashing. Also, if a widget decoration creates its DOM synchronously instead of passing a factory function `() => HTMLElement`, the factory evaluation happens immediately anyway causing layout calculations before Prosemirror renders.
**Action:** When implementing ProseMirror decorations, always use the factory function pattern `() => HTMLElement` for `Decoration.widget` construction and derive the `key` string from underlying data properties (e.g., ID, position, opacity, connectionState) to enable DOM node recycling and avoid performance bottlenecks from layout thrashing.
