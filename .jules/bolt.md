## 2024-10-11 - [ProseMirror Decoration Rendering Optimization]
**Learning:** In ProseMirror, eagerly creating DOM nodes for `Decoration.widget` on every transaction, especially when bypassing caching by appending a generation counter to the widget `key` (e.g., `-g${gen}`), causes severe performance bottlenecks due to GC and layout thrashing in collaborative editing environments. ProseMirror's `Decoration.widget` expects a factory function `() => HTMLElement` to lazily construct DOM elements only if they are drawn, and relies on the widget's `key` string to recycle existing nodes.
**Action:** When implementing ProseMirror decorations, always use the factory function pattern `() => HTMLElement` for widget construction and derive the `key` string from the actual underlying data properties (e.g., ID, position, opacity) rather than a global counter. This guarantees optimal performance through DOM node recycling.
