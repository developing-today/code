# Design: license combination checker — combination events, v1 incompatibility rules, override vs exception-request flows, audit records

- **Date:** 2026-11-06
- **Status:** proposed design for review; docs-only, no implementation is included here.
- **Issue:** [#5985](https://github.com/developing-today/code/issues/5985), part of the worlds design program [#5955](https://github.com/developing-today/code/issues/5955) (statements S101–S105 of the 2026-11-04 brief).
- **Inputs:** the license taxonomy & classifier design [#5977](https://github.com/developing-today/code/issues/5977) (license identities and facts — consumed here, not re-specified); the licensing policy design [#5984](https://github.com/developing-today/code/issues/5984) (upload policy; the GPL-upload outcome is **unresolved** there — see §8); the AGPL/GPL hosting research [#5986](https://github.com/developing-today/code/issues/5986) (PR [#6258](https://github.com/developing-today/code/pull/6258), open, not touched by this design); the Roc library imports design [#5956](https://github.com/developing-today/code/issues/5956) (import-time events); the license detection pipeline design [#6008](https://github.com/developing-today/code/issues/6008) (declared-vs-detected license facts).
- **Requirement source:** Drew's brief as recorded on #5985 — "you can't combine this with this" means **warn heavily**, plus either a self-serve **override checkbox** or a **request-exception** button that raises the combination to an admin; on the user's side it should **just all work**, under the norm that anything posted can be shared.

## Decision summary

| Question | Decision |
| --- | --- |
| What is checked | Pairs of license facts (from #5977) plus a combination context, evaluated at the combination events in §2 — never free-floating uploads alone |
| What "can't" means | Never a silent hard block in v1: every incompatibility resolves to **warn + override** (self-serve attestation) or **warn + exception-only** (admin decision), per the rule table in §4 |
| Which class is exception-only | AGPL-class (network copyleft) combinations, copyleft×copyleft term conflicts, and combinations whose license facts are unknown — §4. The AGPL row's *disposition* is a configuration knob whose final value is **provisional pending #5984** (§8) |
| What an override covers | Exactly one combination instance (artifact pair + target world + pinned versions). Not global, not per-user, not transferable to a re-import of a different version |
| What gets recorded | Every override, exception request, admin decision, and reversal is an append-only registry record (§7), written **before** the combination is allowed to proceed — no record, no combination |
| What the user is told | One plain-language sharing notice in the flow at upload, import, and publish (§6.3) — not only in a ToS document |

## 1. Inputs: the license facts this checker consumes

This design owns the rule table and the UX. It does **not** own the license list: license identities, the allowed set, and the copyleft warning ladder belong to #5977, and detection (declared vs detected, upload-time scanning) belongs to #6008. The checker consumes, for each artifact (library, DLL, asset, world), a **license-fact record** of this shape — whoever produces it (#5977's classifier, fed by #6008's pipeline) must supply every field; a missing field is itself a rule input (§4, rule R8).

| Fact | Meaning | Produced by |
| --- | --- | --- |
| `license_id` | Taxonomy identity of the license (SPDX-style identifier or taxonomy-local id), or `unknown` | #5977 via #6008 |
| `license_family` | Coarse class used for display and the #5977 warning ladder only: `permissive`, `public-domain-like`, `weak-copyleft`, `strong-copyleft`, `network-copyleft` (AGPL-class), `noncommercial`, `share-alike-content`, `unlicensed`, `unknown`. Rules do **not** key on this field alone — see `obligation_traits` | #5977 |
| `obligation_traits` | The independent, multi-valued trait set the rules actually key on. Traits are **not mutually exclusive**: a license carries every trait that applies — e.g. CC BY-NC-SA 4.0 carries both `noncommercial` **and** `share-alike`, a GPL-family license carries `strong-copyleft` (and `network-copyleft` additionally for AGPL-class). Vocabulary v1: `permissive`, `public-domain-like`, `weak-copyleft`, `strong-copyleft`, `network-copyleft`, `noncommercial`, `share-alike`, `unlicensed`, `unknown`. Deriving traits is #5977's job; this design requires the interface to expose them independently, because collapsing them into one family value loses obligations before any rule runs (an NC-SA asset classified only `noncommercial` would never match R4; classified only `share-alike` it would never match R3) | #5977 |
| `facts_source` | `declared` (author-stated), `detected` (scanner), or `declared+detected-agree` / `-disagree` | #6008 |
| `rights_holder_is_actor` | Whether the user performing the combination is the rights holder of this artifact | account/ownership records |
| `version_pin` | The exact artifact version the facts describe; facts never carry across versions silently | artifact registry |

A **combination context** is supplied by the event that fires the check (§2):

| Context field | Values / meaning |
| --- | --- |
| `event` | One of the §2 events (import, link, bundle, publish, fork, cross-world reuse, re-check) |
| `distribution` | `private-draft`, `hosted-service` (others connect to a running world), `published-download` (others receive a copy), `forked-copy` |
| `commercial` | Whether the target world charges money, sells items, or is operated commercially |
| `modified` | Whether the combined work modifies the artifact (vs verbatim inclusion) |
| `target_license_id` | The license the combined work is itself offered under, if the author has chosen one |

Rules are pure functions of (fact A, fact B, context). The same pair can be a notice at `private-draft` and an exception-only conflict at `published-download`; that is deliberate — the obligations the brief cares about attach at sharing, not at private experimentation.

## 2. Combination events

A combination happens when two artifacts with independent license facts become one work a user can run, receive, or build on. Each event fires the check at a different moment; the checker must run at **every** event, because an override granted at import says nothing about publish.

| # | Event | Stage checked | Pair evaluated | Notes |
| --- | --- | --- | --- | --- |
| E1 | A world imports a library | **Import time** (the moment #5956 resolves the import) | library facts × world facts (+ each already-imported library) | The physical moment combinations happen; coordinate the trigger with #5956's import resolution, do not build a second import path |
| E2 | A DLL / platform-dependent dependency is linked into a world or library | Import/link time | dependency facts × importing artifact facts | Covers #5956's platform-dependent dependency case; native linking is the classic strong-copyleft trigger |
| E3 | Assets are bundled into a world upload | **Upload time** | each asset's facts × world facts | Asset licenses are content licenses (CC family, NC, share-alike) more often than code licenses — §4 rows R3/R4 exist for this event |
| E4 | A world is published or its distribution mode widens | **Publish time** | the world's full accumulated combination set, re-evaluated under the new context | Re-check even if every pair passed at E1–E3: distribution context changed, so outcomes may change |
| E5 | A moderation library (or any library) is reused across worlds | Import time, in the *receiving* world | library facts × receiving world's facts and context | Reuse is a fresh combination in the new world; an override in world A never transfers to world B |
| E6 | A world is forked | Fork time | the forked world's combination set × the fork's context | Forking is redistribution; unlicensed/share-alike rows (R4/R5) are evaluated here even when the original world was private |
| E7 | An artifact in an existing combination is updated to a new version | Update admission | new version's facts × the existing combination set | Facts are per-version (§1); an update that changes `license_id` or any `obligation_traits` value re-runs the check and can invalidate a prior override (§5.4) |
| E8 | License facts change without a combination change (reclassification by #5977, detection correction by #6008) | Reclassification time | all live combinations containing the artifact | Outcomes are re-derived; combinations that newly fail move to the §5/§6 flows, they are not silently grandfathered |

Out of scope as events: merely *viewing, inspecting, or reviewing* a posted artifact. Per the brief's user-side norm (§6.3), inspection is always allowed and never fires the checker.

## 3. Evaluation model

For each pair in the combination set, the checker returns **one outcome per applicable rule**, and the pair's effective outcome is the strictest of them. Applicable rules are never collapsed away: an outcome authorises only the rule that produced it, and a combination may proceed only when **every** applicable `warn-*` rule has been resolved — by its own override attestation (§5) or its own exception decision (§6). After each individual authorisation the checker re-evaluates the remaining unresolved rules under the (possibly corrected) context, so no obligation — e.g. R1's source-offer attestation sitting behind an R3 exception — is silently dropped by resolving a stricter rule first. The outcome vocabulary per rule is:

| Outcome | Meaning | User experience |
| --- | --- | --- |
| `allow` | No rule fires | Nothing shown |
| `notice` | Compatible, with obligations (e.g. attribution) | A one-line obligation note in the flow; recorded, no decision required |
| `warn-override` | Incompatible unless the user attests | Heavy warning (§5.1) + override checkbox; proceeds only with a recorded attestation |
| `warn-exception` | Incompatible unless an admin approves | Heavy warning + request-exception button; the triggering distribution action stays blocked until an admin decision (§6) |

Evaluation is fail-closed on missing machinery, not on users: if the rule engine or the registry write is unavailable, `warn-*` combinations do not proceed (an unrecorded override is worse than a delayed one), while `allow`/`notice` combinations proceed and are queued for retroactive record.

## 4. The v1 incompatibility rule table

Each rule names the facts and context it consumes, its outcome, and the decision it records. "Pair" below means (incoming artifact facts × resident artifact or target-world facts) under the event's context. Rules are all evaluated; every rule that fires stays in force for the pair. The strictest outcome determines whether the triggering action is blocked pending admin decision, but it does not subsume the others — each applicable rule must be individually resolved and individually recorded (§3), in any order, before the combination proceeds.

| ID | Pair / context consumed | Outcome | Decision recorded |
| --- | --- | --- | --- |
| R1 | `strong-copyleft` (GPL-family) × any pair, context `distribution ∈ {hosted-service, published-download, forked-copy}` and `target_license_id` is not the same copyleft license | `warn-override` | Attestation that the combined work will be offered under the copyleft license's terms (source offer, license text, notices) — or the user picks that target license in the flow and the warning clears |
| R2 | `network-copyleft` (AGPL-class) × any pair, context `distribution = hosted-service` | `warn-exception` — **exception-only** (see §8: disposition is provisional/configurable pending #5984, informed by #5986) | Admin decision only; no self-serve attestation exists for this row in v1 |
| R3 | trait `noncommercial` present (independently of any other traits the same license carries) × context `commercial = true` | `warn-exception` if the commercial context stands; downgrades to `warn-override` if the user corrects the context to non-commercial | Either an admin decision, or an attestation that the use is non-commercial (a context correction, recorded as such — a later flip of the world to commercial re-fires E4 and voids it) |
| R4 | trait `share-alike` present (e.g. a CC BY-SA asset, or the `share-alike` half of a CC BY-NC-SA asset — evaluated independently of its `noncommercial` trait, which R3 handles) × `modified = true` and `target_license_id` is not the same share-alike license | `warn-override` | Attestation that the derivative will be shared under the same license, or that the use is not a derivative work (with the user's one-line basis) |
| R5 | `unlicensed` (no license granted) × context `distribution ∈ {published-download, forked-copy}` | `warn-override` **only if** `rights_holder_is_actor = true` for that artifact; otherwise `warn-exception` | Rights-holder attestation ("this is mine to share"), or an admin decision for anyone else — nobody can override somebody else's missing license |
| R6 | `strong-copyleft` × a different `strong-copyleft`/`network-copyleft` family with incompatible terms (e.g. version- or family-conflicting copyleft pair), any distribution context beyond `private-draft` | `warn-exception` | Admin decision only; the two licenses' terms conflict on their face, so a user attestation cannot cure the pair |
| R7 | `permissive` × any pair; `public-domain-like` × any pair | `notice` (permissive: attribution/notice obligations listed) / `allow` (public-domain-like) | Obligation note recorded with the combination; no decision |
| R8 | Either side's facts are `unknown`, or `facts_source` is `declared+detected-disagree` unresolved | `warn-exception` | Admin decision, or resolution of the facts via #6008's mismatch handling — the checker never guesses a license |

Deliberate non-rules for v1: no rule fires on `private-draft` combinations except R8 (unknown facts are flagged early precisely so they do not surface first at publish); no rule inspects *who* the user is beyond `rights_holder_is_actor`; no rule attempts patent, trademark, or export questions — those are not license-combination facts and are not smuggled into this table.

Every rule row carries a `policy_gate` field in its machine-readable form (§8): rows whose subject is the *admission of GPL/AGPL material at all* resolve their final disposition from #5984's decision when it lands; until then the table above is the provisional default and is labelled provisional wherever it is surfaced (admin UI, warning copy).

## 5. The override flow (self-serve)

### 5.1 The heavy warning

Drew's "warn heavily" is a designed surface, not a dialog to click through:

- It names **both** artifacts, **both** licenses in plain words, and the specific obligation in conflict (from the rule row) — never a generic "license issue".
- It states the consequence of overriding in one sentence: the user is attesting to the rule's condition, the attestation is recorded with their name, and it can be reversed (§5.4) or audited (§7).
- The override checkbox is **unchecked by default, one per combination instance**, physically adjacent to the attestation text it accepts. There is no "always allow this pair", no "don't ask again", and no pre-ticked state anywhere in the flow.

### 5.2 Steps

1. Event fires (§2); checker returns `warn-override` with the rule id.
2. The flow pauses at the warning (§5.1). The underlying action (import, publish, fork…) has **not** completed.
3. The user reads the attestation text for that rule (e.g. R1's source-offer commitment) and ticks the checkbox. Optionally they add a free-text basis (required for R4's not-a-derivative branch).
4. The client writes the audit record (§7) **first**. Only on a successful registry write does the action complete, carrying the record's id. Registry failure = action does not proceed (§3).
5. The completed combination displays its override state wherever the artifact's license summary is shown ("combined under override, rule R1, by <user>, <date>") — overrides are visible facts, not hidden flags.

### 5.3 Scope

An override binds exactly: (artifact A `version_pin`, artifact B `version_pin`, target world, rule id, context as attested). Changing any element — a version bump (E7), a different receiving world (E5), a wider distribution (E4) — is a new combination instance and re-runs the checker.

### 5.4 Reversal

- The overriding user can reverse their own override at any time; an admin can reverse any override. Reversal is a new registry record superseding the old (§7), never an edit.
- Effect of reversal: the combination returns to its rule outcome. For an already-published world this means the publish/distribution action is suspended (the world reverts to `private-draft` visibility) until the pair is resolved by re-override, exception, or removal of the artifact. Private drafts are never deleted by a reversal.
- Automatic reversal: if facts change under E7/E8 so the attested condition no longer holds, the override is marked `superseded-by-facts` and the pair re-enters the flow. The user is notified with the reason; nothing about their earlier attestation is misrepresented — it was true of the facts as they stood.

## 6. The exception-request flow (admin decision)

### 6.1 Request

From any `warn-exception` warning, the user clicks **request exception**. The request pre-fills from the check result: the pair, both licenses, the rule id, the event and context, and the user's intended use. The user adds one required field — what they want to do and why, in their own words — and submits. The triggering distribution action stays blocked; saving private draft work is never blocked by a pending request.

Each request is scoped like an override (§5.3): one combination instance, one rule. A user with three blocked pairs files (or is offered) three requests; admins may answer them together but each gets its own decision record.

### 6.2 Decision

Admins see a queue of requests with the full check context and the rule's text. Decisions:

| Decision | Effect |
| --- | --- |
| `approved` | That **rule** is resolved under the recorded conditions; the decision record id rides the combination exactly like an override id. The combination itself proceeds only once every other applicable rule for the pair is also resolved (§3) — approving an exception for one rule never clears another rule's override attestation or exception |
| `approved-with-conditions` | As approved, plus machine-checkable conditions recorded on the record (e.g. "hosted-service only, no download distribution"); the checker enforces conditions at later events (E4 re-checks them) |
| `denied` | The combination does not proceed; the record states the reason in plain words the requester sees verbatim |

Decisions are attributed (which admin), timestamped, and reversible by an admin (§5.4 mechanics apply, with the reversal record naming the reversing admin). A denied requester may re-request when facts or context materially change; a re-request links the prior record rather than hiding it. There is no auto-approval timeout in v1: an unanswered request stays pending and visible in the requester's flow state — silence is a queue problem to surface, not a consent mechanism.

### 6.3 The user-facing sharing notice

The brief's norm — anything you post can be shared; whether your edits must be shared back depends on the license — is stated **in the flow**, at upload, import, and publish, in this shape (final copy is a #5984 policy-surface concern; the obligation to state it here is this design's):

> Anything you post here can be viewed, shared, and forked by other people. If you edit something, its license decides whether you have to share your edited version — permissive licenses say no, copyleft licenses say yes. When two licenses can't be combined, we'll warn you and give you a way to attest or ask an admin — we won't silently block you.

The notice is one line at rest (an expandable "how sharing works" line in the upload/import/publish surfaces), and the full text appears the first time a user meets each surface and whenever a `warn-*` outcome fires.

## 7. The audit record

Every override, exception request, admin decision, condition, and reversal is one append-only registry record. Records are never edited or deleted; corrections and reversals are new records that supersede by reference.

| Field | Content |
| --- | --- |
| `record_id` | Registry-unique id; carried by the combination it authorises |
| `kind` | `override` \| `exception_request` \| `exception_decision` \| `reversal` \| `superseded_by_facts` |
| `rule_id` | The §4 rule that fired (R1–R8) |
| `combination` | `{artifact_a: {id, version_pin, license_id}, artifact_b: {id, version_pin, license_id}, target_world_id}` |
| `event` / `context` | The §2 event and the full §1 context the checker evaluated |
| `actor` | The user who attested/requested (id + display name at time of action) |
| `attestation_text` | The exact text the actor accepted (for overrides), or the requester's statement (for requests) |
| `decider` | For decisions/reversals: the admin's id; `null` for user actions |
| `decision` | `approved` \| `approved-with-conditions` \| `denied` \| `reversed`, plus `conditions` when present |
| `supersedes` | `record_id` this record replaces, or `null` |
| `policy_state` | `provisional-pending-5984` on records written under §8-provisional rows, so a later policy ruling can find and re-review exactly the affected set |
| `created_at` | Registry timestamp |

Worked example — an R1 override at import:

```json
{
  "record_id": "lcr_01J…",
  "kind": "override",
  "rule_id": "R1",
  "combination": {
    "artifact_a": {"id": "lib:physics-roc", "version_pin": "2.3.1", "license_id": "GPL-3.0-only"},
    "artifact_b": {"id": "world:harbor-town", "version_pin": "0.9.0", "license_id": "MIT"},
    "target_world_id": "world:harbor-town"
  },
  "event": "E1",
  "context": {"distribution": "hosted-service", "commercial": false, "modified": true, "target_license_id": "GPL-3.0-only"},
  "actor": "user:…",
  "attestation_text": "I will offer this combined work under GPL-3.0-only terms, including the source offer and license notices that license requires.",
  "decider": null,
  "decision": null,
  "supersedes": null,
  "policy_state": "settled",
  "created_at": "2026-11-06T00:00:00Z"
}
```

Read access: admins read the full registry; users read every record naming them as actor or naming an artifact they own. The registry is the answer to the brief's audit requirement — a later admin can always reconstruct **why a combination exists**: pair, rule, who decided, under what attestation or conditions, and what superseded what.

## 8. The provisional boundary (pending #5984, informed by #5986)

#5984 owns licensing policy — server ToS, uploader grants, admin policies — and records the GPL-upload question as **unresolved**. This design therefore settles the *mechanism* and explicitly does **not** settle:

- whether GPL/AGPL material is admitted as uploads at all;
- whether the AGPL-class row (R2) remains exception-only, becomes override-eligible, or becomes inadmissible — #5986's hosting analysis (PR #6258) is the evidence input, #5984 is the decision;
- the account-level defaults and ToS grant language the §6.3 notice abbreviates.

Mechanically, this is carried three ways so the eventual decision is a configuration change, not a redesign: (1) every rule row has a `policy_gate` naming the decision it waits on; (2) records written under gated rows carry `policy_state: provisional-pending-5984` (§7), so the affected combinations can be enumerated and re-reviewed the day the policy lands; (3) warning and admin-UI copy for gated rows labels the disposition "current provisional rule", never settled policy. If #5984 rules AGPL uploads inadmissible, R2's outcome becomes an upload-admission refusal owned by #5984/#6008 — the checker's remaining rows are untouched.

| Dependency | What this design takes from it | What it gives back |
| --- | --- | --- |

| #6008 detection pipeline | `facts_source`, declared-vs-detected agreement state feeding R8 | The requirement that unresolved mismatches surface as combinations blocked on facts, not silent guesses |

## 10. Non-goals

- No implementation, scanner, or upload-detection work (implementation is a follow-up issue once this design is accepted; detection is #6008).
- No taxonomy or classifier entries (#5977).
- No policy settlement (§8) and no edits to PR #6258 or the #5986 research.
- No patent/trademark/export rules, no per-user allowlists, no global overrides.

## 11. Open questions

1. **R2's final disposition** (exception-only vs override-eligible vs inadmissible) — settled by #5984 on #5986's evidence. This design's provisional default: exception-only.
2. **Condition vocabulary for `approved-with-conditions`** — which conditions are machine-checkable in v1 (distribution mode is specified in §6.2; expiry dates and user-count caps are candidates). Settled by the implementation issue, with admin input.
3. **Registry storage home** — the record shape (§7) is storage-neutral; whether the registry lives with the artifact registry or the moderation system is an implementation-issue decision, constrained by the append-only and read-access rules above.
