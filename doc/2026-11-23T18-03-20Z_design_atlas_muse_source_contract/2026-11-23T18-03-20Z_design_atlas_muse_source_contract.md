# Atlas import contract for Muse conversations, memory and artifacts

**Design status.** This record defines the normalized input and acceptance fixture for a future local adapter. The source brief names conversations, branches, memory and artifacts. The source inventory has no verified export format, identifier stability, revision ordering, permission metadata or guarantee that an export enumerates every object. Those properties require a documented producer or a locally inspected authorized sample. No Muse endpoint, credentials, live database or schedule is assumed here. [Source inventory #9097](https://github.com/developing-today/code/issues/9097)

## Source envelope

A mapper for a verified producer format writes one manifest and local payload members. The manifest declares schema (atlas-muse-import/v1), namespace, source scope, exported coverage, export identifier, mapper version, producer schema, cursor/order contract, completeness and member digests. A full snapshot names the exact captured scope, stable permission view and authoritative revision. A paginated capture needs all pages from that view before its omissions have meaning. Restrict raw and incomplete exports to approved local staging. Hold unreadable, ambiguous and unrecognized inputs before promotion.

| Part | Required semantics |
|---|---|
| Object identity | Separate stable source namespace, scope and source key from mutable path, title, text and archive member. Preserve original object kind (conversation, message, memory, artifact). Stable provider identity can survive rename. When a provider supplies only snapshot-relative keys, record that limitation, import as snapshot-scoped occurrences, and disable cross-export inference of edits or removal. |
| Source revision | Persist the upstream version and its ordering domain. Ordered feeds may use a monotonic sequence. An opaque token can detect equality. Ordering two opaque tokens requires an authoritative reread or explicit causal relation. Wall-clock receipt order cannot resolve competing updates. |
| Upsert | Bind source key and revision to a payload SHA-256, kind, parent/thread key, media type and byte length. Namespace identifiers and constrain archive member references to the local payload root. Refuse absolute paths, traversal, symlinks, ambiguous duplicate members, length/digest mismatches and inputs beyond configured bounds. External references stay inert. |
| Relations | Keep reply, branch, attachment and derivation edges occurrence-scoped. If an edge's target is missing or inaccessible, withhold target metadata. Equal content digests do not grant permission to a different occurrence. |
| Access | Intersect source/parent/object policy with the classifier verdict. A child can narrow access. A missing or ambiguous policy keeps it outside serving until classified. Gate adjudication precedes promotion. Only the approved local path handles restricted inputs. Logs use codes and aggregate counts; raw source bodies and raw fixture substitutions never enter logs. |
| Deletion | Require an authorized explicit delete with stable identity and revision, or complete authoritative membership at a comparable newer revision under unchanged permissions. A permission change withdraws visibility immediately while retaining its own reason; a partial export, skipped page, or API error proves no deletion. Logically retire the individual occurrence and fence stale updates. Distinguish authoritative newer restoration from replay. Physical CAS collection requires a check of all authorized references and retention. |
| Delivery and progress | Deduplicate by namespace/scope/export ID and digest. A conflicting digest under the same ID is a refusal. Commit the staged receipt and occurrence changes atomically. Publish a separate gate-approved watermark. Recover after a crash by replaying the durable receipt; a retry must never restore an older object. |
| Scope-wide revocation | Apply a current policy/revocation epoch at every read, including cached search, related/read links and offline synchronization. A newly narrowed source cannot be exposed by an old occurrence or cached snippet. Reconcile storage deletion independently, retaining a disposition for each replica/derived index. |

## Adapter and promotion

1. Verify local producer, schema, source namespace, scope, parent relations, ordering semantics, permissions and complete-membership guarantees. Record which of these are unknown. Use a snapshot-only mapper where the producer lacks stable identities. Defer the live adapter until a supported source is known.
2. Compare source key/revision then content digest. Write a new occurrence for a new source position, and reuse byte-identical approved embed inputs only inside the appropriate policy domain. Store parser/chunker/classifier/model versions. An edited message can leave neighbouring windows intact or change them, according to the actual embed input.
3. Hand the staged unit to the existing gate. Record typed refusals and ordered stage verdicts, keep old authorized states only where the current policy still permits them, publish only successful batches, and preserve per-batch provenance. A periodic inventory can recover missed deliveries when the producer supports an authoritative read. [Gate implementation](https://github.com/developing-today/code/pull/11995) · [One-shot promotion](https://github.com/developing-today/code/pull/10832) · [Occurrence capture](https://github.com/developing-today/code/pull/13216)
4. When an occurrence retires, commit its visibility fence and durable cleanup work together. Search, read and related results respect the fence inside retrieval. Retry idempotent physical cleanup for lexical/vector tables, occurrences, visibility caches, recommendation materializations and read replicas. Replaying retained tombstones precedes enabling a restored replica. A second authorized occurrence of the same bytes survives.

## Acceptance fixture

[fixture.json](fixture.json) contains synthetic source operations and independent, hand-authored results at each step. Its short integer revision is a fixture assumption. Its artifact tokens stand for checked payload digests; they do not exercise archive parsing, hashing or the real provider. The expected visible maps exercise the general and restricted caller independently. A future adapter can substitute its own query and state readouts for the reference model and run the same case. Run the standard-library specimen from this directory with `python3 check_fixture.py`.

The fixture starts with one message and two separately authorized references to identical artifact bytes. It edits and replays the message, deletes the narrower occurrence, rejects its late update, preserves the other occurrence through an incomplete inventory, and retires that remaining occurrence only under a fully attested enumeration. Replaying the older complete inventory cannot resurrect it. A fixture also tests a same-revision collision against the holding of prior state and verifies a separate source scope that uses the same keys.

Before wiring a production adapter, add source-specific acceptance for truncated multipage archives, changed access between pages, opaque/absent revisions, archive member bounds, interrupted staging/publish, and visibility through all enabled routes. Run these against synthetic exports and test identities. When an authorized sample becomes available, verify producer capabilities locally and publish only the capability findings.
