## Cross-cutting findings

1. **Existence is not authority.** A hash acknowledgement proves only that a peer's stated inventory has a matching address under a declared shape; content retrieval must recompute the digest, and metadata/location claims need signer attribution and freshness.
2. **Mutable pointer safety.** Timestamp-only sidecar keys are not unique and do not prevent an ABA update. A version has `(writer, monotone generation, parent version ID, snapshot ID)`; head update is compare-and-swap. A stale writer receives a conflict and must re-read/rebase or issue a new branch. Wall-clock time is descriptive, never the concurrency ordering oracle.
3. **URI parsing security.** Parse once into components before percent-decoding component data; reject invalid UTF-8 only for text-declared fields; raw slash/question/hash are delimiters, percent-encoded versions remain payload bytes. No plus-to-space conversion. Do not normalize a namespace's payload by filesystem path rules. Local authority resolution is explicit and never falls through to a global resolver.
4. **Finite resources, open semantics.** Protocol limits are configurable operational guardrails with observable typed errors. They do not redefine legal address length, numeric magnitude, namespace count, or conceptual stream length. Stream output has per-message chunk cap, total/deadline/cursor budgets configurable by deployment, cancellation and backpressure.
5. **Sidecar privacy.** Metadata can reveal names, paths, user/cohort relationships, locations and access patterns. Default is private to namespace/tenant; location harvest is opt-in and field-scoped. Responses do not enumerate hidden sidecars, and acknowledgements reveal only the requested existence predicate. Do not publish tenant IDs in globally enumerable object paths.
6. **Signatures at every acceptance boundary.** The ingest gate ALWAYS verifies signature, signer binding, domain/tenant/scope, schema and policy before accepted state is committed. Local producers sign before entering the gate; there is no unsigned-local exception. Configuration may make signer authorization restrictive but cannot disable cryptographic validation.

## Existing-mechanism correction and limits

- Existing domain-local namespaces, registries, authorization, signed event/world mechanisms, sync, peer discovery, relay and remote-query surfaces do exist. The requirement is not “no namespaces/federation,” but no uniform cross-domain namespace registry/resolution contract or generic peer-class/federated-query protocol (`../baseline/v1-audit.md:35-39`; `../baseline/seam-map.md:7-14`). New work must coexist with Iroh doc IDs, world IDs, account keys, group scopes and name/tag APIs.
- Existing digest profiles are domain-specific: Iroh blob BLAKE3, p2panda event hash, SHA-256 signed-artifact body commitment and world module/signature digests are not interchangeable (`../baseline/v1-audit.md:12`). Keep typed legacy adapters; do not claim all V1 objects are one BLAKE3 shape.
- Storage is not one “ID on redb” engine: Iroh blob persistence, event log redb, durable world JSONL/module store and Atlas stores are distinct. The store seam cannot imply replacing event/world authority (`../baseline/v1-audit.md:14,39`; `../baseline/seam-map.md:7`).
- Atlas `content_hash` has consumers but no production producer source was found. In the inspected external snapshots the stored profile is lowercase SHA-256 of exact UTF-8 chunk text (101,471/101,471 corpus rows and 6,941/6,941 top-up rows match); the writer program/config and stability contract remain unknown. Do not generalize the snapshot data fact beyond that corpus, and keep vector output identity distinct from chunk/content identity (`../baseline/v1-audit.md:18,22-24`).
- The independent seam map notes #6277–6290 issue/design overlap has not been reconciled; summit owner should check issue snapshots. This worker does not claim that sibling contract family is resolved (`../baseline/seam-map.md:8,22`).

## Settled design updates (supersede earlier candidate outcomes)

- **#9113 vs #9118 vs #9120:** #9113 owns shape/profile dispatch only; #9120 owns the immutable content-address core; #9118 owns the mutable array-address core. Initial content profile is raw exact-byte Iroh BLAKE3-256. SHA-256 signed-artifact commitment is a separate domain type. Profile selection is static/configured parse dispatch, not a per-object lookup/translation map. Preserve all legacy representations.
- **Atlas snapshot identity:** focused read-only check in the updated baseline audit found that 101,471/101,471 rows in `/home/user/atlas/v3/corpus.db` and 6,941/6,941 in `topup-chunks.db` match lowercase SHA-256 over each exact `text.encode('utf-8')` value. This identifies observed snapshot values only; the writer source/config is still absent. Record this as a separate `atlas-chunk-sha256-utf8` profile/seam and file a producer-contract follow-up; do not equate it with raw-byte Iroh IDs or vectors. See `../baseline/v1-audit.md:18,22-24` for the bounded read-only evidence and external script digests.
- **#9117 URI:** settled syntax is `id://<resolver-hint>/<namespace>/v1/content/<profile>.<digest>` or `id://<resolver-hint>/<namespace>/v1/array[ /<slot> ...]`. Resolver hint is a required lowercase registry alias in the RFC 3986 authority and must match the caller-selected local resolver; it never triggers DNS/global lookup. Null is `~`, bytes are `b.` plus percent-encoded octets (empty bytes `b.`); empty array ends at `/array`. Codec/reference corpus: `uri_codec_reference.py`.
- **#9114 identity bytes:** new records use deterministic CBOR. `PayloadId` hashes raw payload; canonical Body commits payload ID, length and domain/context; detached signature covers domain prefix + Body; EnvelopeId/AssertionId/SnapshotId hashes the complete signed envelope including signature. IDs are not self-embedded. Snapshot filenames use signed snapshot digest; mutable head uses CAS generation/parent. This deliberately refines timestamped sidecar naming.
- **#9115 receipts/locations:** ExistsAck uses the B19 V2 shared receipt schema's `verified_present` assertion; B11 is unrelated Diamond Types research. Bind responder, subject digest, scope, policy epoch and observation time without promising retention. Unverified inventory observation is distinct from verified presence. Index all valid authorized visible locations in a complete signed sidecar; typed initial locators are R2, laptop hostname/path and Drive account/fileId/URL. Signed stale/delete tombstones reconcile projection.
- **#9122 numerics:** `Integer(BigInt) | Decimal(coefficient, exponent10) | BinaryFloat(sign, BigInt significand, exponent2)`, normalized significands, canonical `+0`, no NaN/infinity in ordered registry, type-tag-first mixed-kind comparison, no coercion. Comparators must avoid materializing large exponent powers and return operational budget errors.
- **#9106 staging:** registry + array/content cores and URI codecs belong in V2 per proto core plan; names/numeric derived family and streams are V3, signed worlds V4. Twelve coarse slices were refined into independently testable codecs, contracts, storage, queries, compatibility, projection and conformance slices.

## Limits and summit questions

- V1 observations follow the bounded source-only baseline audit, plus the specific local SQLite snapshot check above; not a deployment inventory. “Implemented” means source exists; deployment/runtime status remains unknown (`../baseline/v1-audit.md:3,18,22-24,30-34`).
- Internal URI shape is settled; keep it explicitly unregistered and do not claim IANA registration. RFC 7595 remains relevant only if a later public scheme-registration proposal is made.
- Initial ID content profile is settled as raw exact-byte Iroh BLAKE3-256 with compatibility preserved; the separate Atlas snapshot profile/data evidence does not identify the absent producer source.
- Resolver hint syntax is settled; implementation must bind its lower-case alias to the caller-selected local resolver and never perform implicit DNS/global lookup.
- Storage adapter capability varies. CAS is required for multi-writer mutable-head semantics; where absent, the adapter must reject unsafe writes or serialize per head. Do not weaken this as an undocumented fallback.
- Numeric mixed-kind order, zero normalization and finite-only ordered profile are settled in `versioned-design.md`; remaining implementer work is exact comparator vectors and resource-budget behavior.
- Signed-world key-history source/revocation policy remains an external seam. Conservative default: unknown key status is not currently authorized; historical signature validity is returned only when historical key state is verifiable. #9124 can specify that verifier interface without taking on SSO (#9077), tenancy (#9083), or #9084 reference-vs-copy.
