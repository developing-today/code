# Part B versioned design — federation and trust

**Status:** proposed design, not implemented protocol. **Date:** 2026-11-13. Source inventory and ranges are in the proto note §1 and §7. This Part B owns #9141–#9148; #9111's crosscut writer owns the final mode/config schema. #9077 SSO and #9083 tenancy are inputs/boundaries, not redesigned here. Relationship with #9084 content plane remains unresolved: use content digests and references without assuming its transfer/retention contract.

## Architectural choice

Keep identity, authority, content, location and network topology separate. The immutable content digest identifies bytes; a signed event identifies an assertion by a key; peer policy determines whether that assertion may be accepted; a location or query response is time- and policy-scoped evidence, not identity. Every ingress follows one signature-validation gate, including local/loopback and first-party peers. Trust classes are directional policy labels, never cryptographic facts. Query fanout is a bounded primitive; priority and modes are configuration. Sync first reports conflict, then may exchange/resolve; no silent merge in V2.

## V1 — observed baseline (audited source, not a uniform target contract)

The bounded source audit in `../baseline/v1-audit.md` is authoritative for this wording. Implemented mechanisms include Iroh blob storage/references; Iroh raw BLAKE3-256 over exact bytes; BLAKE3 event commitments; signed artifact SHA-256 over `serde_json::to_vec(SignedBody)` with a documented-preimage/code mismatch; Ed25519 identity/artifacts; specialized Iroh/event-log sync; type-tagged tuples; and Atlas corpus/search consumers. Atlas `content_hash` has no checked-in production producer contract. ID already has domain-local namespaces/registries, replicated event/world data, authorization, peer discovery, relay and local/remote query behavior. Those are not one uniform cross-domain registry or generic federation/query protocol. Blob storage, event-store redb, and fsynced `worlds/journal.jsonl` are separate. Never silently change legacy signed bytes to fix the preimage mismatch. The universal signed gate is proposed: local producer signs before admission and traverses the same validation path. For sibling designs #6277/#6287–6290 are staged; #6312 is not settled plan-of-record. Preserve their contracts pending reconciliation.

Identity vocabulary for new records: `PayloadId` hashes raw payload bytes; `ContentId` hashes exact profile bytes; `EnvelopeId`/`AssertionId`/`SnapshotId` hash the complete canonical signed envelope including signature and are never included in their own preimage. `LogicalGraphId`/space address is a stable logical coordinate, not assertion content identity. A new signed `Body` commits `PayloadId`, length and domain/context using deterministic CBOR; Body excludes its signature and all IDs computed from the enclosing envelope. Initial new-envelope suite is **Ed25519 over deterministic-CBOR Body with a domain prefix**, using 32-byte public keys and 64-byte signatures, and a versioned allowlist registry for suite agility; unknown or unallowed suites fail closed. Detached signature signs domain-prefix plus canonical Body. Legacy JSON artifacts keep their exact byte profile and compatibility vectors; no implicit rehash/re-sign. Derived indexes/caches are rebuildable projections of validated signed authority; independently retained/transported derived objects require signed service-produced envelopes. These types do not assert an IANA namespace-core registry.

## V2 — signed acceptance, classes, reports

### Wire/data model

- `PeerPolicy { peer_id, class, operations, relay, scope, policy_version, valid_from, expires_at }`, where class is `fully_trusted | send_only | accept_signed_from`. “Fully trusted” means broad configured operations only; never skips validation. Unknown peers default to reject/no acceptance.
- Directional class semantics: `fully_trusted` permits only the explicitly configured send/accept operations (not validation bypass); `send_only` permits local outbound sends and rejects peer-originated accepted data; `accept_signed_from` permits configured inbound objects only after signature, signer identity, semantic validation and scope authorization. None of these classes alone grants query relay, completeness authority, or cross-tenant access. Class changes are versioned per peer; demotion/revocation stops future admission and triggers the stated quarantine policy for past records.
- S1.55 relay eligibility requires **both** `class=fully_trusted` and explicit scoped `relay=true`, plus current authorization and budgets. `accept_signed_from` remains accept-only and cannot relay even if a malformed configuration requests it; `send_only` cannot relay incoming queries. Config validation rejects those combinations.
- `SignedEnvelope { suite, signer_id, key_id, event_id, object_id, sequence?, parent_ids[], issued_at, payload_digest, payload_len, scope, signature }`. Canonical bytes are domain-separated and signature binds all fields. Key lineage is signed; rotation does not invalidate prior valid envelopes. Revocation records effective interval and reason; affected accepted data is revalidated/flagged/quarantined by policy, never silently rewritten.
- Ingest state: `received -> parsed -> signature_valid -> identity_bound -> policy_allowed -> accepted`; any failure ends in typed rejection with evidence. Local producer signs **before admission**, then local and remote channels share this path—local does not bypass the gate. Events are immutable; update means a new event referencing predecessor.
- `ConflictReport { report_id, object_id, versions[], signer/source[], scope, policy_digest, detected_at, evidence_refs[], status }`. Creation precedes merge. Reports are durable/addressable, resolution is a new signed event. Conflicts do not block unrelated objects.
- **Emergency key/peer controls are V2-crucial.** A local signed revocation/disable record immediately blocks new acceptance and relay authority for the key/peer. Keep signed bytes and admission-time policy/key-status evidence; label affected data `quarantined` pending explicit revalidation. V2 does not infer true signing time from issuer wall-clock claims: attacker backdating cannot be solved by timestamps. Historical validity needs independently witnessed key-status/epoch evidence or is `indeterminate`. Advanced cross-peer takeover attribution/reputation remains V4.

### Errors / state outcomes

`MalformedEnvelope`, `UnsupportedSuite`, `BadSignature`, `UnknownSigner`, `RevokedKey`, `Replay`, `BindingConflict`, `UnauthorizedClass`, `OutOfScope`, `Expired`, `ConflictDetected`, `Quarantined`. Rejection is observable/auditable; it does not automatically become a public accusation. Record locally observed admission-time key status/policy. A signed wall-clock timestamp is not independent proof of historical validity; it may remain indeterminate.

### Conformance and tests

All implementations reject unsigned, misattributed and invalid signatures, including fully trusted and local inputs; reject unknown/unallowed suites and noncanonical new-profile bodies; reject unknown peer by default; retain historical signer/key binding across normal rotation; distinguish replayed event IDs from new events; create report before resolution. Cross-language vectors cover canonical new CBOR bytes, malformed and noncanonical encodings, invalid/misattributed signatures, exact legacy JSON artifact bytes, and the documented-preimage/code mismatch. Vectors prevent silently changing legacy signature bytes.

### V2 shared receipt schema (B19; later V3/V4 consumers)

The shared signed assertion enum is `accepted | retained_until | verified_present`. Each receipt binds payload/content digest, recipient key identity, scope, time/epoch, policy digest, validity duration/interval and unique receipt ID; signer-key identity binding is validated separately from the signature. `accepted` means the normal universal gate admitted the exact digest under stated policy; `retained_until` is a bounded retention commitment, not perpetual availability; `verified_present` is a challenge-verified existence assertion at a time. #9115 existence acknowledgement uses `verified_present`. `stored_unverified` is only an inventory observation and is never accepted content or a bypass of the signed gate. Receipt schema is V2-crucial and depends only on V2 signer/envelope foundations; V3 fanout adds relay provenance later.

## V3 — bounded query federation, duplicate and routing semantics

### Query contract

`OriginQuery { request_id, origin_nonce, origin, query_digest, scope, issued_at, expires_at, initial_max_hops, initial_budgets, signature }` is immutable and origin-signed. `request_id` is derived from origin key, fresh origin nonce, and canonical immutable query-binding fields (excluding ID/signature to avoid a cycle); verifier recomputes it. Thus independent requests for identical query/scope/time have distinct IDs. Any changed query/scope/expiry/limit paired with old ID is `BindingConflict`, statelessly. Replaying the same signed query after expiry is `Expired` and never reruns. `RelayGrant { request_id, origin_query_digest, parent_grant_digest, relay_id, child_id, hop_index, path[], child_budgets, expires_at, signature }` is separately signed by the parent relay and chained to the previous grant. Relays cannot edit origin query/signature. Each honest relay maintains a durable local reservation ledger: disjoint child allocations sum to no more than remaining parent allocation; retries reuse exact reservation. Cancellation/expiry closes outstanding reservations; finite binding tombstones are retained through origin expiry. Local store is queried first; a remote negative is local-to-that-peer, never global absence.

Every origin query independently caps total hops, peer breadth, work units, bytes and elapsed time. The reservable vector is hops/peer slots/work/bytes; elapsed is a monotonic deadline, never refundable or reset. Accounting uses nested scopes: per-query; per authenticated requester/origin and supplying peer; per locally authorized tenant context; and node aggregate across all tenants/requests. The node aggregate remains the final cap; one requester cannot consume another's reserved per-peer allowance. Tenant identity comes from local authorization context, not an arbitrary query field. Each honest node atomically reserves the vector against every applicable scope before work/forwarding, and child allocations partition remaining amounts. Cancellation refunds only unspent reservations; locally measured completed work/bytes stay charged. Reservations expire at request expiry plus finite cleanup grace; cancel/expiry closes remaining allocations. Retries reuse the same reservation ID and exact vector, never mint; elapsed/hop/breadth/work/byte counters do not reset. Fair queueing is a policy option, not a fairness proof. A network-wide total cannot be enforced against Byzantine nodes that fork grants, falsify work or ignore cancellation. The guarantee is per-requester and per-honest-node local enforcement, not global spend. Defaults are conservative; modes may adjust within hard limits.

### Response/provenance

`SignedResponse { request_id, responder_id, scope, policy_digest, completeness?, results[], generated_at, signature }`. A relay wraps but preserves original responder bytes/signature and adds its own signed forwarding receipt; it cannot re-sign as the origin. Validate origin, signature, request binding, scope and budget at every hop. `complete=true` is an explicit claim with defined scope/policy/authorization/time; omission cannot be inferred merely from absence.

### Duplicate/replay/cycle state

Replay is a signature/event freshness failure. Duplicate is a valid repeated `request_id`; cycle requires signed grant-chain path proving local peer already visited. Changed query binding under the same ID is `BindingConflict`. In-flight duplicates attach to one work item; completed duplicates return deterministic cached outcomes; results dedup on stable result ID while retaining provenance. Cached outcomes are reauthorized under current policy before release; revoked/disabled peers cannot disclose old cached results. If result cache is evicted while the origin request remains valid, the retained ledger permits only rehydration or resumption against the **same reservation and remaining counters**, never a new reservation or fresh execution of completed work; if outcome cannot be rehydrated, return `ResultEvicted` without rerun. Cache and ledger retention are finite but request-binding tombstones remain through origin expiry. After expiry the origin-signed query **must not rerun**, even if its result cache was evicted. Requester is informed of duplicate/loop status.

### Resource/security invariants

Every query bounds **hops, breadth/peer fanout, total work units, bytes in/out, and elapsed time** independently; no retry resets consumed budget. Enforce response size before allocation where possible. Privacy: every queried remote learns the query interest; config declares allowed scope and retention. No shared global topology assumption. Signed routing observations carry observer, scope, timestamp and expiry; periodic probes/observations may mark partial graph stale, not complete. Route changes are signed evidence but still subject to local policy.

## V4 — conditional CRDT, reputation, takeover and public claims

CRDT adoption is conditional on measured scale/latency/merge pain and the five #9143 research slices: (1) Automerge structured metadata fit; (2) Diamond Types text fit, with intended “diamonds” referent unresolved; (3) Willow scoped reconciliation; (4) OCapN capability-based authority/handoff fit and separate application-level attenuation question (not an established OCapN feature); (5) common comparison/revisit threshold. Complete outcome may be “adopt none.” Conflict report is always preserved pre-merge. Any later CRDT adapter consumes signed operations and emits deterministic state plus retained provenance; it does not authenticate authorship. No CRDT implementation work is enabled until evaluation gives measured reason and interop/signature adapter contract.

`Claim { claim_id, claimant, subject, allegation, scope, interval, evidence_refs[], created_at, signature }` and `Reply { claim_id, respondent, statement, evidence_refs[], signature }` are append-only claims, not verdicts. Require signatures, bounded rate/bytes and evidence references; corrections and appeals are new records. Reputation is evidence-derived local policy, not a globally authoritative scalar. Ratings may be signed and portable as claims but locally weighted, capped, freshness-decayed, and separated by evidence class. No first-party privilege. Sybil/collusion/whitewashing cannot be eliminated; document trust assumptions and redress.

### V4 acknowledgment and recipient-list evidence

V4 consumes the shared V2 receipt schema above. A recipient-list commitment binds transfer ID, exact recipient set (or Merkle root and inclusion proof), digest and time; receiver's `accepted` receipt independently proves admission. Contradiction evaluator requires same object/digest, interval, scope, policy, authorization and exact claim semantics (accepted/retention/completeness); otherwise result is `insufficient_evidence`. Withheld evidence is not proof of omission.

### Routing validation and reputation policy

Routing probes use a locally configured interval and jitter, nonce-bound signed request/response, timeout and finite observation TTL. They produce partial local evidence, not a global topology. Preference is local and signed observer attribution does not establish truth; no first-party preference. Auto-reputation evidence classes are explicit: attributable supplying-peer protocol violations, scoped receipt contradiction, availability timeout, and successful valid service. An invalid signature does **not** authenticate its purported signer; never attribute it to that claimed signer. Count a bad-signature event against a supplying peer only when authenticated session/peer binding plus signed/session evidence establishes that peer supplied the exact bytes; otherwise reject and retain unattributed evidence without peer-rating penalty. Unverified public claims/popularity have no direct verdict weight. Proposed initial deterministic thresholds: 1 attributable cryptographic failure rejects that object; 3 distinct attributable events for the accountable peer in 10 minutes trigger local peer quarantine/review; retries of one event count once. For availability, 3 timeouts among 5 valid probes in 10 minutes lower local priority; 5 consecutive successful probes after 10-minute cooldown restore one band. Positive service evidence cannot override security quarantine. Hysteresis prevents oscillation; no threshold implies global verdict. Rate-limit 3 claims per claimant/subject/day and 64 KiB evidence references per claim; deduplicate evidence IDs, cap per-identity contribution, allow appeal/right-of-reply, and never reward allegations. Values are proposed starting defaults, not externally verified or universal weights.

### Public claims log privacy/fairness

Log append-only signed commitments with redacted public metadata and private evidence references under explicit access control. Claim and reply have equal authentication, rate and size rules; subject receives equivalent reply opportunity. Inclusion proves publication only. A unilateral allegation cannot automatically alter global reputation; there is no first-party adjudicator. Corrections, privacy redactions and appeals are new signed events; cryptographic audit retention is distinct from private evidence retention, deletion and quarantine policy.

### Retention, deletion, quarantine and privacy boundary

Sync convergence excludes records outside authorized scope, expired retention, tenant boundary or privacy policy. A deletion/tombstone is a signed scoped event; physical deletion may prevent historical 1:1 equality, so report `deleted_by_policy` separately from `missing` and `not_authorized`. Quarantine preserves bytes and provenance but withholds normal query/sync release pending revalidation. Private evidence references are access controlled and may be redacted/deleted under policy; the public commitment must not leak content or infer guilt from a redaction. Each conflict/receipt/claim records the applicable retention policy digest and expiry; those fields constrain evidence, not guarantee future availability.

Takeover response: V2 immediately disables acceptance/relay for locally revoked key or peer; preserves signed history; identifies data by key lineage and admission-time evidence; quarantines affected records. Signer wall-clock dates do not prove pre-compromise signing; historical status may be indeterminate absent independent epoch evidence. V4 adds cross-peer incident attribution and reputation. A signed acknowledgment proves only its bounded assertion at that time; it does **not** prove perpetual retention or later query eligibility. A contradiction requires identical object/digest, scope, interval, policy, authorization and completeness/retention claim with proof obligations met. Missing result otherwise proves nothing.

## Modes/config seam (#9111)

The separate #9111 design should own named modes, link kinds and storage tiers. This design requires knobs for peer class, sync scope, relay permission, fanout priority, budgets, retention and local rating weights. Config cannot disable validation, bounds, provenance, finite dedup retention, emergency key revocation/peer disable, or rejection observability. Mode bundles compose with per-peer settings; hosted service is an ordinary configured peer. No final serialized config shape is asserted here.

## Migration and compatibility

1. Inventory current ID/hash/transport paths; preserve existing ID world/event/group contracts. Do not claim V1 protocol features without audit.
2. Introduce versioned envelope parser and canonical test vectors in shadow mode; do not admit new API objects until signer/key binding and required validation exist.
3. Activate the mandatory signed-and-validated gate for the new API (configuration cannot disable it); unknown peer rejects. Backfill legacy bytes as `legacy_unverified`, quarantined from accepted data; accept only after authorized re-attestation over the exact legacy profile bytes/digest and full validation, never fabricated signatures or silent rehash/re-sign. Keep compatibility vectors for legacy JSON preimages and introduce deterministic CBOR only as a new profile.
4. Add conflict report persistence and anti-entropy without auto-merge; retain old bytes and report migration provenance.
5. Add query protocol as an opt-in link kind with conservative caps. Old peers are not implicitly relays or accepted data sources.
6. Upgrade suites via parallel verifier support and signed capability advertisement; deprecate only after interoperability window. Key revocation/emergency peer disable is V2-crucial; it blocks new acceptance/relay immediately and quarantines affected material. It does not rewrite signatures or pretend signer timestamps prove signing time.

## Executable invariants and test oracles

- **PBT envelope:** arbitrary mutation of any signed field causes verification failure; oracle is independent reference verifier/golden vectors.
- **PBT budget accounting:** spent counters are monotone non-decreasing and never refunded; `spent + held reservation <= cap` in every scope. Cancellation/expiry refunds only unused held amount, and retries do not create an extra reservation. Oracle is a multidimensional reference ledger, not a fairness/crypto proof.
- **PBT dedup:** same request ID + policy version yields one deterministic result; cache eviction while request remains live can only reuse retained outcome/state and reservation, never mint budget or repeat completed work; once origin expires return `Expired` and never rerun. Oracle is reference state machine.
- **MBT state machine:** generate ingest/rotate/revoke/replay/accept sequences; expected result comes from explicit model (event accepted at time/key policy and subsequent incident status).
- **MBT network:** generated cyclic graphs, failures, duplicate delivery and retries; every trace terminates under deadline/work/byte/hop caps; oracle is budget ledger plus model result set.
- **Conflict-first oracle:** audit log sequence must contain report before any merge/resolution event; unrelated object sync remains possible.
- **Claims/evidence oracle:** a receipt alone never proves future retention/eligibility; contradiction evaluator returns “insufficiently scoped” unless scope/time/policy/auth/completeness match exactly.
- **Runnable experimental model:** `python3 -I doc/2026-11-13T03-40-00Z_design_id-atlas-summit/part-b/federation_model.py` checks fixed oracles for disjoint sub-budget reservation, retry reuse, changed-binding rejection, revocation-before-cache-release and no rerun after expiry, then 2,000 seeded bounded allocation-tree traces. It models grants as already authenticated edges; it is not crypto, Byzantine agreement, or proof of global network budget enforcement.

Open questions recorded with defaults: exact historical revocation policy (default quarantine affected interval, preserve bytes; signer wall-clock alone cannot prove signing time); dedup TTL/capacity (finite config with bounded hard maximum, request-binding tombstone through origin expiry); whether complete responses are allowed (default opt-in); #9084 transfer/retention boundary (default only digests/references until agreed); original Part B candidate provenance (see source log). Initial crypto suite is settled as Ed25519 + deterministic-CBOR new profile and allowlisted suite registry; legacy artifact JSON is preserved. No question blocks progress; #9111 owns final config choices.
