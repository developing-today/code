## Proto amendments recommended to summit owner

1. In version plan V1, replace categorical “no namespaces” with “no single cross-domain namespace registry/resolution contract; multiple domain-local namespaces and IDs already exist.” Replace categorical “no federation” with “no generic peer-class/federated-query protocol; specialized peer sync and relay mechanisms exist.”
2. Refine “ID on redb” to enumerate blob storage vs event/world stores; establish actual package/path ownership and backend before promising redb → SQLite/Turso/IndexedDB as a single migration.
3. **Clarify current implementation status without changing mandatory V2 invariant.** Today’s source proves particular signed formats and receipt checks, not a universal invariant. The proto's mandatory acceptance rule remains binding for V2: configuration cannot disable validation and there is no trusted-local exception; local producers sign before crossing the same gate. The remaining work is to map all ingress paths, specify key lifecycle/replay/migration and produce path-by-path conformance evidence—not to decide whether the invariant is optional. This matches the query design's owner sensitivity override only for own unencrypted data; it does not override cryptographic boundaries.
4. Keep the #9083/#9084/#9078 and #9091/#9100 interfaces owned by their existing issues/designs. Summit should record dependency/seam acceptance (scope, identity, auth, lifecycle, conformance) rather than cloning their contents.
5. **Issue reconciliation (2026-11-12 `gh issue view`):** #6277 and #6287–#6290 are all OPEN. #6277 is a research/design umbrella (explicitly no implementation) and its comments link the version ladder and #6312 plan-of-record. #6287 v1 waits on #6277 first-pass research; #6288 v2 waits on v1 design; #6289 v3 waits on v2; #6290 v4 waits on v3.
