# Part C versioned design — economics, search, recommendations

**Scope:** #9133–#9140; S2.1–S2.19 and S6.1–S6.17. **Status:** proposed contracts; does not supersede #9082 (store), #9083 (tenancy), #9084 (content plane), #9091/#9092 (Atlas), or #9100 (VFS). V1 is an inventory of repository reality, not a claim about a deployed system.

## Cross-part identity and signed-derived-data contract

Use shared summit vocabulary without coercion. `ContentId` hashes exact profile bytes; `PayloadId` hashes raw payload bytes. New signed records have canonical `Body` committing `payload_id`, length, domain and context; detached signature covers domain-prefix + canonical Body, and Body excludes its own signature and `EnvelopeId`. `EnvelopeId`/`AssertionId`/`SnapshotId` hash the complete canonical signed envelope including signature and never occur in their own signed preimage. `LogicalGraphId`/space address stays stable and separate from assertion content hash. New profile uses deterministic CBOR. Existing legacy artifact JSON bytes/signatures remain a legacy profile with compatibility vectors; never silently re-sign or rehash. Current Iroh exact-byte BLAKE3 identity, Atlas consumer/schema `content_hash`, `ContentId`, and `PayloadId` are distinct unless producer profile contract explicitly maps them. Cache/index/search are rebuildable projections over validated signed authority; independently retained/transported derived objects require signed service-produced envelopes. Conflicts reject/report, never implicitly coerce.

### #9135 store placement adapter (S2.7–S2.9)

Separate `BlobStore` (immutable bytes), `MetadataIndex` (tenant-scoped metadata/locations), `EventStore`, `WorldStore`, and `SyncStore`; placement is per surface. Candidate implementations: D1 shard set; SQLite file with single-writer WAL replication (Litestream-style) to object storage; Turso remote + embedded replica/logical sync; current redb. `StoreCapabilities` declares transaction scope, durability, read consistency, max object/db size, sync mode, and conditional-write support. No transparent adapter may promise semantics it cannot provide. `put_if_absent(tenant, content_id, bytes, metadata)` verifies hash/signature/authorization before commit and returns created/already-present; `get` is authorized and consistency-qualified. Recovery tests verify crash-prefix, WAL/checkpoint and replica restore. Multi-writer object-store SQLite is prohibited unless a separately proven coordination protocol is specified.

### #9136 shared bucket (S2.10–S2.13, S2.18)

`BucketRef { bucket_id, trust_domain, mode: Trusted|BrokeredUntrusted, locator_profile, encryption_profile }`. `ContentId` hashes exact profile bytes; `PayloadId` hashes raw payload. Physical ciphertext locator is a separate tenant-scoped opaque mapping. Do not silently change global IDs to keyed IDs. In untrusted mode co-tenants see ciphertext payloads only; broker-enforced opaque locators and metadata policy prevent plaintext payload/metadata exposure. Per-request broker authorization precedes object operations. Broker and encryption are separate interfaces. Hash equality, HEAD/list, timing, metadata and dedup are explicit leakage dimensions. Tenant/trust-domain mandatory; missing isolation config rejects.

### #9137 GC (S2.14–S2.15, S2.19)

#9084 must own an atomic reference/tombstone generation authority. Writers conditionally commit reference intents only while generation `Live(g)`; GC atomically fences `Live(g)→Tombstoned(g)` only when no references/intents/valid leases exist. This prevents late ref-add TOCTOU: g is no longer referenceable. Each physical generation uses an immutable generation-qualified key that is never reused. Resurrection allocates g+1, uploads/verifies it under a distinct new physical key, then commits refs to g+1; canonical `ContentId`/`PayloadId` profile does not change. A failed pre-commit upload may leave an orphan but cannot publish a reference. After grace, collector may issue ordinary DeleteObject only for the captured, fenced, never-reused key for g; it does not rely on a conditional-delete API. A stale delete of g cannot address g+1. If either the #9084 atomic fence or key non-reuse cannot be proven, physical deletion is unsupported/disabled. A normal put addressed to Tombstoned(g) rejects or returns Tombstoned; only explicit resurrection may allocate g+1. Collector prioritizes largest reclaimable files within bounded budget; chunk identities/manifests are independently reclaimable without changing whole-file canonical identity. #9084 owns the predicate/transaction mechanism; reference-v-copy remains unsettled.

## V3 — bounded hot cache, ID search and recommendation processing

### #9134 tenant hot cache (S2.4–S2.6, S2.17)

Current #9092 cache is indefinite. Avoid Turso hop per hot hit: ingestion pushes a signed monotonic corpus watermark to the cache control plane; policy authority pushes monotonic authorization epoch/revocations. DO durably records watermark, policy epoch, event sequence and a lease. Cache admission is configured by tenant tier and compute usage, with hard per-tenant/global byte limits, LRU/age eviction and observable eviction counters. Cache key binds tenant, authz scope, policy epoch, normalized query, schema and search-space version—no per-hit source-snapshot lookup. Serve only if watermark lag is within configured max-staleness and lease/sequence/policy epoch are current. Event gap, stale/unknown policy epoch or expired lease fails closed to uncached source/bypass. Real-time/cache-disable options bypass result cache. Revocation is immediate: stale policy cannot serve; if push propagation cannot be guaranteed, require synchronous authorization check or disable cache. #9083 owns auth/policy epoch authority.

### #9138 indexing/search (S6.1–S6.3, S6.13–S6.14)

Current model: Snowflake arctic-embed-m-v2.0. Second embedder is owner-undecided per #9092; evaluate BGE-M3, Voyage, OpenAI text-embedding-3, Workers AI using #8627 quality, cost, self-hostability and mixed-corpus support. Do not default to Snowflake Cortex as a vendor. The platform contract is ingest→async autoqueue for configured much/all accepted content, idempotent embed jobs, backfill, and built-in tenant-authorized ID search; ingest never waits for vectorization. Persist exact model identity/version and keep incompatible spaces separate. Embeddings/index/cache are rebuildable projections over validated signed authority. Independently retained/transported vector artifacts need signed service-produced envelopes under shared identity contract. Search/shard acceptance belongs only to #9092.

### #9139 fanout and DO accumulator (S6.4–S6.7, S6.15)

One logical scheduler dispatches bounded jobs. At job start pin parent snapshot inputs, ranking configuration and candidate cutoff, then materialize a deterministic total order: score descending, immutable recommendation ID ascending; later arrivals belong to the next snapshot and cannot reorder current pages. `ParentSnapshotId` hashes its complete signed parent envelope, which describes inputs/ranking/cutoff and excludes page EnvelopeIds (avoiding a hash cycle). Each independently retained/transported page has its own service-signed envelope; its body binds `ParentSnapshotId`, page position and entries, and its `EnvelopeId` hashes the complete signed page envelope including signature. Cursor binds only the pinned parent ID plus position (and schema/expiry), never a page ID. State includes job, snapshot, algorithm, partition cursor, sequence, finite dedup/replay horizon, status/lease and watermark. `next(10,cursor)` yields stable pages; restart/replay at same parent and position returns same page envelope. Wrong-parent and expired cursors reject. Define terminal `done=true` separately from empty nonterminal page. Expired replay is rejected, not applied. DO state is a rebuildable projection; per-tenant/user partitions prevent hot spots/leaks. A separate result manifest, if needed, is a later envelope referencing parent/page IDs and is not included in ParentSnapshotId.

### #9140 recommendation objects/history (S6.8–S6.12, S6.16–S6.17)

Immutable `RecommendationSnapshot` has `SnapshotId` (hash of complete canonical signed service envelope), tenant/subject, input reference, algorithm/model version, created timestamp, result references, provenance and retention class. Envelope Body commits payload identity/length/domain/context; detached signature covers domain prefix + canonical Body; ID is excluded from its own signed preimage. Search-history/input objects remain separate, separately authorized and retention-tagged. Before/after compares explicit signed snapshot IDs and version metadata. Hot intermediates have shorter TTL; comparison snapshots longer class; deletion/legal hold explicit. GC follows #9084 fence.

## API invariants, errors and budgets

- Security: every request includes tenant and principal; authorize before cache/search/bucket lookup. Signed/validated acceptance remains mandatory for content; auth is not inferred from signature. A local producer signs before admission; local origin does not bypass the signature gate. Missing tenant, policy or signature returns typed rejection, never permissive default.
- Storage errors distinguish `NotFound`, `Unauthorized`, `Stale`, `Conflict`, `QuotaExceeded`, `Unavailable`, `Corrupt`, and `Retryable`; mutations require idempotency keys and conditional generation/version checks.
- Budgets: benchmark workload bounds; cache max bytes + freshness; vector queue max attempts/DLQ; DO per-invocation page/time ceiling; GC page/object/bytes budget. Values are deployment config with safe caps, not universal constants.
- Observability: tenant-safe aggregate counters; do not log raw search query, plaintext object key, or cross-tenant identifiers without policy. Benchmark raw fixtures stay synthetic/public.
- Compatibility: all persisted records include schema/version and migration path; old vectors remain addressable by embedder/pipeline identity while reindexing.

## Conformance and migration

Contract tests run against in-memory adapters and each engine; differential oracle checks logical results against reference model, not timing. PBT: hash/tenant isolation, idempotent queue page replay, cursor monotonicity, GC never deletes referenced or active-leased object, crash/restart preserves committed pages, cache key changes on tenant/auth/policy/watermark. MBT: generate ingest/retry/delete/revoke/GC and recommendation paging interleavings; oracle is a small reference state machine. Fault injection: timeout after write-before-ack, duplicate delivery, stale cache event, lease expiry, concurrent ref addition at GC grace boundary, provider quota exhaustion. Migration: inventory actual store authority per crate; add adapter without changing authority; shadow-read and compare; move a tenant only after restore/conformance proof; retain rollback source until verified; vector reindex is versioned side-by-side; no destructive delete before all references/consumers have migrated.
