# Fleet schedule registry

One record for every recurring schedule the fleet runs, across all three
schedule surfaces — the unified registry required by #4988, from the
placement-framework v1 synthesis on #2024 (registry requirement first
specified in the #2020 Jules investigation).

- **Surface 1 — Muse cron:** judgement-bearing fleet jobs, defined in
  Muse's scheduler (the definitions are the source of truth; the
  read-only copies live under `~/workspace/cron.d/` and
  `~/workspace/goals/<goal>/crons/` on the Muse host).
- **Surface 2 — OpenCode schedules:** OpenChamber per-project
  `scheduledTasks` (laptop stores:
  `~/.config/openchamber/projects/*.json`) plus the laptop's systemd
  user timers — the OS-timer surface the #2019 pattern and its
  implementation issue #2232 build on. #2232 is still open, so this
  section lists the units as they exist today.
- **Surface 3 — Jules schedules:** web-UI CRUD on the one collected
  Jules account (pilot #2265).

**This registry is an input to the placement audit** proposed in the
#2024 framework doc
(`doc/2026-11-03T15-10-56Z_design_task-placement-framework-v1/`): the
audit's "which surface owns this recurring work" question is answered
from these tables, not from memory.

## Maintenance rule (same-pass)

**Creating, changing, or retiring a schedule on ANY surface updates
this registry in the same pass** — same PR, same run, same commit
series. A schedule that exists on a surface but not here is a defect
(the failure mode #2020 named: schedules invisible to fleet reviews);
a registry row whose schedule no longer exists is the same defect in
the other direction. Reviews refresh the `Last review` date and fill
in any `not recorded` fields the surface now exposes.

When refreshing systemd timer rows (Surface 2b), preserve each timer's complete effective calendar specification — date and time components — exactly as `systemctl --user show` reports it; truncating a spec to a date-only prefix silently changes the documented cadence (issue #5313).

## Fields

Per schedule, per #4988: surface, name/id, repo/scope, cadence, route
or pool, prompt/brief pointer, budget expectation, owner, kill
criteria, date created, last review. Where a surface does not record a
field, the cell says `not recorded` — never a guess. For Muse cron,
cadence is the scheduler's schedule key; the prompt/brief pointer is
the job's definition file on the Muse host. Budget expectation and
kill criteria for cron jobs live in each job's own body (its timeout
and its stop conditions) and are summarised here only where the job
states them in its title; otherwise `not recorded`.
