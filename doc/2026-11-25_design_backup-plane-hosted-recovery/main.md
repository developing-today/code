# Backup plane hosted recovery design (#14964)

Status: proposed design, 2026-11-25. This is not an authorization to change live schedules. No schedule registry entries are changed by this record; proposed hosted cadences must be explicitly reviewed and entered in the registry when implemented.

## Evidence and decision

The audit `doc/2026-11-25_audit_backup-paths.md` (F4) found the GitHub backup timers uninstalled on amd-6, mirrors drifted, R2 bundles stale, three of four rehost repos unpublished, and the freshness probe absent. The queue D1 export was about 41 hours stale (F4/C1), tracked as a silent failure on #10296. The relevant scripts already verify their outputs, but their inputs and schedules are tied to a laptop checkout (`infra/github-backup/README.md`, `infra/github-backup/rehost/README.md`, `infra/fleet-queue-backup/README.md`).

**Decision:** hosted scheduling is the recovery home; amd-6 remains an optional cache/consumer, never a required source or the only alarm path. Use GitHub Actions on the default branch for repeatable jobs that can reconstruct from GitHub/remote APIs. Actions cannot see `~/backups/github` or laptop state: mirror, bundle, and rehost jobs must fetch the repositories they need from GitHub into ephemeral runner storage, then publish. Queue export reads Turso remotely. No Tunnel, runner on amd-6, or claim that a hosted workflow can inspect its filesystem.

The GitHub mirror targets and source are in the same provider failure domain: this leg protects against accidental deletion/drift and supplies an independently verified clone, not GitHub-wide/provider loss. R2 bundles and the Cloudflare Worker/R2 rehost are the cross-provider recovery legs. Queue D1 is a coordination/analytics copy, not durable decision truth (`infra/fleet-queue-backup/README.md`); do not widen its recovery promise.

## Per-leg design and recovery

| Leg | Proposed hosted path | Failure removed / remaining | Replacement recovery procedure |
|---|---|---|---|
| Plain mirrors (17 owners + force-includes) | Scheduled Actions workflow fetches the configured repo inventory directly from GitHub into fresh runner-local bare mirrors, then invokes/adapts `plain_mirror.py` semantics to push all refs to pre-created mirror repos and compare advertised refs. Preserve tier rules and explicit inaccessible-repo gaps (SAML/451); never depend on laptop alternates or local checkout. Note: fork-family alternates dedupe is a laptop-local optimization — hosted fresh clones either pay full storage/time or need an explicit sharding/incremental strategy; validate the full inventory against Actions time/storage limits and the GitHub App rate-limit pool before claiming full coverage. | Removes laptop power, checkout cleanliness, and uninstalled systemd timers as freshness blockers. Does **not** remove GitHub-provider/account loss, nor prove inaccessible repositories. | On missed/failed run, dispatch workflow; inspect per-repo outcome and repair missing target repos/credentials. On source loss, clone from mirror repo and verify refs/HEAD; accept that source and mirror share GitHub failure domain. |
| R2/cold bundles | Separate scheduled Actions job reconstructs bundles from GitHub for the configured fleet set (and later agreed inventory), validates with `git bundle verify` plus isolated clone/HEAD check, uploads via narrowly scoped R2 credential and reads back/hash verifies. Reuse bundle tooling where it can accept fetched ephemeral mirror paths. | Removes laptop mirror/cache and laptop timer dependence; R2 is independent provider. Does not protect against R2 bucket/account loss or a source already lost before capture. | Manually dispatch the job; investigate run artifact/log and object key/hash. Restore by downloading selected bundle, `git clone`/`git fetch` from bundle, then verify expected HEAD and refs. Keep retention policy from #12269; no pruning until successful verification of replacement generation. |
| Git rehost publisher | Scheduled job independently fetches all four intended fleet repos from GitHub, builds complete packs and refs indexes using `rehost_publish.py` semantics, uploads pack then refs commit marker, reads both back, retaining current+previous verified generations. Run live clone drills for all four repos. | Removes laptop publisher and its local-mirror dependency. Worker serving survives laptop downtime (it reads already-published R2 packs) but shares Cloudflare/R2 account fate with the bundle leg — the two are cross-provider relative to GitHub, not independent of each other. Does not remove GitHub-source/provider loss before a publication, nor Cloudflare/R2 account/domain loss. | Dispatch publish; if refs marker did not commit, previous generation stays authoritative. Restore publisher from repository workflow/code and scoped credentials; verify pack/index readback then clone each endpoint and compare HEAD. Roll back Worker separately if protocol deployment is faulty; never delete prior pack generation before a successful clone drill. |
| Freshness probe | Independent hosted scheduled workflow compares source GitHub refs, mirror refs, R2 bundle metadata/hash, rehost live advertised refs, and D1 export timestamp against per-leg SLOs; emits a machine-readable per-repo/leg result and creates or updates a GitHub alert issue on stale/missing/error. Alerting must not rely on the job it monitors alone: use GitHub Actions failure notifications/monitoring plus a second scheduled watchdog or external uptime check for missed workflow runs. | Removes laptop probe as sole observer and detects stale copies even when the source jobs are green-but-no-op. Hosted probe cannot prove laptop local mirror state; that state is deliberately non-authoritative. GitHub Actions/account-wide outage remains a common-mode blind spot and needs external monitor. | On alert, dispatch the named leg, inspect run IDs and observed source/copy heads/timestamps, then restore from R2 bundle or rehost as appropriate. Close/update alert only after fresh verification. If the probe itself misses its interval, external monitor pages/files a separate alert. |
| Queue export | Extend #10296: scheduled hosted exporter reads Turso `fleet-queue` over its API, writes D1 using current exporter/readback-count oracle, records export timestamp and run identity, and alarms on stale age or failed/missed run. Keep credentials in Actions secrets, least privilege; restore drill remains separate and targets scratch Turso. | Removes laptop timer/checkout dependence and makes the silent failure visible. Does not make D1 durable truth, solve the broader Turso mesh, or cover GitHub Actions/Cloudflare/Turso simultaneous outage. | Dispatch exporter after diagnosis; verify `_fleet_queue_backup_meta.exported_at`, readback counts, then run restore drill into scratch target. Never restore over production as an alert response; reconstruct coordination state from durable GitHub artifacts if D1 is unavailable. |

## Scheduling, security, and operational contract

Proposal only: daily mirror/R2/rehost jobs in ordered windows (mirror first, then R2 and rehost); freshness shortly after all three; queue export at least daily with staleness threshold shorter than its tolerated recovery point. Final UTC cadence, concurrency, and freshness thresholds are implementation decisions to be measured and recorded in `doc/fleet-schedule-registry.md` in the same change that creates/changes a live schedule. Do not copy the laptop systemd times blindly or edit the registry for this design proposal.

Workflows run from default branch under `workflow_dispatch` and explicit schedule triggers consistent with `.github/ci-policy.md`; do not introduce PR-triggered secrets/deploys. Pin actions, restrict token permissions, use dedicated scoped credentials, avoid logging secret values, serialize writers per destination, and make reruns idempotent. A job must fail nonzero on partial/incomplete coverage and publish per-repo outcomes; missing inventory entries are not success. Restrict scope to the GitHub backup and queue export surfaces; no live deployment or schedule change in this design slice.

## Review boundaries / unresolved gaps

- Inventory and credentials for the full 17-owner + force-include mirror set must be validated against Actions time/storage limits and GitHub App installation/rate limits; the four fleet repos are the first required end-to-end acceptance set.
- R2 bundles and the rehost Worker share one Cloudflare account fate; they are independent of GitHub but not of each other. R2 itself currently has no second-target replication (#13457, outside scope).
- Class-D D1→Turso home leg (`export_to_turso.py`, #13458) is out of scope for this slice; queue-export work here covers Turso→D1 only.
- Alert loop needs dedup, flap/rate-limit guard, and distinct "probe-missed" vs "leg-stale" signals; probe credential needs read access to all legs (least privilege per leg).
- Retention reference #12269 must be confirmed at implementation before relying on "no pruning until verified replacement."
- Hosted credentials and exact Actions API capabilities for triggering a genuinely independent missed-run monitor require implementation verification. If a second GitHub-only watchdog cannot observe Actions outages, choose an external monitoring surface before claiming independent alerting.
- GitHub mirror does not protect against GitHub provider loss. R2 and rehost are the intended independent retrieval surfaces; R2 itself currently has no second-target replication (#13457, outside scope).
- The actual D1 export failure root cause remains #10296's diagnosis; moving scheduling does not by itself fix API/export errors.
- Freshness claims must be based on observed source/copy ref equality, verified bundle metadata, rehost live advertisement, and D1 export metadata—not timer presence or a successful process exit alone.

## Code-grounded clarifications and verified when

The audit's 18-owner figure differs from the README's 17 owners plus force-includes; use generated config inventory as the operational oracle, not either prose count. Local bare acquisition across that inventory is distinct from the off-machine plain GitHub mirror leg: `plain_mirror_all.py` imports a fixed `FLEET_REPOS` set; `bundle_r2_all.py:18-23` enumerates code, fleet, openchamber, and opencode. The required hosted publisher scope is these four fleet repos. Scaling acquisition/export to the whole estate is contingent on measured disk/runtime/rate limits, not silently promised by migrating the existing drivers. No laptop alternates file can be reused remotely.

`bundle_r2_all.py` and `rehost_publish.py` already accept `--root`; hosted adapters must create a valid plan and independent bare mirrors there. `plain_mirror_all.py` resolves its root from configuration and accepts no CLI arguments, so a config/root adapter is required. `rehost_publish.py:19-25` verifies pack before refs, then prunes except current/previous; delaying pruning through the live clone drill requires an explicit implementation adjustment. No direct portability claim is made for the current laptop wrappers or their Bitwarden/rclone setup.

#10296 originally concerns Supabase `pg_dump` failure with two scheduled-success and watchdog acceptance checks. The later audit associates the Turso→D1 silent failure with it; reuse requires an additive current-store subsection/comment, not replacing its historical acceptance or falsely claiming that root cause was diagnosed. Preserve the Supabase gap until independently resolved or explicitly retired with evidence. Class-D reverse export (#13458) is outside scope.

**Design verified when:** independent review confirms all five legs have explicit removed/remaining failures and recovery procedures, the record is indexed, and #15000/#15001 plus reused #10296 are linked from #14964 with enqueue results. The existing `python3 -I scripts/research_workflow.py check` is a documentation/workflow consistency check, not proof of deployed backups. No prose-specific tests are invented.

**Implementation verified when (follow-ups, not claimed here):** with amd-6 unavailable, hosted manual then scheduled runs publish all four repos with exact refs, downloaded bundle isolated clones resolve expected HEADs, all four live rehost clones match captured refs, and D1 counts/timestamp plus scratch restore match the export. Compare against a captured source ref set rather than a moving HEAD; rerun if it changed during validation. Simulated stale/failed/missed legs and a stopped probe produce distinct deduplicated external alerts. An external watchdog must signal outside GitHub too when GitHub issue filing itself is unavailable. Record run IDs, source refs, hashes, timestamps and restore evidence before declaring live coverage; schedule registry updates occur only with implementation. GitHub outages prevent refreshing from source, but existing Cloudflare copies remain retrieval sources; never overwrite a good destination after failed source acquisition.
