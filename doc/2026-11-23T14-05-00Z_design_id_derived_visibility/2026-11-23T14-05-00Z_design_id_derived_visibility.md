# Visibility of derived search, navigation and federation metadata

**Design proposal dated November 23, 2026.** The motivating observations use the pinned sources below.

**Proposed integration contract.** Choose a visibility profile per peer class and entry point. The strict reader profile compares two stores that differ only in facts the principal cannot learn. The projected response must agree for the declared observables at the same visible frontier. A selected trusted peer can have a wider replication entitlement. The reviewed native exchange constructs its greeting from a full inventory while offers subsequently apply scope. B09 is an implicit-trust link. Whether its greeting is appropriate depends on which peers may enter that link. [Native exchange](https://github.com/developing-today/code/blob/7310a95730791e66da98f7b0e13865930058a516/pkgs/id/crates/id-sync/src/federation/exchange_net.rs#L586) · [Peer-class design](https://github.com/developing-today/code/issues/9142)

| Surface             | Observables to specify                                         | Independently specified fixture                                                                                                                                                                                                                 |
| ------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Graph query         | Count, edge provenance, next-page indication, branch badges    | A principal sees A and B and the edge A→B. Add a hidden neighbor H to a copy. Compare authorized adjacency, count and pagination at the visible cut.                                                                                            |
| Search and diagrams | Ranking, snippet origin, visible layout inputs and legend      | Compare two corpora with the same authorized rows. For strict ranking privacy freeze public scoring statistics or use a suitably partitioned index. A shared BM25 corpus may legitimately differ under a separately documented looser contract. |
| Replication         | Inventory IDs/digests, withheld IDs, receipt and diagnostics   | Define entitlement for full-trust, scoped and unauthorized peers separately. Fail the fixture only if a class sees something outside the agreed profile.                                                                                        |
| Cached derivative   | Availability and source of cached detail after a grant changes | A thumbnail or snippet retains an authorizing source reference and checks current service authority. Eviction and physical copies already received have distinct semantics.                                                                     |

**Boundary.** Define the observable set including errors, cursor validity, result order and metadata. Physical timing noninterference is a separate, much stronger property and this fixture makes no timing claim. The existing authorized-query adapter can keep its own symbols and wire format. Host-side scope and a caller-supplied filter must have separate roles. Shared global statistics are compatible only with a declared policy that permits their influence. [Federation query chapter owner](https://github.com/developing-today/code/issues/9108) · [Atlas publication](https://github.com/developing-today/code/issues/6062)

**Decision needed.** First find the existing peer-class and Atlas policy records. Only ask an owner to decide which profile applies where the records leave a real choice. No wholesale protocol or search-index replacement follows from this proposal.
