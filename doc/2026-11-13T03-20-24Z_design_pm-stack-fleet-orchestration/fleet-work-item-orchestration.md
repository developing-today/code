# Fleet work-item orchestration, context hydration, and reliable completion

**Track:** B · **Status:** integrated design proposal; no implementation, schema or rollout authorization.  
**Scope:** canonical work identity, lifecycle/claim compatibility, durable context and activity, relations/journal/authority, operation outbox, direct verified completion.  
**Shared contract:** [`architecture.md`](architecture.md). **V1 evidence:** [`census/track-b.md`](census/track-b.md), [`census/commands.jsonl`](census/commands.jsonl). **Requirement crosswalk:** [`components/9198-requirement-crosswalk-current-state-census.md`](components/9198-requirement-crosswalk-current-state-census.md).

## 1. Outcome and boundaries

Extend the existing Fleet multicall and queue/broker, not replace them. A work item has canonical `(authority_id, work_id)` identity and typed external resource links; GitHub `owner/repo#number` is a locator, not globally unique work identity. Both serialize as strings: authority ID is an opaque canonical authority reference, while this queue's work ID is canonical unsigned decimal. Compare authority IDs bytewise and work IDs by arbitrary-precision numeric order (digit count then digits; 9 before 10), never lexical decimal-string order. Opaque provider/session IDs remain opaque strings. Preserve independent lifecycle, readiness, ownership/lease, execution/session receipt, and remote issue/PR state. CLI sugar composes existing validated service primitives behind one typed, versioned `Command`/`Result`; all arguments parse strictly before side effects. No new queue/database/scheduler/binary/resolver/GitHub client or generalized creator-outbox producer.

Existing `fleet queue`/`repo-queue`, queue `park`/`wake`/`complete`, fallback and merge-intent stack replay are real source-level substrate; they do not establish the proposed `fleet work` lifecycle, all command aliases, verified cross-resource completion, or deployment. Exact target spellings stay individually tracked in `census/commands.jsonl`; `list` is not `search`, `wake` is not `resume`, `queue complete` is not `work complete`, `fleet gh` is not a new `fleet github` backend. Read Track B census/test matrix before claiming any surface.

## 2. Lifecycle, identity, claim and CLI composition

Map current queue states loss-aware; do not silently rename existing stored `queued/parked/blocked/done/cancelled/failed`. Claim is ownership, not proof a session started. `manual_only` is persistent eligibility; Do Now is a distinct one-shot directive. Honor #9178 claim/manual/takeover/resume and #9179 park rules. Task requirements AND caller filter both apply; both empty defaults true; identity is not an implicit filter. Selection snapshot and broker transaction cover item/work version, graph, policy/profile, lane/ownership, lease and authoritative time. Staleness recomputes/reselects or returns typed conflict; no sampled candidate grants claim. If storage cannot validate atomically, target cannot advertise this guarantee.

Where approved by storage owner, monotone per-item lease generation fences stale local writes only. Expiry supports takeover/liveness, not remote cancellation; GitHub does not accept Fleet fencing tokens. Authenticated principal/capabilities—not `actor_ref`—authorize. Accepted intent captures principal, exact permitted effect/request digest and policy; delayed send rechecks revocable permission/preconditions. Revocation blocks future sends, not already sent effects. An authenticated restricted broker recorder can append independently verified late evidence to the exact operation, never confer stale-worker mutation rights. New work-command v1 fingerprints use RFC 8785 JCS + SHA-256 with purpose/version separation over validated/default-expanded intent, excluding retry/delivery/receipt/format/wait/dry-run metadata; legacy creation-outbox hash stays unchanged. JCS property sorting is UTF-16, preserves strings without normalization, and does not define queue work-ID numeric ordering. Shared `CLI-02` and `HYD-01` fixtures own cross-language digest vectors and manifest self-digest exclusion, not a new hash service or shipped claim.

One local owner handles shared CLI glue and capability registration; domain slices provide typed handlers. Current proposed placement is internal modules in `fleet-queue`, not storage ownership. QTI remains unlocated; #9241/task 15480 is bounded research. Crosswalk #3424/#8575/#8579 (and #8580–#8585) before schema-coupled work; offline model/contracts may proceed. See [#9206 §3–7, §8](components/9206-work-item-lifecycle-fleet-subcommands.md) for transition matrix, exact CLI map/compatibility, implementation slices and test commands; `commands.jsonl` and writer-owned `command-slice-map.jsonl` maintain every command/option key, including absent exact forms.

## 3. Durable context and incremental activity

Hydration publishes a versioned immutable generation and provenance manifest, with completeness/status per source/endpoint, bounded request/byte/time/memory budgets, safe repository-scoped artifact identity, source freshness, hashes, PR head binding and no missing-as-empty. Stage, validate and persist; manifest last; switch current pointer atomically or use versioned conditional pointer with weaker guarantee explicit. Preserve previous complete generation on failure. Artifacts are not queue-row blobs.

Cursor identity is per canonical source/resource, endpoint, query shape, API version, auth-scope class and cursor generation. Persist every page's records and dedupe identity before cursor advance; handle DB/artifact split through staged refs + durable ingest intent + hash verification. Reordered/duplicate pages replay idempotently. Event ID, resource revision, delivery ID, occurrence/observed/source-updated times stay distinct. Old comments can be edited; overlap is mitigation not proof. Record deletions/minimizations only on authoritative evidence; otherwise expose coverage limit. Attribute origin through operation/session/outbox and remote IDs, never shared username alone; uncertain events remain external by default.

Hydrated content is untrusted data, not authority or executable instructions; private notes obey visibility. Full object list and 250-commit/3000-file caps, API pagination, resource bounds and failure tests are detailed in [#9207 §§2–7](components/9207-context-hydration-incremental-activity.md).

## 4. Typed dependencies, journal, notes and field authority

Store each relation once with canonical direction/type/hardness/status/history/provenance. Only active hard blockers affect readiness/effective pressure; parent-child hierarchy, advisory, duplicate and supersedes relations are not blockers or implied completion. For edge `u→v`, cycle iff `u=v` or current graph has path `v→u`; validate and commit under serialized graph revision to prevent opposing insert race. Incomplete graph returns partial/unknown and fails closed. Resolve one edge without clearing others; unresolved external hard ref is not silently satisfied.

Fleet owns work state/urgency and private journal; GitHub owns external issue/PR body/discussion; provider owns actual session; Project orchestrator remains sole writer. Private notes, status reasons, checkpoints, public comments and journal events are different concepts. Corrections append superseding records; do not claim complete event reconstruction absent proven field/transaction coverage. Default private; allowlisted safe status projection only; note mirror requires explicit scoped authorization and is a separate remote operation. Body-section updates default unsupported without verified conditional-write capability; separately approved best-effort must disclose lost-update risk and retain before/after evidence. GET/compare/PATCH is not CAS; known managed comment IDs still lack universal exactly-once creation.

Crosswalk existing #3424 task model and #8575/#8579/#8580–#8585 one-home/metadata/mirror constraints before schema. See [#9208 §§2–7, 9–11](components/9208-typed-dependencies-notes-journal-field-authority.md) and [FDR-PMO-005](decisions/FDR-PMO-005-dependencies-journal-authority.md).

## 5. Durable operation outbox and direct verified completion

For accepted consequential mutation, one **local** transaction commits canonical state, journal fact, and required immutable remote intent, after current store semantics are verified. Never hold transaction across HTTP. Outbox records stable operation ID, actor-scoped idempotency key + canonical digest, work/version/fence, target, immutable payload, effect-specific precondition, attempt history, remote refs and verification evidence. At-least-once relay; no remote exactly-once/fence assumption. Unknown after send timeout requires remote readback before retry. Same-target causal operations cannot overtake unresolved prior effect. New owner can wait/reconcile, supersede only pre-send with CAS, or compensate after observed effect; never silently discard intent.

Completion explicitly authorizes each PR/issue reference and required/optional effect. Transition to recoverable `completing`; refresh activity and check policy; merge using expected head SHA where supported; distinguish accepted/queued from merged; verify remote merge and specifically designated closures; then directly finalize canonical queue item and effect receipts in one local transaction. Normal success requires no webhook/sweep. Partial merge/close remains recoverable; don't undo successful merge. Final refresh watermark and read→merge TOCTOU are explicit. Changed head/check/review/branch rule, new hard blocker, revoked authority or hold/cancel stop further consequential effects. Actionable review/comment observed before finalization holds for policy evaluation; post-completion activity appends evidence and invokes explicit post-completion triage/reopen policy, never rewrites history.

Creation outbox is a bounded one-producer pilot; generalized lifecycle mutation outbox is separate scoped work and schema gate. Do not create a new DB/service. See [#9209 §§3–10](components/9209-leases-fencing-outbox-direct-completion.md) for effect states, crash cuts, merge strategy verification and recovery oracles.

## 6. Worked source scenarios and acceptance

1. **Fresh worker (charter A):** bootstrap capability discovery → `work next` uses normal highest eligible selection, atomic claim/revalidation → full hydration generation → agent reads summary/selective diffs → private journal note → external activity since session start attributed by operation mapping → refresh review/check state → completion outbox, remote verification and direct Fleet finalization. Incomplete hydration or unknown source stays explicit; no claim from board sort.
2. **Blocked/parked/resume (charter B):** add typed hard blocker with evidence; preserve hierarchy separately. Park checkpoints durable cursor/artifact refs before lease release under #9179. Later resume refreshes activity, checks every blocker and #9178 semantics, acquires new generation, incrementally hydrates. One resolved edge cannot unblock while another remains.
3. **New live comment (charter C):** reuse the projector's bounded HMAC-verified ingress and delivery dedup as a disposable projection/intake seam; then authorize/resolve/normalize and durably accept the typed operation at canonical Fleet authority. Projector ACK is not command acceptance. Resolve current bound session; deliver and record ack; do not ordinary-queue-wait or duplicate on redelivery. If parked, direct dispatch only after explicit authorization, fresh gates and canonical reservation; #6533 live proof remains separate.
4. **Near-timeout (charter D):** checkpoint branch/commit, tests, activity cursors and next steps; park/release safely. Timeout returns resumable operation receipt, not cancellation. Do not start risky merge merely to beat budget.
5. **Crash after remote success / lost acknowledgment:** operation is unknown until readback; exact operation effect may be confirmed and finalized even if worker lease expired, through restricted recorder and unchanged/current-completing validation; no new stale-worker mutation.
6. **Late external review/comment:** final refresh captures watermark; expected head SHA protects only changed-head merge precondition; no global GitHub/Fleet lock. Apply policy to any event observed before local terminal commit, and post-completion policy for later observations.

Tests use independent lifecycle/cursor/graph/outbox reference models, PBT invariants, concurrency races and fake remote ledger with apply-then-timeout. A test filter must list the exact unique test before it counts. Mock pass, code merge, deployment and live GitHub/dispatch proof are reported separately.

## 7. V1–V4 and alternatives

- **V1:** existing queue verbs, worker/lease fields, queue events/outbox and merge-intent substrate are pinned facts only. No general work namespace, generalized outbox, monotone fence proof, full cursor/hydrator, typed graph/journal or verified completion saga inferred. See `census/track-b.md` and `commands.jsonl` exact evidence/gaps.
- **V2:** reviewed common identity/envelope, source authority, state transitions, graph/cursor, outbox/receipt and negative-oracle contracts. Eight FDRs are locally adopted for design scope; this does not adopt new live semantics or settle unresolved #9178/#9179 rulings.
- **V3:** pure/reference tests and adapter conformance → persistence only after schema gate → remote effects/recovery → direct completion and one CLI integration slice. New issues required for implementation, migration, rollback, runbook and coverage.
- **V4:** #9079/#9081 use identical state-machine, cursor, authority and recovery fixtures; implementation/storage differ only behind contract. Separately prove deployment/live behavior.

Alternatives: replace Fleet with new workflow/event-store infrastructure, dual-write, webhook-only completion, worker-ID-only lease, whole-body replacement, or flat/untyped blockers. The chosen direction reuses the existing broker and bounded saga pattern because remote effects cannot join a local transaction; a workflow runtime would add operation surface without solving GitHub idempotency/fencing. A controller is useful for recovery, not normal successful completion. Full event sourcing is deferred until measured audit/replay need; append-only facts do not imply reconstructable total state. Details and comparative risks are in #9206–#9209 and `research/track-b-state-of-art.md`.
