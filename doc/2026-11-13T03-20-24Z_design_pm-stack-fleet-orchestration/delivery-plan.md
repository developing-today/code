## Planning rules

- Each implementation slice is independently testable and owns exact files. The existing integration glue (`fleet-queue/src/lib.rs`, client dispatch, `fleet/src/main.rs`, registry/capabilities) has **one** CLI registration owner from #9206 (`CLI-13`). Domain slices deliver handlers/contracts and do not concurrently change shared glue.
- Hard dependencies are semantic or file-collision prerequisites. Soft edges mean useful-before relationships or adapters that can be built in parallel. A whole domain parent is not a prerequisite when a granular key is the real dependency; this avoids cycles.
- Offline pure contract/reference-model and read-only work can proceed before QTI/storage authority. Any overlapping persisted schema/migration remains blocked pending QTI #9241 plus #3424/#8575/#8579 and current storage owner reconciliation.
- Each issue gets a named failing test/oracle, negative case, compatibility behavior, migration/rollback if relevant, and a measured done command. Proposed component tests are future tests, not passing evidence.
- CI/test coverage and actual adapter behavior are independent acceptance; mock-only tests never prove live GitHub/Project/dispatch. Rollout/deployment/live proof requires separate authorization and evidence. No production changes authorized here.
- **First executable work after the design documents land:** offline/reference-model and schema golden fixtures in Wave 1 (`CEN-01/02`, then `DST-01`/`CLI-02`, `PRI-01/03`, `SEL-01`, `HYD-01`, `REL-01/03`). These operate on local fixtures and do not write production data. The source/semantic judge and filing owner review can proceed in parallel; QTI does not block these contracts.
- **Runtime-only gates:** #9028 producer reconciliation before canonical PM dispatch reservation/cutover; #9178/#9179 compatibility before live claim/park changes; #6533 separately authorized live launch/bind proof; Project/GitHub/hosted deployment readback after adapter and rollback acceptance. No offline test is a substitute for those gates.

## Hard and soft edge summary

- **Hard:** shared envelope before adapters; exact #9178/#9179 behavior before claim/park implementation; QTI/#3424/#8575/#8579 owner compatibility before overlapping schema changes; #9028 reconciliation before canonical PM dispatch reservation/cutover; operation identity/outbox before remote lifecycle effects; hydration final-refresh contract before completion freshness; authentication/field authority before mutation; each handler before single CLI registration.
- **Soft:** #9079/#9081 hosted targets and #9201 UI are consumers of pure contracts; read-only projection and offline fixture work can proceed while QTI is researched. #6533 is a separate direct-dispatch live acceptance gate, not a blocker to offline routing parser tests or a proxy for lifecycle completion.
- **No invented production blocker:** rollout/security approver, storage migration owner and API endpoint guarantees must be drawn from actual existing authorities; if unverified, record as an evidence gap and keep the affected effect/capability disabled, while continuing independent design work.
