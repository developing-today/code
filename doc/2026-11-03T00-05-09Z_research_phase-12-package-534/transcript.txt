## What and why

These Phase 12 tasks (`.opencode/plans/phase-12-platform-flexibility.md`) need a design, or for D1-026 a research package, before anyone implements them. Run each through the research workflow, commit the design, then open an implementation issue and tick the box. F12.1 (manifest) and F12.4 (provider registry) are the plan's two highest-return tasks; F12.7 (ABI spec) is part of its recommended first slice.

## Items

Each box is done when the design (or research package) is committed and an implementation issue is linked here.

- [ ] **D1-019 — F12.1 Declarative world manifest (world.toml) with apply / --dry-run / diff** (L, design)
  A world.toml naming module (hash or source), seed, grants, ceilings, resource profile, roles/invites and schedules. `id world apply` reconciles a live world idempotently through existing admin operations, and `id world diff` detects drift. The plan calls it one of the two highest-return tasks.
  - Status: not started. No `world.toml` parser and no Apply/Diff command: `grep -rn 'world.toml' pkgs/id/src` finds nothing; `WorldCommand` (cli.rs:1388) lacks Apply/Diff.
  - Source: .opencode/plans/phase-12-platform-flexibility.md:31; .opencode/plans/phase-12-platform-flexibility.md:21; .opencode/plans/phase-12-platform-flexibility.md:80
  - Prerequisites: #543 — D1-011 F11.11 One client projection (seed secret, chat by scope) + enforcement test, #227 — D1-012 F11.12 Journal format version header, check and backup commands
- [ ] **D1-022 — F12.4 Capability provider registry (manifested components)** (L, design)
  Providers become components with a manifest (name, version, argument schema, bounds, required scope, default ceiling), read by the ledger, compile gate and CLI, so adding a capability needs no edit to world.rs. One of the two highest-return tasks.
  - Status: not started. pkgs/id/src/world_caps.rs:55 `pub const CATALOG: &[&str]` is a hard-coded list, and execution is a string `match` in pkgs/id/src/world.rs:2526-2547. No registry type (`grep -rn 'ProviderRegistry\|provider_registry' pkgs/id/src` finds nothing).
  - Source: .opencode/plans/phase-12-platform-flexibility.md:37; .opencode/plans/phase-12-platform-flexibility.md:16; .opencode/plans/phase-12-platform-flexibility.md:80
  - Prerequisites: #540 — D1-010 F11.10 Split world.rs, world_session.rs, cli.rs (moves only), #554 — D1-013 F11.13 Error taxonomy: stable codes plus reasons on the wire
- [ ] **D1-025 — F12.7 Versioned guest ABI spec, plaza_abi_version export, conformance suite** (L, design)
  Write the `plaza_*` exports and capability protocol down as a versioned spec, add a `plaza_abi_version` export, and publish a conformance suite built on F11.16 fixtures and the #239 recordings. Part of the recommended first slice.
  - Status: not started. The ABI is described only in module docs (pkgs/id/src/sandbox.rs:6-8 lists plaza_out_len, plaza_alloc, memory). `grep -rn plaza_abi_version pkgs/id` finds nothing, and there is no spec document or conformance test directory.
  - Source: .opencode/plans/phase-12-platform-flexibility.md:43; .opencode/plans/phase-12-platform-flexibility.md:84
