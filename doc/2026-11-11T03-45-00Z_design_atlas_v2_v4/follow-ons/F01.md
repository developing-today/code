# F01 — synthetic missing-versus-buried diagnostic fixture and runner seam

**Tier/status:** recommended; fixture work ready after this design merges. No runtime integration is implied. Parent [#6020](https://github.com/developing-today/code/issues/6020), programme [#6018](https://github.com/developing-today/code/issues/6018); [design on main](https://github.com/developing-today/code/blob/main/doc/2026-11-11T03-45-00Z_design_atlas_v2_v4/2026-11-11T03-45-00Z_design_atlas_v2_v4.md). Evidence: [baseline](../research/01-baseline-inventory.md), [diagnostic research](../research/04-feedback-retrieval.md), [architecture](../research/06-architecture-directives.md).

## Problem and boundary

The existing #5741 `atlas-eval` scores supplied rankings against qrels; it does not enumerate a corpus or determine which pipeline stage lost a known target. #6046 owns a feedback-derived golden-set builder/gate; #8062 owns its missing fresh-ranking seam. This slice does neither: it tests diagnostic reasoning on a closed synthetic world, with no claim of real-corpus absence.

## Deliverable and minimal interface

Create an offline fixture pack and a test-local runner accepting a synthetic snapshot ID, independently enumerated eligible documents, coverage completeness, target ID and relevance, indexed IDs, generated ordered candidate IDs, served cutoff, context-included IDs, per-stage completion/error state and answer-support flag. Return stage and coverage confidence independently; unknown and intentionally excluded may not be presented as globally absent. A timeout/error is not an empty successful candidate set, and a served hit omitted from context is not an answer-support failure. No production API, trace schema, corpus loader or model is required. Fixed in-memory supplied runs are not #8062's live baseline/candidate generation.

## Steps and oracle

1. Write failing example fixtures: incomplete coverage, fully enumerated absent, stored but unindexed, indexed but not a candidate, candidate below cutoff, served but omitted by context packing, context delivered but unsupported, served supported, stage timeout/error, and policy excluded. Explain a forbidden target only with ordinary not-found shape.
2. Write a small reference decision procedure independent from the runner under test; use generated finite corpora and compare the runner's stage/coverage tuple to the exhaustive-set oracle. A positive control explicitly includes the target; a negative control requires complete enumeration. Mutation tests or explicit deliberately wrong stage outcomes must demonstrate the assertions detect failures.
3. Make the runner pass; add deterministic replay and malformed-input checks. Keep unsupported-answer judgments distinct from retrieval.

**Hard prerequisites:** only this design and a locally runnable test environment. **Soft ordering:** coordinate #6046/#8062 and #8245; no trace persistence or golden-set gate is needed for fixtures. Future production adapters are separate, conditional on current snapshot, authorization and trace contracts.

**Candidate seam:** verified existing `pkgs/atlas-search/crates/atlas-core/src/eval.rs` and `tests/`; prefer new isolated `tests/diagnostic_fixture.rs` instead of changing `EvalData` or shared evaluator. Proposed future done command, not yet an existing test: `cargo test --manifest-path pkgs/atlas-search/Cargo.toml -p atlas-core --test diagnostic_fixture`. No network, live corpus, credentials, or external cost.

**Risks:** an implementation that compares a function to itself proves nothing; maintain separate expected fixture data and reference procedure. Never equate unjudged with irrelevant or an incomplete snapshot with absence. This is not a production search-quality or authorization certification.
