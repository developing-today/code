# F02 — permission noninterference reference-model fixture pack

**Tier/status:** crucial; fixture work ready after this design merges, integration conditional. Parent [#6020](https://github.com/developing-today/code/issues/6020), programme [#6018](https://github.com/developing-today/code/issues/6018); [design on main](https://github.com/developing-today/code/blob/main/doc/2026-11-11T03-45-00Z_design_atlas_v2_v4/2026-11-11T03-45-00Z_design_atlas_v2_v4.md). Evidence: [baseline V1-D08/D12](../research/01-baseline-inventory.md), [architecture](../research/06-architecture-directives.md).

## Scope

Build a standalone test-only state machine modeling authorized physical selection, retrieval, resolution/hydration, cache and current-epoch revocation. Its fixture inputs are identities, caller authorization, content visibility, retained snapshot, cache entries and rights transitions. Its public projection contains only observable permitted results, ranks, counts, errors and metadata. This is not #6021's live classification scan, #8479 remediation, #6228 manifest implementation, or a production access-control mechanism.

## Failing-first steps and oracle

1. Create paired worlds with identical permitted objects but differing forbidden objects, source paths and content; write failing noninterference assertions that the low-privilege observable projection is identical, including counts, errors and metadata.
2. Build an independent reference model selecting authorized physical inputs before ranking, then authorizing resolution, hydration and every cached replay against **current** rights. Generate sequences of read, cache, reclassify/revoke and replay; check every result against the model. Seed cached formerly allowed content, revoked historical snapshot, and mixed-rights byte-identical occurrences.
3. Include deliberately insecure selection-after-ranking and stale-cache mutations that assertions reject. Restrict timing/side-channel claims to modeled observable values; don't assert constant-time execution.

**Hard prerequisites:** merged design and local fixtures only. **Soft ordering:** #3125 occurrence work, #6805 cache policy, #6228/#6993 manifest, #6021/#8479 remediation. Future integration requires verified live enforcement at each relevant serving boundary; tests alone do not prove deployed security.

**Existing candidate seams:** `pkgs/atlas-search/crates/atlas-core/src/search.rs`, `filters.rs`, `tests/`; `pkgs/atlas-search/crates/atlas-search/src/server.rs` and fleet counterpart exist. Prefer a new isolated `pkgs/atlas-search/crates/atlas-core/tests/permission_model.rs` for this slice, without changing production APIs. Future proposed done command: `cargo test --manifest-path pkgs/atlas-search/Cargo.toml -p atlas-core --test permission_model`. No live corpus, credentials, network, or external costs.

**Risks:** manifest labels are not authorization, ranking can leak hidden membership, and historical access is not present access. Fixture passes are not a certification of runtime, other surfaces, or side channels.
