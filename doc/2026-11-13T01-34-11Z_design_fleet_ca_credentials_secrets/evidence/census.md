## Baseline gaps and confidence

- **Verified missing in source:** typed canonical credential model; generic provider capability API; provider-native write/update/list adapters beyond BWS CLI fallback; OP/BW adapters in Fleet; resolver freshness contract; sync/three-way reconciliation engine; secret-operation journal; PKI/cert/generate domains; cryptographic backend/signing abstractions; SOPS/age adapter in Fleet.
- **Partial:** broker cache and single-flight exist; #6767 mitigation is merged and has source tests, but deployment/live-canary effect is unverified and outside this run's authorization. The current protocol has no caller-supplied typed class/freshness policy; redacted value wrapper exists, but no structured classification/scope/lease/freshness result type; durable creation outbox exists for GitHub records only.
- **Root-escrow activation boundary:** V1 broker refresh enumerates and caches all records accessible to its BWS credential, while the legacy BWS fallback resolves arbitrary accessible names. A future `RootPrivate` class in new typed APIs cannot protect these old paths by itself. ROOT-09/OPS-10 must prove a separate least-privileged provider grant or trusted scope/native-ID exclusion in both old paths before any root escrow copy; exact project/item permissions are not checked here and production remains blocked.
- **Not inferred:** actual BWS/OP/bw permissions, deployed versions, production vault contents, latency, provider plan limits, or whether OpenBao/fnox/SecureStore are already installed outside the inspected source. No external docs were fetched for this census; all architecture alternatives remain proposals until their source research/benchmarks are recorded.
