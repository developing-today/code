# PM stack — its own model dependencies (PM-SURVEY, 2026-11-23)

Ground truth: laptop clone `~/git/code` at `4d937b3`, greps over `pm-stack/` + `pkgs/atlas-search/` + `pkgs/pm-*` for `embedding|embed|llm|model:` and for direct LLM API calls. **Headline finding: the PM aggregator, console, dispatch, and projector make no LLM calls and no embedding calls of their own.** Every model named below is either (a) a model the stack *routes work to / measures*, (b) a model in an adjacent component that lives in `pm-stack/`, or (c) the Atlas embedding model the brief asked about, which belongs to Atlas, not to the PM stack.

## 1. Embedding models

- **PM stack proper: none.** No embedding model, embedding endpoint, or vector store is referenced in `pm-stack/aggregator/src/`, `pm-stack/console/src/`, `pm-stack/dispatch/src/`, `pm-stack/projector/src/`, or `pkgs/pm-*/`. The aggregator's `/search` (`aggregator/src/search-view.ts`) is a title/ref search over its own projections, not a vector search (per its `pages.ts` blurb: "by title or linked issue/PR ref").
- **Atlas (adjacent, `pkgs/atlas-search/`) — the pinned embedding space:**
  - Production model: **`Snowflake/snowflake-arctic-embed-m-v2.0`**, 768 dimensions — pinned in three places that agree: `pkgs/atlas-search/worker/src/space.ts` (`EMBED_MODEL = "Snowflake/snowflake-arctic-embed-m-v2.0"`, `EMBED_DIMS = 768`, #6788; `validateEmbed` refuses any `/v1/embed` response naming another model or width), `pkgs/atlas-search/atlas_search.py` (`MODEL = "Snowflake/snowflake-arctic-embed-m-v2.0"`, "at full 768 dimensions"), and the Rust staging aggregator's mandated identity `EMBEDDING_MODEL_ID` (`pkgs/atlas-search/crates/atlas-core/src/shards.rs`, used by `aggregate.rs` embed-at-promotion; the manifest of every unit DB is stamped `embedding_model`).
  - Dormant fallback (Python reference only): **`BAAI/bge-small-en-v1.5`** via fastembed, 384-dim table `vec_bge_small_384_f32` (`atlas_search.py` header: "The bge-small set remains in the publish as a dormant fallback (--model BAAI/bge-small-en-v1.5 …)"; the Atlas book calls the Python reference "the only surface that still offers the dormant bge-small fallback embedder").
  - Env override exists in the Python tool only: `ATLAS_SEARCH_MODEL` / `ATLAS_VEC_TABLE` (`atlas_search.py`).
  - The PM connection is only documentary: `pm-stack/lineage-manifest-2026-11-12.md` line 329 lists the open design question "#1518 Define code/config embeddings: unit, metadata, usage — and whether they share the prose embedding dump". No PM component consumes Atlas embeddings in the code surveyed. Any claim that the PM dashboard uses embeddings is UNVERIFIED / not supported by code.
- OpenClaw's embedding server (llama-server, port 18791 in `pm-stack/PORTS.md`) is a laptop service recorded in the port registry; it is not a PM-stack dependency (no PM code references it).

## 2. LLM calls made by PM components

- **Aggregator: none.** No `api.openai.com` / `api.anthropic.com` / Workers AI / chat-completions call exists in `aggregator/src/` (grep for provider API patterns returned only quota *accounting* for Workers AI neurons in `src/saas-extract.ts` / `sources/fixtures.ts` — measuring a bill, not calling a model). Its "adapters" (`claude-adapter.ts`, `clinepass-adapter.ts`, `token-adapter.ts`) call provider *usage* endpoints (e.g. `https://claude.ai/api/organizations/<uuid>/usage`) to read quota windows — no inference.
- **Console (local + edge): none.** No LLM call in `console/src/` or `console/edge/src/`; its summarisation-shaped surfaces (overview, questions) are projections of stored data. (Test/demo fixtures name models as data — `console/scripts/demo-state.ts` uses `model: "gpt-5.2-codex"` / `"workhorse"` as session labels; `console/test/edge.test.ts` uses `model: "muse"` — fixtures, not calls.)
- **Dispatch: no inference of its own, but it *places* inference.** `pm-stack/dispatch/` passes a caller-supplied model hint (`"provider/model"` or `{providerID, id}`, `dispatch/src/validate.ts`) to the OpenCode server when creating a session (`dispatch/src/opencode.ts`). Its README's worked example names `opencode-go/gpt-5.6-luna`. The placement guard (`dispatch/src/placement-guard.ts`) maps explicit providers to quota pools: `opencode-go.drewrypope`, `opencode-go.popesdrew`, `opencode-go.developing-today-0`, `opencode-go.0x111dev`, plus ClinePass model hints; the bare `opencode-go` provider is pinned to the active OpenCode Console account at launch.
- **Projector: none.** ("embedders" in `projector/src/server.ts` comments means *embedding applications* — hosts that embed the projector library — not vector embedders.)
- **Voice line (in `pm-stack/`, Workers AI — the only in-tree inference calls):** `pm-stack/voice-line-worker/src/session.ts` — `STT_MODEL = "@cf/openai/whisper-large-v3-turbo"` and `TTS_MODEL = "@cf/myshell-ai/melotts"`, both via `env.AI.run(...)`. The *answer* between STT and TTS is **not** an LLM: `matchIntent(transcript)` + `buildAnswer(intent, snapshot)` over a Turso queue snapshot (same file) — template answers for recognised intents (e.g. `queue_state`).
- **ready-for-agent config (a model default, not a call from this repo):** every repo in `pm-stack/ready-for-agent/config.json` sets `defaultModel: "opencode-go/kimi-k3.1-pro"`.

## 3. Models the stack measures / routes (not dependencies)

- The aggregator's AA/Cost Explorer and quota system are *about* models: `aggregator/src/aa.ts` reads the deployed OpenCode config's provider catalogs + `experimental.model_routes` (route names incl. `workhorse`, `speed`, `specialist`, `summit`, `small` — see `push.md` §3), computes route leaf sets, and joins Artificial Analysis measurements, plan seats, and per-model price bands. These are data subjects, not calls.
- Historical/load-test data in `aggregator/docs/aa-load-2026-11-12/gen_load.py` names synthetic families "Claude Sonnet 5.5" / "Claude Opus 5.5" (slugs `claude-sonnet-5-5`, `claude-opus-5-5`) — a generated load fixture, not a dependency; do not cite as a real model in the book without checking AA. Flagged here as a naming trap.
- Session records throughout (`model.ts` SessionRecord, console `Work.sessions()`) carry the *session's* model/route as a string (e.g. `workhorse`) — provenance data about fleet work, again not a PM-stack model dependency.
- Quota adapters name provider *services* (Claude, ClinePass, OpenCode Go/Zen, Open Design, Mistral as a planned exporter adopter in `exporters/README.md`) — account/usage integrations, listed in `apps.md`; none is an inference dependency of the PM stack itself.
