## DO internal routes (TransportState.fetch)
GET-ish /state, /run, /vapid; POST /subscribe, /unsubscribe, /test-push, /test-all.
Subscribe rules (webpush.js validEndpoint + index.js): endpoint must be https, no
userinfo/port, host matching fcm.googleapis.com | android.googleapis.com |
updates.push.services.mozilla.com | *.push.apple.com | *.notify.windows.com;
max 20 subscriptions (MAX_SUBS) -> 409; duplicate endpoint -> ok no-op;
test-push: unsubscribed device 404; repeat within 30s (TEST_EVERY_MS) -> 429;
push results drop endpoints the push service reports gone (404/410).

## Probe (probeBroker in index.js)
GET {BROKER_URL}/healthz with headers CF-Access-Client-Id: ACCESS_CLIENT_ID,
CF-Access-Client-Secret: ACCESS_CLIENT_SECRET, redirect: "manual",
AbortSignal.timeout(PROBE_TIMEOUT_MS, default 10000).
Missing Access secrets -> { ok: true, skipped: "Access service token not configured" }
and run() logs event "skipped" without alerting.
classifyHealthz (logic.js): healthy only on HTTP 200 with JSON body ok === true.
Failure detail hints: 301/302/303/307/401/403 -> "(Cloudflare Access refused the
probe's service token, or it is unset)"; 502/503/504/530 -> "(the tunnel could not
reach the broker)"; timeout -> "no response from <url> within the probe timeout".

## Alert state machine (logic.js step + run.js runPass)
State: consecutive_failures, window_start, last_failure_detail, alerted, incident,
incident_filed_by_probe, alert_notified, recovery_notified, last_ok, last_probe,
last_outage {start,end,incident}, pending [] (cap MAX_PENDING 20).
THRESHOLD (default 2) consecutive failures -> one "alert" event per outage window:
GitHub find open issue titled with prefix "Queue transport incident:" (search API,
per_page 20) -> comment on it, else file new issue titled
"Queue transport incident: repo-queue broker unreachable since <window_start>"
with labels kind/bug, priority/high, area/infra, source/fleet-monitor (INCIDENT_LABELS).
GitHub write failure -> window left un-alerted (alerted reset false), next tick retries.
First passing probe after an alerted window -> "recovered": one GitHub comment,
NEVER a close (no close() method exists in github.js; rule #10136), then
finishRecovery records last_outage. Below-threshold windows end quietly.
Side effects ride state.pending and retry on later ticks: Telegram notify,
Web Push, and (recovery only) the broker enqueue.
APPLY != "true" or missing GITHUB_TOKEN -> github client null (log-only/observe mode);
same gating for Telegram (TELEGRAM_BOT_TOKEN + TELEGRAM_CHAT_ID) and enqueue
(BROKER_AGENT_TOKEN + QUEUE).

## Recovery queue task (queue.js makeBrokerEnqueuer / buildOutagePacket)
POST {BROKER_URL}/enqueue, headers X-Agent-Token: BROKER_AGENT_TOKEN +
CF-Access-Client-Id/Secret, 15s timeout. Packet: repo-task/v1, kind "triage",
queue = QUEUE var (repo-health-code-pilot), priority 20,
dedupe_key "repo-health:v1:triage:<repo>:issue:<N>"; a dedupe/duplicate/already
error from the broker counts as success. Never attempted while probe is failing
(item stays in pending).

## Status JSON fields (status.js publicStatus)
service ("queue-broker"), status (up|degraded|down|stale|unknown; stale = no probe
in 25 min = STALE_AFTER_MS, >2 missed ticks), up (true|false|null), last_check,
last_ok, failing_since, consecutive_failures, last_failure, incident {number,url}|null,
last_outage {start,end,duration,incident}|null, last_push, pending_deliveries
(pending item types), last_errors, probe, cadence_minutes (10),
alert_after_failures, issue_title_prefix, source. No secrets.

--deploy-version <id>] — cf versions flow: versions create --tag git-<sha12>
(secrets via --secrets-file <(cat) pipe) -> deployments create at 100% ->

QTA_WORKER_PRODUCTION_ACCOUNT_ID. No automatic rollback in the workflow.

also run in the flake package checkPhase.
