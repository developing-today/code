## Transport (fleet-dispatch-test/src/lib.rs, "Turso jobs store" section ~line 714)
POST {turso_url}/v2/pipeline, hrana-over-HTTP v2 shape: one execute + one close
request per call; Authorization: Bearer <redacted> (token resolved BY NAME through
fleet-secrets, enters exactly one Authorization header per request, never printed/
logged/stored). Args are typed cells: text / integer (encoded as JSON string) / null.
Failure shapes: non-2xx -> Http error (exit 4) with first 300 chars of body;
top-level {"error": ...} or results[i].type != "ok" -> Transport error (exit 3),
never an empty result; non-JSON body -> Transport error.

## Schema — as the code knows it
Full column list (book + status SELECT agree):
id, created_at, name, target_repo, target_ref, script, status, run_id, run_url,
exit_code, output_tail, updated_at, submodule, commands   (14 columns, all TEXT-shaped
in use; id is the primary key by usage — no DDL in repo states it).
NO "CREATE TABLE jobs" exists anywhere in the searched repo paths
(pkgs/fleet, pkgs/pm-dispatch, pm-stack/dispatch, home/, pkgs/fleet/migrations/).
pkgs/fleet/migrations/* are the fleet-queue database's migrations, not this DB's.
The only DDL the crate runs is the idempotent phase-2 migration, in ensure_schema(),
called by verb_submit and verb_status (NOT by verb_scan, which never opens the store):
  ALTER TABLE jobs ADD COLUMN submodule TEXT
  ALTER TABLE jobs ADD COLUMN commands TEXT
A "duplicate column" error from either is treated as already-migrated and ignored.

## Job id + lifecycle
id: `dt-<unix_millis base36>-<4 hex chars from /dev/urandom>` (generate_job_id).
Lifecycle: queued (client INSERT) -> dispatched (client, after dispatch POST) ->
running (workflow, with run_id/run_url) -> terminal status + exit_code/output_tail
(workflow write-back).
Exit codes (crate): 0 ok, 2 usage, 3 transport down / credentials unresolved /
no eligible scope, 4 HTTP error status from GitHub or Turso (incl. unknown job id).
Verbs: scan (GitHub-only; never opens Turso), submit, status. Nothing trigger-driven.
