## 1. Stated purpose

### 1.1 The product as it presents itself today

- `pkgs/id/README.md` (verified, contents API): "**id** — A peer-to-peer file sharing CLI built with [Iroh](https://iroh.computer). Store, retrieve, and share files across a decentralized network with optional collaborative web editing." Features listed: P2P file sharing over content-addressed hashes, named tags, metadata tags with structured search, remote operations by node ID, collaborative editor (WebSocket web UI), interactive REPL, peer discovery, content modes (text/markdown/images/video/audio/PDF), themes.
- `pkgs/id/ARCHITECTURE.md` (verified): layers CLI / REPL / Web UI over a command layer (`put · get · find · list · cat · show · peek · search · tag · serve · repl · peers · id`) over core services (Protocol P2P RPC, Store/blobs, TagStore, Discovery mDNS/DHT) over the Iroh runtime (blobs, docs/CRDT, gossip, QUIC, hole punching, relays).
- The README also documents the **#9106 walking skeleton** (`id walk`): one signed record at an `id://` address, held in a node's on-disk store, synced to a second node over the federation exchange protocol, a conflicting write, a conflict report on both nodes, and a resolution — plus a stated "client-only boundary": remote/`id world …` commands are clients; hosting begins only through explicit `id serve`; "reaching a node is not world authority: a valid world capability is still required."
