# Design: F12.13 Phase 5 replica operations and admission

- Date: 2026-11-05
- Status: implementation design for issue [#806](https://github.com/developing-today/code/issues/806), Phase 5
- Prior design: [2026-11-01_design_id806.md](../../2026-11-01_design_id806.md)

## Decision update: offline admission is Policy B

The 2026-11-01 design's §8 lists A/B/C as an unresolved choice. That is now superseded: #806 explicitly adopted **Policy B, a writer-signed admission lease** ([decision comment](https://github.com/developing-today/code/issues/806#issuecomment-6634842315)). Do not reopen the A/B/C choice during implementation.

A replica admits a **new** spectator session only when it has a valid lease signed by its explicitly pinned writer. The signed lease is bound to the world, source identity, and a verified journal cursor; it has a finite validity window. The replica verifies signature, signer, domain/version, world, cursor ancestry, and expiry before using it. It never grants participant/write/admin scope. Lease absence, expiry, bad signature, or mismatched binding denies new spectator admission. An outage or expiry does not invalidate already verified spectator sessions or local reads: those continue against the last complete replica state and expose its staleness. A reconnect may refresh the lease only after the replica verifies the corresponding source data and cursor.

## Phase 5 shape

Build on the merged wire, writer-feed, durable-receiver, and read-only restore primitives. Keep the existing journal as source of truth and the existing records-only id world mirror / world_records behavior unchanged.

1. **Follow and serve operations.** Add an id world follow operation that follows the selected world from an explicitly pinned source into the durable replica store, using the existing signed protocol and receiver verification. Add an id world serve replica mode that opens only a verified durable replica, serves the existing spectator/world read protocol locally, and never opens the writer mutation path. Restart must recover the last committed cursor and continue serving it while the writer is unavailable.
2. **Cursor-bound refreshes.** Refresh active module bytes and only the directory facts needed for authorization through authenticated source messages. Each refresh carries the pinned source and world and is bound to a verified cursor; validate the module against the active journal module hash and validate the directory payload and cursor before atomically replacing durable replica facts. A partial, stale, mismatched, or unauthenticated refresh must not replace the last complete values. These facts remain auxiliary to the journal, not an alternate authority.
3. **Admission lease.** Obtain/refresh the writer-signed Policy B lease through the authenticated replication path. Persist it only after verification and admit new spectator sessions only while it is valid and compatible with the current verified chain. Expiry gates new session creation, not reads on existing verified sessions or local replica serving at the last cursor.
4. **Status.** Report pinned source, world ID, verified cursor, and cursor time / staleness in follow/serve status so users can distinguish a current replica from an offline one. Never imply freshness beyond the verified cursor.
5. **Acceptance coverage.** Exercise disconnect, writer and replica restart, reconnect, compaction reset, and lease expiry/refresh through public operation seams. Assert the last complete replica remains usable on outage/interruption, new spectator admission fails without a valid lease, existing verified sessions and read serving survive lease expiry, and reconnect converges.

## Boundaries

- Do not change world_records or the records-only mirror command.
- Do not weaken existing replication signature, source pinning, cursor, module, journal-version, or read-only-world checks.
- A failed refresh or incomplete stream leaves the previous verified cursor and its usable replica intact.
- Do not claim phase acceptance for behavior that lacks an end-to-end or public-seam test; record any implementation blocker precisely.

## 2026-11-05T02-32-14Z Deviation: implementation boundary

This work adds the pinned-source durable journal follower and a durable status
sidecar/CLI that reports the source, world, committed cursor, and elapsed
staleness. The follower reconnects after transport interruption and writes
status only after the receiver commits a signed terminal frame.

The remaining Phase 5 acceptance is not complete. The writer replication feed
still carries journal frames only; it has no authenticated, cursor-bound active
module and directory-fact refresh. There is also no writer-signed Policy B
admission lease or session admission gate. Therefore this change does not add a
replica-serving CLI: wiring the existing world protocol directly to an offline
replica would admit new sessions without the adopted lease and would be unsafe.
The network reconnect/status behavior added here has not been exercised by an
acceptance test in this sandbox. Existing phase 1-4 receiver/restore coverage
does not substitute for those missing Phase 5 checks.
