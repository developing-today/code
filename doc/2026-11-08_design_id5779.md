# Design: deterministic testing for ID across time, replay, corpus, and soak

- Date: 2026-11-08
- Status: **Decision-ready proposal** — design only; implementation is a separate follow-on.
- Issue: [#5779](https://github.com/developing-today/code/issues/5779), under epic [#2056](https://github.com/developing-today/code/issues/2056).
- Related: [#558](https://github.com/developing-today/code/issues/558) (authoring/dev-loop fuzz and fixture replay), [#544](https://github.com/developing-today/code/issues/544) (`id world verify`, closed), [#5685](https://github.com/developing-today/code/issues/5685) (DoS/performance programme), [#2898](https://github.com/developing-today/code/issues/2898) (reconstruction is admission), [#2819](https://github.com/developing-today/code/issues/2819) (lease epoch fencing), [#5545](https://github.com/developing-today/code/issues/5545) (writer-set projection purity, closed), and [#3447](https://github.com/developing-today/code/issues/3447) (crate split).
- Evidence checked against `origin/main` at `e5a4fdcbcb3f90b6552009420d900151454d9103`.

## Decision summary

Build one deterministic test programme around the **world transition boundary**: an initial state plus an ordered stream of explicit guest inputs and recorded host results must produce the same journal and derived state on every replay. Reuse the current world clock, seeded guest initialization, fixture format, replay verifier, and regression cases. Add only the missing controls and oracles; do not create a second fixture system or make all production I/O virtual.

1. Keep `Clock` as the world runtime's source of domain time. Route the `time.now` capability through it, and make other decision-bearing core functions take explicit time (or a narrow injected clock) where elapsed time affects their result. Keep network deadlines, process scheduling, and operational logging real; capture any external outcome that affects world state as an input event.
2. Make replay verification exact and stepwise: compare a versioned, canonical, domain-separated digest of each journal event and its resulting records, then report the first differing sequence. The existing fixture verifier remains the entry point and its current fixture version remains readable.
3. Promote minimized, fixed-seed failures into a reviewed, append-only, versioned corpus. Production cryptographic entropy is never replaced with a test PRNG.
4. Run bounded deterministic checks on every PR, a larger corpus/replay suite nightly, and longer simulated-time soaks on a slower schedule. Reuse #5685's workload driver and result/reporting machinery, but keep determinism and performance as distinct oracles.

## Scope and non-goals

This design covers reproducible tests for ID's event-sourced world and its time-dependent control-plane decisions. It does not implement those tests, change the production journal protocol, reimplement #558's dev-loop fuzzing or #544's replay self-check, or absorb #5685's denial-of-service and latency programme.

The deterministic contract applies to the world state transition and to inputs that cross into it. It does not claim that a live network, OS scheduler, wall clock, random source, or production machine is deterministic. When one of those sources changes a durable or guest-visible result, the exact observed result must either be journaled as an authorized host event or supplied as a controlled test input.

## Existing systems and boundaries

The guest sandbox is intentionally narrow: it exposes no clock, random source, filesystem, sockets, or WASI imports (`pkgs/id/src/sandbox.rs:1-11`); initialization takes an explicit seed. This is a strong base and remains the rule for guest modules.

| Existing component | What it provides | Boundary or gap this design addresses |
|---|---|---|
| `Clock`, `SystemClock`, `ManualClock` (`pkgs/id/src/world/clock.rs:12-83`) | Separate epoch-millisecond and monotonic faces; tests can advance time without sleeping. `WorldCore` owns the clock (`world/core.rs:137-145`). | Advancing `ManualClock` does not wake the actor's Tokio `sleep_until` (`world/actor.rs:455-460`). Direct actor-method tests are controllable; actor-loop tests need a coordinated wake/timer driver. |
| Actor schedule/tick handling (`world/actor.rs:468-486, 791-807, 822-831`) | Due-time decisions and tick payloads use the world clock. | The `time.now` capability currently calls `unix_ms()` directly, rather than the injected clock (`world/actor.rs:872`). |
| Host capabilities (`world/actor.rs:613-652, 871-874`) | Capability outcomes, ticks, and presence are delivered as `System` events; `random.u64` currently draws from `rand::rng()`. | Replay must consume the recorded capability result, never call the live clock or RNG again. The capability implementation should share the world's clock so one test control governs all world time decisions. |
| World fixtures (`pkgs/id/src/world_fixture.rs:71-75, 118-125`) | JSONL history with ordered events; a fixture records module/history metadata, not capabilities or module bytes. Admin-authorized exports can include system events. `verify` replays twice with the supplied seed and compares records stepwise (`:402-429`). | The current verifier's primary oracle is records equality; this design adds an exact journal digest and explicit divergence artifact without changing who may export history. |
| Regression inputs (`pkgs/id/tests/regressions/README.md`) | Fixed regression corpus is replayed by tests and grows when failures are minimized. | Broader generated world traces need schema/version metadata, seed provenance, size policy, and a controlled promotion path. Existing files are not deleted when a bug is fixed. |
| `id-core` time and discovery | `time::unix_ms()` reads `SystemTime` directly (`pkgs/id/crates/id-core/src/time.rs:6-11`); `PeerDiscovery` reads wall time and `Instant` for freshness/arrival decisions (`discovery.rs:448-500, 533-620`). `WaitingPool` already accepts `now_ms` explicitly. | Make pure, decision-bearing transitions controllable without making every transport timeout or liveness check use a global simulated clock. |

The fixture design for #544 already calls for stepwise double replay and first-divergence reporting. Its guarantee is intentionally limited to “this recorded fixture replays deterministically”; it does not prove unrecorded live behavior. #558 already recommends fixture-gated candidate checks and bounded seeded fuzzing, and keeps broad fuzzing out of latency-critical loops. This design composes with both rather than duplicating them.

## 1. Nondeterminism audit and policy

The audit is an implementation deliverable, not a claim that every use of a clock or collection is a bug. Each source is classified by whether it can affect a durable or guest-visible transition.

| Source | Deterministic-test rule |
|---|---|
| Wall clock and monotonic time | Persisted decisions use logical epoch time supplied through `Clock` or explicit `now` arguments. Monotonic time is for local deadlines only and is never serialized. Tests advance logical time directly. |
| Randomness | Guest initialization and test generators use explicit, versioned seeds. A production host capability that returns randomness remains nondeterministic; its returned value is an input event and replay consumes that recorded value. Do not make key generation, nonces, or other security-sensitive entropy deterministic. |
| Tokio wakeups, thread scheduling, task ordering | Durable event order is the journal order, not observed wall time or which task happened to run first. Unit/model tests control actor events and timer advancement. Real concurrency and scheduling remain integration/stress-test concerns; a race that changes valid journal output must be represented by an explicit ordering/input in the deterministic case. |
| Network, filesystem, environment, and external services | The deterministic harness injects adapter outcomes, not sockets or the host filesystem. An external result that changes state is recorded as an event. Separate integration tests continue to exercise real adapters with bounded real deadlines. |
| Hash-map iteration and serialization | Any ordering that reaches a digest, event, or externally compared output must be canonical. Sort map keys in the test encoder; preserve array and journal order. No oracle may depend on hash-table iteration order. |
| Floating point, compiler, target, runtime version | The case manifest pins the guest/module hash and oracle version. Prefer integer/fixed-point state for durable rules. If floating-point behavior becomes state-bearing, either define and test the supported target/toolchain matrix or remove the platform-dependent operation; do not silently promise cross-platform identity. |
| Logging, CLI output, test deadlines | These are outside the state oracle unless the output itself is part of an event. They may use real time. Test deadlines detect a hung test; they are not simulated world time. |

The audit should enumerate direct uses of `SystemTime`, `Instant`, `tokio::time`, RNG APIs, ambient environment, unordered collections, and external I/O at the `id-core` / `id` / native-shell seams. For each use, record: owner, whether it affects durable or guest-visible state, the intended control (explicit input, recorded event, deterministic derivation, or intentionally real adapter), and a test proving that boundary. Re-run the audit when a crate seam moves under #3447.

## 2. Clock and event-input seams

### World time

`Clock` stays the canonical source for world-domain time. `SystemClock` remains the production implementation; `ManualClock` remains the unit-test implementation. The `time.now` host capability should read `core.clock().now_ms()` rather than a separate `unix_ms()` call. Its result is still journaled as a `System` event, so an offline replay consumes the recorded value rather than consulting a clock.

Keep the two clock faces distinct:

- `now_ms` is the domain time used for schedules, expiries, and timestamped world decisions. It may be recorded or compared in a deterministic case.
- monotonic `Instant` is for local waiting/deadline calculations. It must not enter persisted state, fixtures, or a journal digest.

For pure `id-core` transitions, prefer an explicit `now_ms` (as `WaitingPool` already does) when a call only needs a timestamp. Introduce an injected clock at a core boundary only when the object itself must make multiple clock decisions. `PeerDiscovery` is such a candidate for deterministic freshness tests, but its live network arrival and retry deadlines remain real adapter behavior; a test supplies arrival times and outcomes explicitly.

The actor loop needs one narrow test-time driver that advances `ManualClock` **and** wakes its wait loop. It may use Tokio's paused-time support or a test-only wake abstraction, but it must not require a production dependency from `id-core` on Tokio. Direct actor-method tests may continue to call `fire_ticks` and `fire_schedules` after advancing the clock. An end-to-end actor test must exercise the same scheduling decision while preventing a real-time sleep from becoming its clock oracle.

### Host inputs and seeds

All guest-visible host outcomes are replay inputs. System events already cover presence, capability results, and ticks. A deterministic case captures their exact ordered values. If a host result contains secret material, it is not suitable for a checked-in fixture: test with a synthetic value or a redacted adapter that preserves the relevant state transition. Never export credentials or live capability tokens into the corpus.

Use deterministic PRNG seeds only for test generation and guest initialization where the guest contract already accepts a seed. Record the PRNG algorithm and generator version as well as the seed; changing either must not reinterpret old corpus entries. Do not mock production randomness globally—this would make tests pass under a security posture production does not have.

## 3. Replay artifact and exact oracle

### Inputs

Reuse the current world-fixture JSONL as the ordered event stream. Add a **test-side manifest**, separate from the production fixture header, with at least:

```json
{
  "schema": "id-determinism-case/v1",
  "fixture": "cases/<case-id>.jsonl",
  "fixture_version": 1,
  "module_hash": "<hash-or-null>",
  "initial_seed": { "algorithm": "<pinned-algorithm>", "value": "<seed>" },
  "generator": { "name": "<generator>", "version": 1 },
  "oracle_version": 1,
  "expected": {
    "step_digests": "cases/<case-id>.digests.jsonl",
    "final_journal_digest": "<digest>",
    "final_records_digest": "<digest>"
  }
}
```

The fixture is the exact ordered input, including authorized system events; the manifest records how a generated case was made and the expected digest. A complete fixture starts at sequence one. A partial fixture must name and pin its initial snapshot/base digest. The manifest never embeds module bytes, join capabilities, production secrets, or a live random source. The module hash and fixture/schema versions are compatibility identity, not an assertion that every platform's binary is identical.

### Oracle

For each fresh replay, compute two versioned digests after each committed event. The test oracle is sidecar-only; it does not change the production journal protocol:

1. **Journal digest:** for a complete fixture, set `H₀ = BLAKE3("id-world-journal/v1\0genesis")`; for a partial fixture, set `H₀ = BLAKE3("id-world-journal/v1\0snapshot\0" || base_snapshot_digest)`. For each event `i`, set `Hᵢ = BLAKE3("id-world-journal/v1\0" || Hᵢ₋₁ || u64be(sequence) || u32be(kind_length) || kind_utf8 || u64be(payload_length) || canonical_payload)`. `canonical_payload` is RFC 8785 canonical JSON; arrays retain order, object keys are canonicalized, and non-finite or out-of-range numbers are rejected or represented by an explicit tagged string. This defines the exact byte sequence and preserves journal order.
2. **Records digest:** `Rᵢ = BLAKE3("id-world-records/v1\0" || u64be(sequence) || canonical_records)`, where `canonical_records` uses the same RFC 8785 rules. This identifies state/projection divergence even when the recorded event stream is the same.

Store one `(sequence, journal_digest, records_digest)` row per committed event in the manifest's digest sidecar. Run the same case twice from fresh world instances with the same module, initial state, and test seed. Require both executions to match every sidecar row and each other, not only the final digest. A mismatch fails at the first sequence whose expected digest differs and reports: case ID, fixture/module/oracle versions, seed and generator version (when safe), expected/actual rolling digests, the event kind, and a bounded structural diff of the records. Preserve the exact fixture, digest sidecar, and seed so the report can be replayed without the original fuzz run. Ephemeral generated traces need no checked-in sidecar; compare their two fresh executions stepwise and retain the trace if they diverge.

The digest proves reproducibility of the recorded case, not correctness of the expected state, production security, or behavior outside the recorded input. Correctness remains grounded in the named invariants and transition/model oracles below. Version the encoder and oracle; never rewrite old expected values merely to make a changed implementation green. An intentional behavior change updates the case with a rationale and a reviewable before/after diff.

## 4. Seed corpus lifecycle

Keep existing narrow text regressions in `pkgs/id/tests/regressions/`; add world-level deterministic cases in a dedicated location such as `pkgs/id/tests/determinism/corpus/v1/`. Each entry consists of the replay fixture plus a small manifest. Keep the case human-reviewable and minimize it before promotion.

Promotion of a failure follows this sequence:

1. Record the exact failing generator version, seed, module hash, and event trace in the test output or CI artifact.
2. Re-run the failure from a fresh process to distinguish a deterministic counterexample from a harness problem. A failure that disappears on a retry is still a failure to investigate, not a green result.
3. Minimize the event stream while preserving the named invariant failure and the first-divergence sequence. Keep the minimized case; retain the original seed/provenance in the manifest or its review note.
4. Add the fixture, manifest, per-step digest sidecar, and a regression assertion in one PR. Review the new input and expected digests as code. Do not admit secrets or production tokens.
5. Keep promoted cases permanently. Fixing the bug never deletes the case. If the case no longer applies after a protocol version change, mark it superseded with a link and retain its bytes and history.

Corpus growth is by reproduced failure or an explicitly reviewed scenario that covers a named invariant. Minimize large traces; do not check in every random successful run. Scheduled fuzz may generate ephemeral cases, but only reviewed, minimized inputs become the durable corpus.

## 5. Simulated-time soaks and invariants

Soaks run the real deterministic transition logic against a controlled driver. Advance directly to the next scheduled deadline or generated event instead of sleeping for each simulated millisecond. A “day” of simulated time must not mean 86,400 real seconds. The driver retains the same event ordering, tick handling, and state transitions used by production; it may compress elapsed time, not skip transitions or invariants.

Check invariants after every journal append, replay step, timer transition, and modeled external outcome. Start with:

- **Admission/reconstruction:** every admitted recovered state equals the authorized journal prefix and rejects malformed authority-bearing inputs (#2898).
- **Fencing:** lease epochs are monotonic; at most one writer is authoritative at a time; a stale epoch cannot append accepted state (#2819).
- **Projection purity:** the same writer-set/event tuple produces byte-identical canonical projection output (#5545).
- **Replay:** a saved event prefix reconstructs the same journal and records digests; reordering or omission is detected at the first affected sequence.
- **Bounds:** discovery and admission state stay within configured limits; expiry, cleanup, and reconnection do not resurrect an expired or fenced entry.

Generate lifecycle sequences from a small model: create/open, install, input, tick, capability result, disconnect/reconnect, lease/failover where applicable, and recovery. Each transition has a model oracle or invariant; a final digest alone is not an adequate soak oracle.

Initial resource envelopes are targets to validate on CI, not measured performance claims:

| Lane | Work | Initial budget |
|---|---|---|
| PR | Run all pinned corpus cases twice; add up to 100 fixed-seed generated traces capped at 1,000 transitions each. Emit first-divergence diagnostics. | Target ≤3 minutes for the deterministic suite; cap work by transitions as well as wall time. |
| Nightly | Full corpus plus 10 seeds per scenario, up to 100,000 transitions per seed, with continuous invariants and artifact retention on failure. | Target ≤15 minutes. |
| Weekly/slow | Multi-world, failover, reconnect, and fairness scenarios over up to 30 simulated days, capped at 10 million transitions per scenario. | Target ≤60 minutes; stop at the event cap and report coverage, never silently truncate as a pass. |

Measure these budgets on the supported CI runner during implementation. If the PR target is exceeded, reduce generated work or move it to the nightly lane—do not remove pinned regressions or turn a deterministic check into a flaky wall-clock test. Every run reports simulated duration, transition count, scenario/seed, real duration, and the terminal invariant result.

## 6. CI split and relationship to #5685

**PR-required deterministic gate:** run the complete minimized corpus, verify each case in two fresh instances (and, for the harness boundary, at least one subprocess path), compare every step's journal/records digests, and run the bounded fixed-seed traces. This is a correctness gate, not a latency benchmark.

**Nightly:** run the full corpus, more generator seeds, medium soaks, and the controllable clock/discovery/actor-wakeup cases. Retain failure artifacts with seeds and traces. **Weekly/slow:** run the longer multi-world, failover, and reconnect soaks and #5685's abuse/performance scenarios under the same load limits so they do not compete unpredictably for CI capacity.

Share #5685's scenario/workload driver, setup/teardown, metrics envelope, and regression-report format where useful. Keep separate decisions and oracles:

- deterministic programme: same inputs produce the same versioned journal and records digests, and model invariants hold;
- performance/DoS programme: latency, resource use, admission bounds, and adversarial workload behavior stay within measured thresholds.

A performance change must not update a determinism digest just because the benchmark changed; a deterministic case must not claim a p99 or abuse-resistance guarantee. Put the long runs on a separate scheduled lane and reserve a per-run resource cap so #5685 and replay/soak tests cannot make PR checks contend without limit.

## 7. Staged implementation

1. **Audit and boundary tests.** Inventory ambient time, entropy, scheduling, unordered output, and external outcomes across `id-core`, `id`, and native adapters. Add tests for the current explicit-input/recorded-event contract before changing seams.
2. **Coherent world time.** Route `time.now` through `Clock`; provide an actor test driver that wakes Tokio waits when manual time advances. For discovery and other pure core transitions, prefer explicit time arguments or a narrow injected source; leave real transport deadlines real.
3. **Replay oracle.** Add the canonical rolling journal/records digests and first-divergence report around the existing fixture verifier. Version the test manifest and prove old fixtures still read.
4. **Corpus.** Add manifest-backed minimized cases and the append-only promotion workflow. Include a seeded failure from each core transition family as the first corpus set; do not import unrelated fuzz output wholesale.
5. **Soak/CI.** Add the model-driven accelerated-time driver, continuous invariants, and PR/nightly/weekly budgets. Reuse #5685's shared workload tooling without merging its performance oracle into the determinism check.

Each stage should be a separate implementation task/PR with its own tests and owned files. The corpus schema and clock/wakeup seam are shared interfaces, so settle them before parallelizing consumer test suites. The exact transition families and CI event caps may be tuned only after a baseline run; the staged defaults above apply until then.

## Alternatives considered

| Alternative | Decision |
|---|---|
| Make every timer, network operation, and process wait use one global simulated clock. | Reject for v1. It couples `id-core`, Tokio, and live adapters, while network liveness must remain tied to real outcomes. Use a narrow test driver and explicit adapter inputs. |
| Test only with real time and retry flaky failures. | Reject. It is slow, irreproducible, and can hide a race; real-time integration remains useful but is not the deterministic oracle. |
| Keep only per-feature property tests and no durable corpus. | Reject. A minimized failure must survive the generator run and prevent regressions. Existing property tests remain, and discovered counterexamples are promoted. |
| Replace production randomness with a deterministic PRNG for easy replay. | Reject. Seeded generation belongs to tests; production entropy is either an explicit recorded result or an intentionally external boundary. |
| Make #5685 own all soak tests. | Reject. Reuse its load machinery, but deterministic replay and performance have distinct outcomes and should be independently diagnosable. |

## Risks and open questions

- **Journal canonicalization:** implementation must confirm whether the current journal already has a stable canonical byte representation. If not, the test encoder must be specified and versioned before golden digests are added; it must not accidentally become a new production protocol.
- **Actor time versus Tokio time:** `ManualClock` advancement currently does not wake the real actor wait. Choose paused Tokio time or a test-only wake driver in stage 2, and prove that no real deadline is the test oracle.
- **Core discovery scope:** `PeerDiscovery` uses wall and monotonic time; decide during the audit which freshness transitions are deterministic core behavior and which are real adapter liveness. The default is explicit time for pure freshness transitions, real time for network waits.
- **Partial history and private inputs:** fixtures may be partial and system-event exports require authorization. The manifest must pin the base snapshot digest, and checked-in cases must use synthetic, non-secret inputs.
- **Cross-target reproducibility:** start with one pinned toolchain/target for exact digests. Add a target matrix only when a requirement exists and the canonical encoding/runtime behavior is portable; never treat platform variation as a flaky retry.
- **Budget calibration:** the transition caps and wall targets are initial ceilings. Record the CI baseline before enforcing the slow lanes; reduce generated volume if necessary, not coverage of the permanent corpus.
- **Document placement:** this file follows the established ID issue-linked record pattern (`doc/YYYY-MM-DD_design_id<issue>.md`, e.g. #558 and #5787) rather than the newer general-purpose folder-based dated-record pattern. This is intentional for discoverability beside other ID designs.
