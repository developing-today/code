# Discovery services for `id` on iroh 1.3.0

**Answer.** Make n0's pkarr and DNS the default, since the N0 preset publishes only your relay URL. Keep the mainline DHT and a self-hosted Worker relay opt-in, and leave mDNS off because it publishes every IP to the LAN. Two surprises: pkarr HTTP has no timeout, so an ID-only `connect()` can hang on a stalled relay; and the DHT dependency is `n0-mainline`, not the `mainline` crate. Nothing was compiled; [inferred] marks deductions, other claims are [read].

| Service | Default | Privacy cost | Switch | Notes |
|---|---|---|---|---|
| n0 pkarr publish + resolve | On (`presets::N0`) | n0 learns ID↔relay, your IP, each ID you dial | `presets::Minimal`, `.clear_address_lookup()`; or `PkarrPublisher::builder(url)` | Relay-only publish; republish every 5 min |

| Worker pkarr relay | Off | Host sees what n0 sees | Relay URL | Durable Objects, not KV |
| Mainline DHT | Off | Public per-key record, hourly refresh; DHT nodes see your IP | `.address_lookup(DhtAddressLookup::builder())`; `.no_publish()` | Relay-only by default; bootstrap replaceable |
| mDNS | Off (not in N0) | LAN hosts learn ID and all IPs | Omit; `.advertise(false)`; `.addr_filter(AddrFilter::relay_only())` | IPv4 multicast TTL 16 |

Paths are `<crate>/src/…` under `/tmp/research-disc/src/<crate>-<ver>/<crate>-<ver>/`. Short names: `iroh` = iroh-1.3.0; `lookup-dht` = iroh-mainline-address-lookup-0.6.0; `lookup-mdns` = iroh-mdns-address-lookup-0.6.0. Line refs are in `notes/findings.md`.

**(a) pkarr/DNS.** Publish filter defaults to relay-only (`iroh/src/address_lookup/pkarr.rs:168`). The record is a signed pkarr packet: pubkey, ed25519 signature over `3:seqi<µs>e1:v<len>:<packet>`, µs timestamp, and a ≤1000-byte DNS packet of `_iroh` TXT attributes (`iroh-dns/src/pkarr.rs:17-30, 291-295`). It is HTTP PUT to `dns.iroh.link/pkarr/<z32>` on change and every 5 min; failures retry after 1, 2, 3… s, uncapped (`iroh/src/address_lookup/pkarr.rs:146, 389, 657-682`). DNS answers `TXT _iroh.<z32>.dns.iroh.link`. Custom relay: `PkarrPublisher::builder(url)`, `PkarrResolver::builder(url)` (`pkarr.rs:290, 507`). Custom DNS: `DnsAddressLookup::builder(origin).dns_resolver(…)` (`iroh-dns/src/dns.rs:420, 762`).

**(b) Mainline.** `lookup-dht` 0.6.0 is the latest release. Builder: `secret_key`, `dht_builder`, `ttl`, `republish_delay`, `no_publish`, `addr_filter`, `build` (`src/lib.rs:152-243`). Passed to `Endpoint::builder().address_lookup(...)`, it takes the endpoint key (`lib.rs:245-251`). Storage: BEP 44 mutable item; `k` = pubkey, no salt, `seq` = µs timestamp, `v` = DNS packet, `sig` = pkarr signature (`lib.rs:44-52`). Relay-only by default (`lib.rs:169`). Put without CAS on change, then hourly (`lib.rs:34, 295`); a failed put is not retried until the next tick or change (`lib.rs:294-311`). Bootstrap: `DhtBuilder::bootstrap(&[..])` replaces the list (`n0-mainline/src/dht.rs:74-97`); defaults include `relay.pkarr.org`, which is not n0 (`n0-mainline/src/actor/config.rs:3-8`). Testnet: `n0_mainline::Testnet::new(n)` (`n0-mainline/src/lib.rs:27`), passed as `DhtBuilder::bootstrap(&t.bootstrap)` (`lookup-dht/src/lib.rs:376-378`). The crate's DHT test is `#[ignore = "flaky"]` (`lib.rs:371`). Reliability: 500 ms RTT floor (`n0-mainline/src/actor/socket.rs:26`); storage is an LRU of 1000 items with no timer (`n0-mainline/src/core/server.rs:138`); BEP 44 allows 2 h expiry, hence hourly refresh. No latency figures in the sources. Visibility: storage nodes see the publisher's UDP address and record; lookup nodes see the requester's address and target hash [inferred]. Anyone can `get` by key [read, BEP 44]. BEP 42 responses echo your external `ip` [read].

**(c) mDNS.** `lookup-mdns` 0.6.0 on swarm-discovery 0.6.1. IPv4 group 224.0.0.251 with multicast TTL 16 (`swarm-discovery/src/socket.rs:12-14, 146`), so it is not strictly link-local [inferred]. Defaults `advertise(true)` and an identity filter publish every IP (`lookup-mdns/src/lib.rs:169-173`; `iroh-dns/src/endpoint_info.rs:242-283`). It announces endpoint ID, IP:port, first relay and user data. A resolve for an unknown ID stays open up to 10 s (`lib.rs:95`). Not in N0 (`iroh/src/endpoint/presets.rs:116-137`).

**(d) Worker.** A Worker can serve as the pkarr relay: PUT/GET `/<z32>` (`iroh/src/address_lookup/pkarr.rs:620-666`). Verify with WebCrypto Ed25519, which Workers supports. Use a Durable Object per key: KV allows one write per second per key and can lag 60 s; DO storage is strongly consistent (Cloudflare docs). The reference server returns 204 on stale packets (`iroh-dns-server/src/http/pkarr.rs:14-35`); the pkarr spec says 409; iroh accepts only 2xx, so 204 is safer [inferred]. Rate-limit per IP, as the reference does (`iroh-dns-server/src/http/rate_limiting.rs:59-64`). DoH works: `NameserverConfig::https(ip).with_tls_server_name(host)` POSTs `application/dns-message` to `https://host:443/dns-query` (`iroh-dns/src/dns.rs:309-345`; `n0-dns-resolver/src/resolver/transport.rs:278-292`), compiled in by default (`iroh-dns/Cargo.toml:124-128`). Effort [inferred]: about 150–200 lines of JS for the relay, plus 150–250 for DoH. No fatal blocker; use the Paid plan, since free CPU is 10 ms [read, Workers limits].

**(e) Tickets.** `EndpointTicket` wraps one `EndpointAddr` and has no expiry (`iroh-tickets/src/endpoint.rs:30-31`). `connect` takes it directly; its addresses enter as `Source::App` paths, so the dial does not wait on lookup (`iroh/src/socket/remote_map/remote_state.rs:870-880`). `MemoryLookup::add_endpoint_info` serves later ID-only dials (`iroh/src/address_lookup/memory.rs:184-199`). Entries never expire (`memory.rs:218-240`); stale IPs stay until 30 or more non-relay paths force pruning (`iroh/src/socket/remote_map/remote_state/path_state.rs:18, 256`). Its doc says relay URLs are overwritten; the code appends them (`memory.rs:181-191`).

**(f) Combining and blocking.** Multiple lookups: yes. `address_lookup(...)` appends (`iroh/src/endpoint.rs:616-618`) and all run concurrently (`iroh/src/address_lookup.rs:565-579`). Precedence: none; addresses merge into one path set (`remote_state.rs:906-937`). An ID-only dial returns at the first item, or once every service has yielded or ended (`path_state.rs:161-207`). DNS ends within about 6 s (`iroh-dns/src/dns.rs:1197-1228`); mDNS within 10 s; DHT once nothing is in flight. Pkarr HTTP has no timeout (`iroh/src/util.rs:21-71`), so a stalled relay blocks indefinitely [inferred]. The 10 s connect timeout starts after resolution (`iroh/src/endpoint.rs:1146-1153`). Wrap `connect` in `tokio::time::timeout`.

**(g) Recommendation.**
1. **On by default:** n0 pkarr and DNS (`presets::N0`). Cost: n0 sees your ID↔relay mapping, IP and each ID you dial. Switch: `presets::Minimal`; `.disable_fallback()` on the DNS resolver. Dropping only `PkarrPublisher` means others cannot dial you by ID, but you can still dial them [inferred].
2. **Opt-in:** (i) a Worker pkarr relay. Cost: its host sees what n0 sees; Cloudflare terminates TLS [inferred]. Switch: the URL. (ii) Mainline DHT. Cost: a public per-key record, refreshed hourly; DHT nodes see your IP. Switch: `.address_lookup(DhtAddressLookup::builder())`; `.no_publish()` for lookup-only.
3. **Off:** mDNS. Cost: every LAN host learns your ID and all IPs. Switch: omit it, or `.advertise(false)` or `relay_only`.

Keep user data empty: it bypasses filters (`iroh-dns/src/endpoint_info.rs:194-196`). The mainline crate's lock pins iroh 1.0.0; docs.rs lists the same dependencies, but I did not build it [inferred].
