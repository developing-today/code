## 2026-10-12T21:08:19Z Note: P6.7c, documents and tags CLI

- Done: `id doc publish FILE --media-type T [--tag name[=value]]...` prints `publish document=<ID>` (the `document.put`'s event ID), then one `set` line per tag. `id doc events DOC` lists the tags and any removal on it; `id doc history DOC` adds the `document.put`, in causal order; `id doc frontier` lists each author's head. `id claim set SUBJECT NAME [VALUE]`, `clear SUBJECT NAME`, `list SUBJECT`, `search NAME [VALUE]`. `--json` as for the group CLI.
- Signed, not the group log's stand-in. `src/local_events.rs` signs each event with the node key (`.iroh-key`), names the other authors' heads as `after`, and ingests it with `EventStore::ingest`, the path sync uses. The store is `--event-store` (default `events` in the data directory). Nodes that share one store directory stand in for sync, as they share `--groups-log`. Nothing crosses machines yet. A second process on the same store is refused while the first holds it.
- Name change from the plan: the tag verb is `id claim`, not `id tag`. `id tag` is the legacy file-tag command (iroh-docs store, also in the REPL). Keeping `id tag` for the event-backed tags would retire the legacy command, which is an owner decision.
- Not in this step: publish does not store the bytes, since the blob path is iroh-blobs and has no CLI yet; there is no `document.remove` command, so a removal comes only from the library; `claim clear` removes the live claims on the subject and name by any author, which a shared store allows.
- Library: `EventStore::chains` (the authors and their chain state), and `src/local_events.rs`, with unit tests for causal order and tag checks.
- Evidence: 15 e2e tests failed on the red commit `462f02ce` (`--event-store` and the commands did not exist), and pass on `5d4dc149`. Lib 1251 pass (4 ignored); `cli_documents` 8, `cli_tags` 7, `cli_groups` 8 pass.
