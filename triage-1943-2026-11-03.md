## The one real constraint: Pages has a single custom domain

Drew's 2026-10-29 decision names **both** `mcpx.developing-today.com` **and** `mcpx.developing.today`. A GitHub Pages site has exactly one custom domain, and GitHub's automatic redirects only cover an apex ↔ its own `www` (docs: [Managing a custom domain](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)). So "both" means:

- **canonical:** `mcpx.developing-today.com` on the Pages site (recommended — it is the product/org domain and matches the `zettel` precedent), and
- **redirect:** `mcpx.developing.today` → canonical, via Porkbun's free **URL forwarding** (Domain Management → URL Forwarding: host `mcpx`, 301, "include requested URI path"). This is a console setting on the existing Porkbun account — **no nameserver change and no Cloudflare move** ([Porkbun: How to Set Up URL Forwarding](https://kb.porkbun.com/article/39-how-to-set-up-url-forwarding)).
